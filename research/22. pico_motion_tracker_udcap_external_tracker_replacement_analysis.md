# PICO Motion Tracker로 UDCAP 외부 트래커 대체 가능성 분석

> **날짜**: 2026-04-01
> **관련 문서**: `14. udcap_glove_tracker_compatibility_pico_vs_vive_configuration_research.md`, `15. quest3s_vs_pico4ultra_fullbody_tracking_headset_selection_research.md`, `18. xrobotoolkit_udcap_minipc_implementation_guide.md`
> **핵심 질문**: PICO Motion Tracker를 UDCAP VR Gloves의 외부 트래커(Vive Tracker/PICO Controller)로 대체할 수 있는가?

---

## 1. 배경: UDCAP가 외부 트래커를 필요로 하는 이유

### 1.1 UDCAP는 "핑거 전용" 센서

```
UDCAP VR Gloves가 측정하는 것:
  ✓ 15개 손가락 관절 (21개 각도, 0.01° 해상도)
  ✓ 손가락 굽힘 (flexion)
  ✓ 손가락 벌림 (abduction)
  ✓ 엄지 대립 (opposition)

UDCAP가 측정하지 못하는 것:
  ✗ 손의 3D 위치 (x, y, z)
  ✗ 손목 방향 (roll, pitch, yaw)
  ✗ 팔꿈치/어깨 위치
```

**결론**: 외부 트래커 없이 UDCAP만 사용하면 가상 손이 공간에서 위치를 잡을 수 없음.

### 1.2 현재 UDCAP 공식 지원 트래커

| 트래킹 플랜 | 트래커 타입 | 마운팅 | 정밀도 | 비용 |
|------------|-----------|--------|--------|------|
| **Lighthouse (Vive 3.0)** | Vive Tracker 3.0 | 1/4" 나사 마운트 | **< 1mm** | ~$130 + 베이스 $300 |
| **Lighthouse (Tundra)** | Tundra Tracker | 전용 어댑터 | **< 1mm** | ~$100 + 베이스 $300 |
| **Vive Ultimate (UTK)** | Vive Ultimate Tracker | 클립 마운트 | **~2mm** | ~$200 |
| **Quest Controller** | Quest 컨트롤러 | 전용 어댑터 | **~cm급** | 무료 (기존 보유) |
| **PICO Controller** | PICO 컨트롤러 | 소프트웨어 설정 | **~cm급** | 무료 (기존 보유) |
| **PICO Motion Tracker** | - | - | - | **공식 미지원** |

> **PICO Motion Tracker는 UDCAP 공식 트래킹 플랜에 포함되어 있지 않음.**

## 2. PICO Motion Tracker vs Vive Tracker 기술 비교

| 항목 | PICO Motion Tracker | Vive Tracker 3.0 |
|------|------|------|
| **위치 정밀도** | 5cm 평균 편차 | < 1mm |
| **방향 정밀도** | 6° 평균 편차 | < 1.6° |
| **트래킹 방식** | IMU + 헤드셋 IR 카메라 (inside-out) | 외부 베이스 스테이션 적외선 (outside-in) |
| **업데이트 속도** | 200Hz | 100Hz |
| **지연 시간** | 20ms | ~5ms |
| **연결 방식** | 2.4GHz 전용 → PICO 헤드셋 전용 | Bluetooth/USB dongle → PC 직접 |
| **SteamVR 인식** | PICO Connect 경유 시 가능 | 네이티브 지원 |
| **SteamVR 핸드 역할** | **할당 불가** (바디 역할만 지원) | 할당 가능 (Hand L/R) |
| **글러브 마운팅** | 어댑터 없음 (팔뚝 스트랩 전용 디자인) | UDCAP 전용 어댑터 제공 |
| **무게** | 27g | 75g |
| **배터리** | 25시간 | 7.5시간 |
| **가격** | ~$50/개 | ~$130/개 + 베이스 $150×2 |

### 2.1 SteamVR 호환성 핵심 차이

**Vive Tracker 3.0**:
```
Vive Tracker → Bluetooth/Dongle → PC SteamVR → "Hand (Left/Right)" 역할 할당 가능
→ UDCAP Software가 SteamVR에서 Hand 역할 트래커의 위치를 읽어 핑거 데이터와 결합
```

**PICO Motion Tracker**:
```
PICO MT → 2.4GHz → PICO 헤드셋 → PICO Connect → SteamVR OpenVR 드라이버
→ SteamVR에서 "Generic Tracker" 또는 "Body" 역할로 인식
→ ⚠ "Hand (Left/Right)" 역할 할당 불가
→ UDCAP Software가 Hand 역할 트래커를 찾을 수 없음
```

**SenseGlove 공식 문서 참조** (유사한 VR 글러브):
> "Unlike Vive (Wrist) Trackers, Pico Motion Trackers **do not show up in the `UnityEngine.InputDevices.GetDevices` list**, and wrist tracking using Pico Motion Trackers does **NOT work 'out of the box'**."
> "The PICO API **does not allow you to assign a left and right hand** to a tracker."

## 3. 대체 경로 분석 (3가지)

### 3.1 경로 A: SteamVR 경유 (PICO Connect)

```
PICO MT → PICO 헤드셋 → PICO Connect → SteamVR OpenVR 드라이버 → UDCAP Software
```

**가능 여부**: **부분적 가능, 실용성 낮음**

| 장점 | 단점 |
|------|------|
| SteamVR 표준 프로토콜 사용 | Hand 역할 할당 불가 (Body/Waist 등만) |
| PICO Connect가 Vive Tracker 호환 프로파일 생성 | UDCAP Software에 "PICO MT" 프리셋 없음 |
| | Windows PC + PICO Connect + SteamVR 모두 필요 |
| | 5cm 위치 편차 (로봇 텔레오퍼레이션에 부정확) |
| | 글러브 마운팅 어댑터 없음 (DIY 필요) |

**SteamVR 역할 할당 문제**:
- PICO Connect의 OpenVR 드라이버는 `vive_tracker_handed_profile.json`을 사용
- 하지만 이 프로파일은 **바디 트래킹용** (waist, foot, knee, chest 등)
- UDCAP는 **Hand (Left/Right) 역할**의 트래커만 인식
- PICO MT에 Hand 역할을 할당하는 공식 방법 없음

### 3.2 경로 B: XRoboToolkit 직접 경유 (SteamVR 완전 우회) ★★★

```
PICO MT → PICO 헤드셋 → XRoboToolkit App → WiFi/TCP → XRoboToolkit PC Service
→ JSON 데이터 (6DoF pose: position + quaternion)
→ 커스텀 브릿지에서 UDCAP 핑거 데이터와 결합
→ Isaac Lab
```

**가능 여부**: **가능, 커스텀 개발 필요**

| 장점 | 단점 |
|------|------|
| SteamVR/PICO Connect 불필요 | 커스텀 통합 코드 개발 필요 |
| XRoboToolkit이 MT 6DoF 포즈를 JSON으로 직접 전송 | UDCAP의 공간 트래킹 시스템 우회 |
| Linux 네이티브 (기존 아키텍처와 일치) | MT 정밀도 한계 (5cm) |
| 90Hz 데이터 스트림 | 글러브에 물리적 마운팅 DIY 필요 |
| Windows 미니PC 불필요 가능 | |

**XRoboToolkit MT 데이터 형식**:
```json
{
  "Motion": {
    "joints": [
      {
        "p": "x,y,z,qx,qy,qz,qw",    // 6DoF 포즈
        "va": "vx,vy,vz,wx,wy,wz",     // 속도 + 각속도
        "wva": "ax,ay,az,ex,ey,ez"      // 가속도 + 각가속도
      }
    ],
    "len": 3,                           // 트래커 수 (최대 3)
    "timeStampNs": 1733287634681455104,
    "sn": "PC2310MLJ6050513G"           // 시리얼 번호 (트래커 구분용)
  }
}
```

**GR00T WholeBodyControl에서 이미 사용 중**:
NVIDIA GR00T VR Teleop 가이드에서 PICO MT 2개(발목)를 XRoboToolkit으로 전송하여 휴머노이드 로봇 텔레오퍼레이션에 사용 중. 동일 패턴을 손목/글러브에도 적용 가능.

### 3.3 경로 C: 하이브리드 (UDCAP 핑거 + XRT MT 공간) ★★★★★ 추천

```
┌─────────────────────────────────────────────────────┐
│  PICO Motion Tracker (글러브에 장착)                   │
│  → XRoboToolkit → 6DoF 손 위치/방향                  │
│                                                      │
│  UDCAP VR Gloves (핑거 센서)                          │
│  → VMC/OSC → 21관절 핑거 각도                         │
│                                                      │
│  통합 브릿지에서 두 데이터 결합:                        │
│  → MT 포즈 = 손 공간 위치 (EEF delta pose 계산)       │
│  → UDCAP = 손가락 관절 (Inspire 12D 매핑)            │
│  → 합쳐서 38D 액션 텐서                               │
└─────────────────────────────────────────────────────┘
```

**가능 여부**: **가장 실용적, 현재 아키텍처에 자연스럽게 통합**

| 장점 | 단점 |
|------|------|
| UDCAP의 핑거 트래킹 (0.01° 정밀) 유지 | MT 5cm 위치 편차 |
| PICO Controller를 글러브에서 해방 | 글러브에 MT 마운팅 DIY 필요 |
| 기존 통합 브릿지(unified_bridge.py) 구조에 적합 | MT 2개 추가 필요 ($100) |
| Windows 미니PC는 UDCAP 핑거 전용으로 유지 | |
| PICO Controller는 원래 용도(VR 인터랙션)로 사용 | |

### 4.3 기존 아키텍처 대비 변경점

| 구성요소 | 기존 (PICO Controller on glove) | 변경 (MT on glove) |
|---------|-------------------------------|-------------------|
| **손 위치** | PICO Controller → XRT JSON `controllers.left/right.pose` | PICO MT → XRT JSON `Motion.joints[0/1].p` |
| **버튼 입력** | Controller 직접 (글러브에서 누름 어려움) | Controller 별도 (양손에 자유롭게 들고 조작) |
| **핑거** | UDCAP → VMC (동일) | UDCAP → VMC (동일) |
| **글러브 무게** | +170g (PICO Controller) | +27g (PICO MT) ← **대폭 경량화** |
| **그리퍼 제어** | Controller trigger (글러브에서 어색) | Controller trigger (별도로 편하게) |
| **개입 트리거** | Controller grip (글러브에서 어색) | Controller grip (별도로 편하게) |

### 4.4 물리적 마운팅

PICO MT는 팔뚝 스트랩 전용이지만, 글러브 등판에 마운팅하는 방법:

```
방법 1: 벨크로 (가장 간단)
  - PICO MT 뒷면에 벨크로 테이프 부착
  - UDCAP 글러브 Data Box 옆에 벨크로 수 부착
  - 27g으로 가벼워 벨크로로 충분

방법 2: 3D 프린트 어댑터
  - PICO MT 하우징에 맞는 클립 설계
  - UDCAP 글러브 등판에 고정
  - STL 파일 직접 설계 또는 커뮤니티 공유

방법 3: 실리콘 밴드
  - 작은 실리콘 밴드로 MT를 글러브 등판에 고정
  - 빠른 탈착 가능

마운팅 위치: 글러브 등판 (손등) 중앙
  → IR LED가 헤드셋 카메라 방향으로 노출되어야 함
  → Data Box와 간섭하지 않는 위치
```

## 5. 코드 수정 가이드 (경로 C 구현)

### 5.1 g1_retargeter.py 수정

기존: 컨트롤러 포즈로 EEF 델타 계산
변경: MT 포즈로 EEF 델타 계산, 컨트롤러는 버튼 전용

```python
# g1_retargeter.py 변경 개념

def retarget(self, xrt_frame, udcap_bones, use_mt_for_hands=True):
    """
    use_mt_for_hands=True:
      → Motion Tracker #1,#2의 포즈로 손 위치 계산 (MT on glove)
      → Controller는 버튼/트리거만 사용 (그리퍼, 개입)
    use_mt_for_hands=False:
      → Controller 포즈로 손 위치 계산 (기존, Controller on glove)
    """
    if use_mt_for_hands and len(xrt_frame.trackers) >= 2:
        # MT #0 = 오른손, MT #1 = 왼손 (SN으로 구분)
        right_hand_pose = xrt_frame.trackers[0]  # MT on right glove
        left_hand_pose = xrt_frame.trackers[1]   # MT on left glove
    else:
        # 폴백: 컨트롤러 포즈 (기존 방식)
        right_hand_pose = xrt_frame.right_controller.pose
        left_hand_pose = xrt_frame.left_controller.pose

    # 그리퍼/개입은 항상 컨트롤러에서
    right_gripper = xrt_frame.right_controller.trigger
    left_gripper = xrt_frame.left_controller.trigger
```

## 6. 정밀도 영향 분석

### 6.1 로봇 텔레오퍼레이션에서 5cm 편차의 의미

| 작업 | 필요 정밀도 | MT 5cm 편차 | 영향 |
|------|-----------|------------|------|
| 물체 접근 (approach) | ~5cm | ≈ 한계 | 중간 (보정 필요) |
| 물체 파지 (grasp) | ~1cm | 부족 | **높음** (미세조정 필요) |
| 물체 이동 (transport) | ~3cm | 가능 | 낮음 |
| 빈에 놓기 (place) | ~3cm | 가능 | 낮음 |
| 전체 분류 작업 | 혼합 | 가능 | 중간 |

### 6.2 보정 전략

```
1. 속도 필터링: MT 포즈에 저역 필터(Low-pass) 적용 → 떨림 제거
2. 칼만 필터: IMU + IR 데이터 융합 → MT 자체적으로 수행
3. IK 스무딩: DifferentialIK에서 delta 크기 제한 → 급격한 움직임 방지
4. 교정 티칭(HG-DAgger): Phase 2에서 정밀도 부족 구간을 사람이 교정
   → 이것이 정확히 교정 티칭 시스템의 목적!
```

### 6.3 결론: "충분히 사용 가능"

- **BC-RNN 모방학습** 관점: 시연 데이터의 약간의 노이즈는 학습 일반화에 오히려 도움
- **HG-DAgger** 관점: 정밀도 부족 구간에서 사람이 개입하여 교정 → 시스템 설계 목적에 부합
- **MimicGen 데이터 증강**: 기본 시연에 노이즈를 추가하여 증강 → MT의 자연스러운 노이즈가 증강 효과
- **앙상블 불확실성 (Phase 3)**: 불확실한 상황에서 도움 요청 → MT 노이즈로 인한 실패를 자동 감지

## 7. 최종 추천 구성

### 7.1 구매 목록 (추가 필요 하드웨어)

| 항목 | 수량 | 용도 | 가격 |
|------|------|------|------|
| PICO Motion Tracker | 2개 추가 | 양손 글러브 마운팅 | ~$100 |
| 벨크로 테이프 | 1세트 | MT→글러브 고정 | ~$5 |

> **기존 보유**: PICO MT 3개 (허리+발목), PICO Controller 2개, UDCAP 글러브 2개
> **추가 구매**: PICO MT 2개 ($100) → **총 MT 5개** (손2+허리1+발목2)

### 7.2 역할 분담

```
PICO Motion Tracker × 5:
  #1: 오른손 글러브 → 오른손 공간 위치 (EEF delta)
  #2: 왼손 글러브 → 왼손 공간 위치 (EEF delta)
  #3: 허리 → 상체 방향 (풀바디 트래킹)
  #4: 오른쪽 발목 → 다리 트래킹 (선택)
  #5: 왼쪽 발목 → 다리 트래킹 (선택)

PICO Controller × 2:
  오른손 (별도 들고 사용):
    → Trigger: 오른쪽 그리퍼 열기/닫기
    → Grip: 개입 시작 (양손 동시)
    → A/B 버튼: 커스텀 기능
  왼손 (별도 들고 사용):
    → Trigger: 왼쪽 그리퍼
    → Grip: 개입 시작 (양손 동시)
    → X/Y 버튼: 커스텀 기능

UDCAP VR Gloves × 2:
  → 핑거 관절 각도만 (VMC/OSC → Windows 미니PC → Ubuntu 호스트)
```

### 7.3 장점 요약

| 기존 (Controller on glove) | 변경 (MT on glove + Controller 별도) |
|---------------------------|-------------------------------------|
| 글러브 +170g (무거움) | 글러브 +27g (**85% 경량화**) |
| 컨트롤러 버튼 접근 어려움 | 컨트롤러 별도 → **자유로운 버튼 조작** |
| 컨트롤러 IR 링 가림 우려 | MT IR LED 노출 용이 (작은 크기) |
| 그리퍼 제어 어색 | 트리거 별도 → **직관적 그리퍼 제어** |
| 개입 트리거 어색 | 그립 별도 → **안정적 개입/복귀** |
