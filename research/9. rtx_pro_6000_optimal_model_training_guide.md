## 2. 동시 실행 워크로드 VRAM 분석

### 2.1 개별 워크로드 VRAM 사용량

교정 티칭 시스템은 **3가지 워크로드가 동시에 실행**됩니다:

#### 워크로드 1: Isaac Sim / Isaac Lab 환경
| 구성 요소 | VRAM 사용량 |
|-----------|-------------|
| Isaac Sim 기본 렌더링 | 3-4 GB |
| USD 씬 (G1 + 주방 + 물체) | 0.5-1.0 GB |
| PhysX GPU 물리 시뮬레이션 | 0.5-1.0 GB |
| 카메라 센서 (enable_cameras) | 0.5-1.5 GB |
| **합계 (카메라 없음)** | **4-6 GB** |
| **합계 (카메라 포함)** | **5-8 GB** |

#### 워크로드 2: 사전학습 모델 추론 (VLM + 분류기)
| 모델 | 정밀도 | VRAM | 추론 속도 |
|------|--------|------|-----------|
| Qwen3-VL-32B-Instruct | FP16 | 70-80 GB | ~30 tok/s |
| Qwen3-VL-32B-Instruct | INT4 (AWQ) | 19-24 GB | ~50 tok/s |
| **Qwen3-VL-8B-Instruct** | **FP16** | **18-20 GB** | **~80 tok/s** |
| Qwen3-VL-8B-Instruct | INT4 (AWQ) | 6-8 GB | ~120 tok/s |
| SigLIP2-so400m | FP16 | 1.5-2.0 GB | <10ms/img |
| Florence-2-large-ft | FP16 | 3.0-4.5 GB | <50ms/img |
| CLIP ViT-L/14 | FP16 | 1.0-1.5 GB | <5ms/img |

#### 워크로드 3: BC-RNN / IWR 학습
| 설정 | VRAM 사용량 |
|------|-------------|
| BC-RNN 단일 모델 (state-based, batch=64) | 0.5-1.0 GB |
| BC-RNN 단일 모델 (vision-augmented, batch=64) | 2.0-4.0 GB |
| BC-RNN + optimizer states (Adam) | +0.3-0.5 GB |
| BC-RNN + gradient checkpointing | -30% |
| **합계 (state-based)** | **0.8-1.5 GB** |
| **합계 (vision-augmented)** | **2.5-5.0 GB** |

> **참고**: 앙상블 학습(K=5)은 **순차적**으로 진행하므로 단일 모델 VRAM과 동일

## 3. 최적 사전학습 모델 선정

### 3.1 필요한 사전학습 모델 목록

교정 티칭 시스템에서 사전학습 모델이 필요한 부분:

| 용도 | 위치 (코드) | 요구사항 |
|------|-------------|----------|
| **VLM 물체 분석** | `phase3/vlm_analyzer.py` | 이미지→물체 식별+카테고리 분류 |
| **빠른 분류기** | `phase3/help_request_decider.py` | 물체 임베딩→카테고리 확률 (실시간) |
| **물체 탐지** | 설계 가이드 Phase 3 | 바운딩박스→물체 위치 파악 |
| **ResNet 인코더** | Robomimic 내부 (선택) | 이미지 관찰값 인코딩 |

### 3.2 추천 구성: 3-Tier 아키텍처

RTX PRO 6000의 96GB VRAM을 최대한 활용하는 **3단계 추론 파이프라인**:

```
Tier 1: 빠른 분류기 (매 스텝, <10ms)
  └── SigLIP2-so400m (~1.8GB) → 물체 임베딩 + 카테고리 확률

Tier 2: 물체 탐지 (30스텝마다, <50ms)
  └── Florence-2-large-ft (~3.5GB) → 바운딩박스 + 물체 레이블

Tier 3: 상세 VLM 분석 (불확실할 때만, ~1-2초)
  └── Qwen3-VL-32B FP16 (~75GB) → 상세 물체 분석 + 카테고리 판단
```

### 3.3 시나리오별 최적 모델 조합

#### 시나리오 A: 최대 성능 (권장)

**VLM: Qwen3-VL-32B-Instruct FP16**

```
VRAM 할당:
├── Isaac Sim (카메라):    7 GB
├── Qwen3-VL-32B FP16:   75 GB  ← VLM
├── SigLIP2-so400m:       2 GB  ← 빠른 분류
├── BC-RNN 학습:          1 GB
├── CUDA 오버헤드:         3 GB
└── 여유:                  8 GB
총계:                     88 GB / 96 GB
```

**장점**:
- 최고 수준의 VLM 추론 품질 (GPT-4V 수준)
- FP16으로 정밀도 손실 없음
- 1,792 GB/s 대역폭으로 대형 모델도 빠른 추론

**단점**:
- 여유 VRAM 8GB로 다소 타이트
- VLM 추론 중 학습 일시 중지 권장

**적용 시점**: Phase 3 최종 운용 (불확실성 기반 도움 요청 활성화)

#### 시나리오 B: 균형 (Phase 2 학습 시 권장)

**VLM: Qwen3-VL-8B-Instruct FP16**

```
VRAM 할당:
├── Isaac Sim (카메라):    7 GB
├── Qwen3-VL-8B FP16:    19 GB  ← VLM
├── SigLIP2-so400m:       2 GB  ← 빠른 분류
├── Florence-2-large:     4 GB  ← 물체 탐지
├── BC-RNN 학습:          1 GB
├── CUDA 오버헤드:         3 GB
└── 여유:                 60 GB
총계:                     36 GB / 96 GB
```

**장점**:
- 60GB 여유로 학습과 추론 동시 진행에 충분
- Qwen3-VL-8B도 물체 분류에 충분한 성능
- Florence-2 물체 탐지까지 동시 로드 가능
- 대형 배치 사이즈 학습 가능

**단점**:
- VLM 분석 품질이 32B 대비 다소 낮음

**적용 시점**: Phase 2 HG-DAgger 학습 중, Phase 3 초기 프로토타이핑

#### 시나리오 C: 학습 집중 (Phase 1 학습 시 권장)

**VLM 없음, 분류기만 로드**

```
VRAM 할당:
├── Isaac Sim (카메라):    7 GB
├── SigLIP2-so400m:       2 GB  ← 사전학습 인코더로 활용
├── BC-RNN 학습 (batch=128): 2 GB
├── CUDA 오버헤드:         3 GB
└── 여유:                 82 GB
총계:                     14 GB / 96 GB
```

**장점**:
- 대규모 배치 사이즈 가능 (128~256)
- 앙상블 5개 모델 동시 로드 후 병렬 학습 가능 (이론적으로)
- 데이터 전처리 파이프라인에 여유분 활용

**적용 시점**: Phase 1 BC-RNN 학습, 앙상블 학습

### 3.4 추천 모델 상세 분석

#### 3.4.1 VLM: Qwen3-VL-32B-Instruct (1순위)

| 항목 | 상세 |
|------|------|
| HuggingFace ID | `Qwen/Qwen3-VL-32B-Instruct` |
| 파라미터 수 | 32B |
| VRAM (FP16) | ~70-75 GB |
| VRAM (INT4 AWQ) | ~19-24 GB |
| 이미지 해상도 | 가변 (최대 4K) |
| 핵심 기능 | 이미지 → 물체 인식 + 카테고리 분류 + 상황 추론 |
| 성능 수준 | GPT-4V / Gemini Pro 1.5 수준 |
| 라이선스 | Apache 2.0 |

**왜 Qwen3-VL-32B인가?**
1. **Apache 2.0 라이선스**: 상업적 사용 제한 없음
2. **96GB VRAM에 FP16 로드 가능**: INT4 양자화 불필요
3. **한국어 지원 우수**: 물체 분류 프롬프트를 한국어로 작성 가능
4. **구조적 출력**: JSON 형식 응답에 강함 (vlm_analyzer.py 호환)
5. **비전-언어 통합**: 주방 물체 분류에 최적화된 시각적 추론

**대안 모델들:**

| 모델 | VRAM (FP16) | 장점 | 단점 |
|------|-------------|------|------|
| InternVL3.5-38B | ~76 GB | 비전 성능 최고급 | 96GB에 단독으로도 타이트 |
| Gemma-3-27B | ~54 GB | Google 생태계 | 비전 성능 Qwen3보다 약함 |
| Qwen3-VL-8B | ~18 GB | 가벼움 | 분석 품질 다소 낮음 |
| Llama-4-Scout-17B | ~34 GB | Meta 최신 | 비전 특화 아님 |

#### 3.4.2 빠른 분류기: SigLIP2-so400m-patch14-384 (1순위)

| 항목 | 상세 |
|------|------|
| HuggingFace ID | `google/siglip2-so400m-patch14-384` |
| 파라미터 수 | ~400M |
| VRAM | 1.5-2.0 GB (FP16) |
| 입력 해상도 | 384×384 |
| 추론 시간 | <10ms/이미지 |
| 핵심 기능 | 이미지-텍스트 유사도 → 카테고리 확률 |

**왜 SigLIP2인가?**
1. **경량**: ~400M 파라미터로 1.5-2GB만 사용
2. **제로샷 분류**: 사전 학습 없이 텍스트 프롬프트로 분류 가능
3. **실시간 가능**: <10ms로 매 시뮬레이션 스텝마다 호출 가능
4. **Conformal Prediction 호환**: 소프트맥스 확률 출력 → `conformal_predictor.py` 직접 사용

**사용 방법 (코드 예시):**
```python
from transformers import AutoProcessor, AutoModel
import torch

model = AutoModel.from_pretrained("google/siglip2-so400m-patch14-384")
processor = AutoProcessor.from_pretrained("google/siglip2-so400m-patch14-384")

# 카테고리 텍스트
categories = ["kitchen utensil", "food item", "miscellaneous object"]

# 이미지 + 텍스트 유사도 계산
inputs = processor(text=categories, images=image, return_tensors="pt", padding=True)
outputs = model(**inputs)

# 카테고리 확률 → conformal_predictor.predict() 입력
probs = torch.sigmoid(outputs.logits_per_image[0]).numpy()  # [3] 확률 벡터
```

#### 3.4.3 물체 탐지: Florence-2-large-ft (1순위)

| 항목 | 상세 |
|------|------|
| HuggingFace ID | `microsoft/Florence-2-large-ft` |
| 파라미터 수 | ~770M |
| VRAM | 3.0-4.5 GB (FP16) |
| 핵심 기능 | 객체 탐지 + 캡셔닝 + OCR |
| 추론 시간 | <50ms/이미지 |

**왜 Florence-2인가?**
1. **다기능**: 탐지 + 캡셔닝 + 분류를 하나의 모델로
2. **경량**: 770M 파라미터로 3-4.5GB만 사용
3. **프롬프트 기반**: `<OD>`, `<CAPTION>` 등 태스크 전환 가능
4. **탐지 정밀도**: 주방 물체 탐지에 충분한 성능

#### 3.4.4 Phase별 모델 로드 전략

```
Phase 1 (기초 학습):
  로드: SigLIP2 (선택, 데이터 전처리용)
  학습: BC-RNN × 1
  VRAM: ~14 GB / 96 GB

Phase 2 (HG-DAgger):
  로드: SigLIP2 + Florence-2
  학습: IWR (BC-RNN 기반)
  VRAM: ~20 GB / 96 GB

Phase 3-초기 (프로토타이핑):
  로드: SigLIP2 + Florence-2 + Qwen3-VL-8B
  학습: 앙상블 × 1 (순차)
  VRAM: ~36 GB / 96 GB

Phase 3-운용 (최종):
  로드: SigLIP2 + Qwen3-VL-32B
  학습: 필요 시 오프라인
  VRAM: ~88 GB / 96 GB
```

## 4. 최적 학습 규모 설정

### 4.1 Phase 1: BC-RNN 기본 학습

#### 4.1.1 Robomimic BC-RNN 설정

```python
# 최적 학습 설정 (RTX PRO 6000)
train_config = {
    # 데이터
    "dataset_size": "1000+ trajectories",  # MimicGen 증강 후
    "obs_type": "low_dim",                 # state-based (135D)
    "action_dim": 38,                      # G1 InspireFTP

    # 모델 아키텍처
    "rnn_type": "LSTM",
    "rnn_hidden_dim": 400,
    "rnn_num_layers": 2,
    "gmm_num_modes": 5,
    "gmm_min_std": 0.0001,

    # 학습 하이퍼파라미터
    "batch_size": 128,            # 96GB VRAM에서 충분히 큰 배치
    "sequence_length": 10,        # 10스텝 시퀀스
    "num_epochs": 2000,
    "learning_rate": 1e-4,
    "lr_scheduler": "multistep",  # [1000, 1500]에서 0.1배
    "weight_decay": 1e-5,
    "grad_clip_norm": 1.0,

    # 최적화
    "mixed_precision": "bf16",    # Blackwell BF16 최적화
    "num_workers": 8,             # DataLoader
    "pin_memory": True,
}
```

#### 4.1.2 학습 시간 예측

| 설정 | 예상 시간 |
|------|-----------|
| 1000 trajectories, 2000 epochs, batch=128 | ~25-35분 |
| 1000 trajectories, 2000 epochs, batch=64 | ~45-60분 |
| 500 trajectories, 1000 epochs, batch=128 | ~10-15분 |

> BC-RNN은 state-based이므로 학습이 매우 빠릅니다. RTX PRO 6000에서는 batch_size=128도 VRAM 1GB 미만으로 가능합니다.

### 4.3 Phase 3: 앙상블 학습

#### 4.3.1 앙상블 설정

```python
ensemble_config = {
    # 앙상블 구성
    "num_models": 5,              # K=5 멤버
    "subsample_ratio": 0.8,       # 80% 부트스트랩
    "base_seed": 42,              # 시드: 42, 43, 44, 45, 46

    # 개별 모델 학습 (Phase 1 BC-RNN과 동일)
    "batch_size": 128,
    "num_epochs": 2000,
    "learning_rate": 1e-4,
    "mixed_precision": "bf16",

    # 순차 학습 전략
    "training_strategy": "sequential",  # 순차 학습 (VRAM 효율)
    # 각 모델: ~1GB VRAM, ~30분
    # 5개 순차: ~150분 (2.5시간)

    # 불확실성 임계값
    "initial_uncertainty_threshold": 0.05,
    "threshold_adaptation": True,
    "target_intervention_ratio": 0.15,  # 15%
}
```

#### 4.3.2 앙상블 병렬 학습 (선택)

RTX PRO 6000의 96GB VRAM에서는 5개 모델 동시 로드도 가능합니다:

```python
# 병렬 학습 옵션 (실험적)
parallel_ensemble_config = {
    "training_strategy": "parallel",
    "num_models": 5,
    "batch_size_per_model": 32,   # 모델당 배치 감소
    # VRAM: 5 × 1GB = 5GB (모델) + 5GB (옵티마이저) ≈ 10GB
    # 속도: ~30분 (순차의 1/5)
    # 주의: DataLoader 경합으로 실제 속도는 1/3 정도
}
```

### 4.4 BF16 혼합 정밀도 설정

Blackwell 아키텍처의 BF16 Tensor 코어를 활용하는 설정:

```python
import torch

# PyTorch BF16 AMP 설정
scaler = None  # BF16은 GradScaler 불필요 (동적 범위가 FP32와 동일)

with torch.amp.autocast('cuda', dtype=torch.bfloat16):
    pred = model(obs_batch)
    loss = criterion(pred, action_batch)

loss.backward()
optimizer.step()
```

**BF16 vs FP16 비교:**

| 항목 | FP16 | BF16 |
|------|------|------|
| 지수 비트 | 5 | 8 (FP32와 동일) |
| 가수 비트 | 10 | 7 |
| 동적 범위 | 작음 → 오버플로 위험 | FP32와 동일 |
| GradScaler 필요 | 필요 | **불필요** |
| Blackwell 성능 | 251.9 TFLOPS | **251.9 TFLOPS** |
| 학습 안정성 | 불안정할 수 있음 | **매우 안정** |

> **결론**: RTX PRO 6000에서는 BF16을 기본으로 사용. FP16보다 학습이 안정적이고 GradScaler가 필요 없어 코드가 간결합니다.

