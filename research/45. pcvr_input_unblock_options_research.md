### 1.3 우리 `vr_sampler.py` 의 snapshot 인터페이스

[`teleop/vr_sampler.py`](../ust_hm_grip/teleop/vr_sampler.py) 의 `snapshot()` dict:
```python
{
    "timestamp": float,
    "hmd": {"pos": (3,), "quat": (4, wxyz)} | None,
    "trackers": {role: {"pos": (3,), "quat": (4, wxyz)}},
    "hands": {"left": {"bones": (31,7), "fingerCurls": (5,), ...} | None, "right": ...},
    "controllers": {"left": {"pose": ..., "buttons": {"trigger": float, "grip": float, "menu": bool}}, "right": ...},
    "frame_count": int,
}
```

`gr1t2_gripper_device.py` 와 `gr1t2_gripper_retargeter.py` 는 이 dict 만 의존. **새 backend 가 같은 형식의 dict 를 생성하면 retargeter / device 코드 무수정**.

→ 각 옵션의 통합 비용은 결국 "이 snapshot dict 를 만드는 데 얼마나 걸리는가".

## 2. 옵션 A: XRoboToolkit (🥇 최우선 추천)

### 2.1 정체
**PICO 가 직접 개발한 cross-platform robotics teleoperation framework**. 오픈소스 (Apache-2.0). PICO Developer 공식 발표 (2025).

### 2.2 핵심 아키텍처

```
PICO 4 Ultra 헤드셋
├── XRoboToolkit-Unity-Client (APK, sideload 필요)
│   ├── OpenXR backend (PICO 네이티브 OpenXR 직접 사용)
│   └── Wi-Fi/USB 로 TCP 전송
│        │
│        ▼
PC (Windows x86 / Linux)
├── XRoboToolkit-PC-Service (C++/Qt 6.6.3)
│   ├── gRPC + Protocol Buffers IPC (TCP/UDP)
│   ├── 단일 instance (singleton)
│   └── Apache-2.0 license
│        │
│        ▼ gRPC client (Python 또는 C++)
└── 우리 Isaac Lab teleop 앱
```

### 2.3 노출하는 data (모든 필요한 채널 포함)

[`XRoboToolkit-PC-Service`](https://github.com/XR-Robotics/XRoboToolkit-PC-Service) 의 gRPC service 가 다음을 expose:

| 채널 | 데이터 | 우리 사용 |
|---|---|---|
| **Headset pose** | 7-float (xyz + quat) | observation 가능 |
| **Controller analog** | **trigger, grip** (per side) | ✅ **그리퍼 close/open 직접 소스** |
| **Controller button** | A/B/menu/joystick click | menu = intervention |
| **Controller 6-DOF pose** | xyz + quat | ✅ **Pink IK wrist target** |
| Hand gesture 26 joint | 핀치/주먹 분석 가능 | optional |
| Body mocap 24 joint | full-body teleop 시 사용 | future |
| External tracker IMU | PICO Motion Tracker 5 개 | future (사용자 미래 사용 예정) |

모든 데이터에 Unix nanosecond timestamp + 오른손 좌표계.

### 2.4 우리 환경 호환성

| 항목 | 결과 |
|---|---|
| Windows x86 지원 | ✅ 명시 |
| PICO 4 Ultra 지원 | ✅ 검증된 디바이스 (Meta Quest 3 도 지원) |
| SteamVR 요구 | ❌ 불요 (standalone) |
| PICO Connect 요구 | ❌ 불요 (자체 streaming) |
| Python integration | ✅ [`XRoboToolkit-Teleop-Sample-Python`](https://github.com/XR-Robotics/XRoboToolkit-Teleop-Sample-Python) reference |
| Latency | 100.50 ms ± 3.12 ms (논문 측정값, PICO 4 Ultra) |

### 2.5 우리 기존 design guide 와의 관계

이미 우리 ust_ws/research 에 XRoboToolkit 관련 design guide 3 개 존재:

### 2.6 통합 비용 (우리 ust_hm_grip 측)

3-5 시간 추정:
1. **헤드셋에 Unity Client APK sideload** (PICO 개발자 모드 활성화, 30 분)
2. **PC 에 XRoboToolkit-PC-Service Windows installer 실행** (30 분, Qt 6.6.3 의존성 자동 설치)
3. **새 backend `teleop/xrobo_sampler.py`** 작성: gRPC client → snapshot dict 생성 (1-2 h, Protocol Buffers 정의 따라가서)
4. **`gr1t2_gripper_device.py` 의 `cfg.input_backend` flag** 추가하여 SteamVRSampler ↔ XRoboSampler 분기 (30 분)
5. **`run_teleop.py` 의 `--input_backend xrobotoolkit|openvr` CLI** (15 분)
6. **검증** + 디버깅 (1-2 h)

### 2.7 위험

- **Windows 검증 부족**: GitHub README 가 "currently only tested on Ubuntu 22.04". Windows installer (`Inno Setup`) 는 있지만 실제 검증 정보 부족. → **Linux WSL 또는 Ubuntu native 로 fallback 가능**.
- **Unity Client APK sideload 가 PICO 개발자 모드 활성화 필요**: 사용자가 자기 PICO 계정의 developer mode 신청 + headset 측 ADB enable.
- **PICO Connect 와 동시 작동 시 driver 충돌 가능성**: 26. 가이드의 coexistence 분석 참조.
- **다른 SteamVR 게임 동시 사용 시 영향**: XRoboToolkit 의 단일 instance 정책상 다른 OpenXR client 와 conflict 가능.

### 2.8 검증 전략

1. **단독 sample 검증**: XRoboToolkit-Teleop-Sample-Python 의 minimal example 실행 → controller trigger/grip 값 stream 확인.
2. **우리 backend 작성**: `vr_sampler.py` 의 snapshot dict 형식으로 변환.
3. **monitor mode** smoke test → 우리 retargeter 가 정상 작동.
4. **steamvr_native 모드** vs **xrobotoolkit + 별도 viewport** 의 video stream 검증.

## 3. 옵션 B: Virtual Desktop Streamer (🥈 최단경로)

### 3.1 정체
상용 PCVR streaming 솔루션 ($20-30 one-time, [Virtual Desktop on Meta Quest store / PICO store](https://www.vrdesktop.net/)). PICO 4 Ultra 지원.

### 3.2 binding pipeline 의 차이점

Virtual Desktop 의 PCVR 모드는 SteamVR add-on `Virtual Desktop Streamer (Quest)` driver 를 통해 OpenVR + OpenXR layer 에 input 을 push. PICO 4 컨트롤러를 **Oculus Touch emulation** 으로 expose 하므로, SteamVR Action System 의 binding pipeline 이 *oculus_touch* controller_type 으로 일관성 있게 적용됨.

> **검증 보고** (Steam Community): "Virtual Desktop 으로 PCVR 할 때 PICO 4 controller 의 trigger/grip 가 잘 작동. SteamVR Input 2.0 도 normal binding flow 로 동작."

PICO Connect 의 `pico` driver 가 가진 알려진 Personal Binding commit issue 가 **Virtual Desktop 의 다른 driver path** 에선 발생 안 함.

### 3.3 우리 환경 호환성

| 항목 | 결과 |
|---|---|
| Windows 지원 | ✅ |
| PICO 4 Ultra 지원 | ✅ |
| 라이선스 | $20-30 one-time |
| 우리 기존 코드 변경 | **0 lines** (SteamVRSampler 그대로 사용) |
| PICO Motion Tracker 지원 | ⚠️ Virtual Desktop 의 body tracking (AI body) — PICO Motion Tracker 와 차이 있음 |

### 3.4 통합 비용

0.5-1 시간:
1. Virtual Desktop streamer 구매/설치
2. PICO 헤드셋 측 Virtual Desktop client APK 설치 ([PICO Store](https://store.picoxr.com))
3. SteamVR add-on 에서 `prism` → `Virtual Desktop Streamer` 로 toggle
4. 우리 `run_teleop.py` 의 `--vr_runtime virtual_desktop` 분기 활성화 (이미 코드에 존재!)

### 3.5 위험

- **비용**: $20-30 one-time
- **PICO Motion Tracker 지원 제한**: Virtual Desktop 의 body tracking 은 AI 기반 (PICO 의 inside-out tracker 와 차이). 사용자가 미래에 5-tracker mode 사용 시 호환성 별도 검증 필요.
- **Wi-Fi 의존**: 5GHz Wi-Fi 환경 권장.

### 3.6 우리 코드 의 즉시 호환성

[`run_teleop.py:419-426`](../ust_hm_grip/scripts/run_teleop.py) 에 이미:

## 4. 옵션 C: ALVR (오픈소스, PICO 4 input issue 잔존)

### 4.1 정체
[ALVR](https://github.com/alvr-org/ALVR) — Rust + C++ 작성된 오픈소스 PCVR streaming 솔루션. MIT 라이선스. PICO 4 Ultra + PICO 4 controller emulation 지원 추가됨.

### 4.2 PICO 4 controller 호환성 issue

[ALVR GitHub Issue #2910](https://github.com/alvr-org/ALVR/issues/2910): **"PICO 4 joystick issue — touch not detected"**. 2025-02 발생, "not planned" 로 closed + stale 처리.

- joystick movement 가 ALVR 에서 비활성 (Virtual Desktop 에선 작동)
- joystick click 은 작동
- left/right 또는 양쪽 random 발생
- v20.14.0 stable + nightly 모두 영향

**우리 case**: trigger/grip 만 필요. joystick 안 씀. 따라서 이 issue 직접 영향 없을 수 있음. 그러나 PICO 4 controller 의 ALVR 통합 자체가 incomplete 상태임을 시사.

### 4.3 우리 환경 호환성

| 항목 | 결과 |

| PICO 4 Ultra | ✅ (Pico 4 Ultra / G3 controller support 명시) |
| 라이선스 | MIT (무료) |
| 우리 기존 코드 변경 | 적음 (SteamVR Sampler 그대로 — ALVR 도 SteamVR add-on) |
| PICO Motion Tracker | ❌ 미지원 (ALVR 은 controller + HMD 만) |

### 4.4 통합 비용

2-3 시간:
1. ALVR PC client 설치 (Windows installer)
2. PICO 헤드셋에 ALVR client APK sideload (개발자 모드 필요)
3. SteamVR add-on 에서 `prism` OFF + `ALVR` driver ON
4. PICO 컨트롤러 trigger/grip 작동 검증
5. (issue 발생 시) Pico 4 controller fork / 패치 시도

### 4.5 위험

- **사용자 PICO Motion Tracker 5 개 미래 사용 시 차단** — ALVR 은 PICO Motion Tracker stream 미지원. 사용자 요구사항 ("미래에 모션트래커 5 개 전부 연결해서 사용") 충족 불가.
- **PICO 4 input issue 잔존**: trigger/grip 은 OK 일 가능성 높지만, "PICO 4 controllers' joysticks sometimes do not work in SteamVR" 보고. 우리 case 에선 영향 적지만 검증 필수.
- **stale 처리된 issue**: ALVR 의 PICO 4 통합이 active maintenance 안 받을 가능성.

→ **ALVR 은 사용자가 motion tracker 사용 안 할 경우만 권장**.

## 5. 옵션 D: SteamVR `vrwebui_shared.js` patch (🥉 임시방편 빠른 시도)

### 5.1 정체
SteamVR 의 Personal Binding commit bug 가 명확히 식별됨:

> **Bug**: `vrwebui_shared.js` 의 `let i=this.m_sInteractionProfile.trim()` 이 `m_sInteractionProfile=null` 일 때 TypeError → save 단계가 silent 하게 fail, blank page.

[GitHub: SteamVR controller bindings save bug](https://github.com/ValveSoftware/openvr/issues/1659) + [Steam Community thread](https://steamcommunity.com/app/250820/discussions/3/596271068722815083/) 에서 6 년 이상 지속.

### 5.2 패치 방법

`C:\Program Files (x86)\Steam\steamapps\common\SteamVR\resources\webinterface\vrwebui_shared.js` 의 해당 line 을 다음과 같이 수정:
```javascript
// 기존
let i=this.m_sInteractionProfile.trim()

// 수정
let i=(this.m_sInteractionProfile || "").trim()
```

또는 nullish 처리:
```javascript
let i=(this.m_sInteractionProfile ?? "").trim()
```

### 5.3 위험

- **Steam 자동 update 시 revert**: SteamVR 가 자동 update 되면 패치 무효화.
- **다른 file checksum 영향**: SteamVR 가 integrity check 하면 startup 거부 가능.
- **비공식 patch**: Valve 가 보장 안 함. 사용자 환경 의존.

### 5.4 적용성

15 분 작업 → 운 좋으면 **즉시 Personal Binding 저장 가능**. 그러면 우리 SteamVR Action API path 가 자동 작동 → 기존 코드 변경 0.

→ **무료 + 15 분으로 시도 가능, 작동 시 가장 빠른 해결**.

### 5.5 다른 보조 workaround

같은 thread 의 보조 fix:
1. **Restart SteamVR** + 모든 "required" bindings 명시 assign 후 save
2. **Run Steam as administrator**
3. **SteamVR 의 Documents 폴더 read-only 해제**

→ 패치 전에 먼저 시도 권장 (위험 0).

## 6. 옵션 E: Custom OpenVR Driver / Bridge

### 6.1 정체
SteamVR 의 add-on driver 를 우리가 작성. PICO Connect 의 prism driver 가 emit 한 input 을 intercept + 우리 앱으로 직접 deliver.

### 6.2 사용 가능한 컴포넌트

| Component | 상태 | 라이선스 |
|---|---|---|
| [OpenVR-InputEmulator](https://github.com/matzman666/OpenVR-InputEmulator) | **Deprecated** (SteamVR 1.14.15 이후 broken) | GPL |
| [OpenVR-InputEmulator-Fixed (forks)](https://github.com/Erimelowo/OpenVR-InputEmulator-Fixed) | 부분 작동 (WIP) | GPL |
| [Simple-OpenVR-Bridge-Driver](https://github.com/ju1ce/Simple-OpenVR-Bridge-Driver) | 활성 | MIT |
| [ViGEmBus](https://github.com/nefarius/ViGEmBus) | 활성 (Windows kernel-mode game controller emulation) | BSD |
| [OpenVR Driver Tutorial](https://github.com/terminal29/Simple-OpenVR-Driver-Tutorial) | tutorial 만 | MIT |
| [Joy2OpenVR](https://github.com/mmorselli/Joy2OpenVR) | DirectInput → OpenVR controller commands | LGPL |

### 6.3 우리 case 의 작업량

8-15 시간:
1. C++ OpenVR driver project 생성 + 빌드 환경 setup (Visual Studio)
2. `IServerTrackedDeviceProvider` + `ITrackedDeviceServerDriver` 구현
3. PICO prism driver 의 input 을 capture 하는 shim 또는 ViGEmBus 가상 controller
4. 우리 Python 앱 ↔ driver IPC 채널 (shared memory 또는 named pipes)
5. 우리 `vr_sampler.py` 의 새 backend
6. 검증 + 디버깅

### 6.4 위험

- **Valve API 변경 risk**: SteamVR 1.14.15 이후 OpenVR-InputEmulator 가 죽은 사례 — Valve 가 input API 를 자주 변경.
- **kernel-mode driver signing**: Windows 11 은 unsigned kernel driver 거부. 코드 서명 인증서 필요 ($300+/year).
- **maintenance 부담**: SteamVR 업데이트 마다 재빌드.

→ **Long-term solution 으로는 부적합**. 단기간 시도해 볼 가치 있을 때만.

---

## 7. 옵션 F: PICO Connect Experimental OpenXR Runtime

### 7.1 정체
PICO Connect 의 PicoStreamingXR runtime 으로 ActiveRuntime switch → SteamVR 없이 OpenXR 앱 직접 streaming.

### 7.2 우리 10th session 결과 (시도 끝남)

- [Path 5: pyopenxr Action API (headless)](../ust_hm_grip/scripts/diagnose_pyopenxr_controller.py): 우리 session FOCUSED 도달 못 함 → `is_active=False`
- DCS/BMS 등 graphics binding 있는 *scene application* 은 정상 작동 보고 ([DCS forum thread](https://forum.dcs.world/topic/372463-pico-headsets-pico-connect-built-in-experimental-openxr-runtime/), [Falcon BMS](https://forum.falcon-bms.com/topic/28080/pico-connect-and-bms-openxr/14))

### 7.3 우리 case 의 적용성

이 옵션은 우리가 Isaac Sim 자체를 PicoStreamingXR runtime 위에서 boot 시키는 방향:
- Isaac Sim 의 `--render_mode openxr_pico` 같은 새 mode 추가
- Isaac Sim 의 graphics rendering 이 PICO runtime 으로 forward
- 우리 pyopenxr session 도 정상 작동 (Isaac Sim 의 visible session 안에서)

문제: Isaac Sim 의 omni.kit.xr.core 가 PICO runtime 과 호환되는지 미보장. Phase 1.5 에서 시도 했으나 hand_tracking 채널만 검증했고 controller path 는 unclear.

### 7.4 위험 + 적용성

- 추가 검증 비용 큼 (Isaac Sim 의 XR backend 가 PICO runtime 과 정상 작동하는지)
- 우리 진단 toolkit 으로 일부 재검증 가능
- 단독 솔루션으로는 ALVR / Virtual Desktop 보다 비효율

→ **다른 옵션 모두 실패 시 마지막 시도**.

## 8. 옵션 G: Steam Link for PICO (Valve official, 신규)

### 8.1 정체
Valve 가 PICO 헤드셋용 Steam Link 공식 출시 (2025-late). PICO 4 Ultra / PICO 4 / PICO Neo 3 지원.

### 8.2 우리 환경 호환성

- 공식 Valve 솔루션 → SteamVR 의 Action API binding pipeline 과 일관성 높음
- 새 출시라 PICO 4 + 우리 use case 의 검증 데이터 부족
- 무료 ([Steam Link app](https://store.steampowered.com/app/353380/Steam_Link/))

### 8.3 통합 비용

1 시간:
1. PICO 헤드셋에 Steam Link app 설치 (PICO Store)
2. PC + 헤드셋 페어링
3. SteamVR add-on toggle (`prism` ↔ Steam Link driver?)
4. 우리 `run_teleop.py` 의 `--vr_runtime` 분기에 `steam_link` 추가

### 8.4 위험

- **Personal Binding commit issue 가 SteamVR 측 (driver 가 아님) 이라면 영향 없을 수 있음** — Steam Link 가 다른 binding 경로 사용한다면 우리 issue 우회 가능.
- **출시 직후라 안정성 미보장** — beta 상태 가능성.

→ **Personal Binding patch (옵션 D) 와 함께 시도 권장**. Steam 공식이라 Valve 가 fix 할 가능성 높음.

## 9. 옵션 H: Soft Fallback (키보드 / 외부 입력 디바이스)

### 9.1 정체
PCVR controller 의 trigger/grip 채널을 포기하고 다른 입력 채널로 대체:
- 키보드 단축키 (`C` = left close, `V` = right close)
- USB foot pedal (게이밍 / 의료용)
- 게임패드 (Xbox controller)
- 별도 손가락 센서 (글로브)

### 9.2 우리 case 의 적용성

- 코드 변경 1-2 시간 (`run_teleop.py` 에 keyboard listener thread 추가)
- 100% 작동 보장
- 그러나 **두 손이 PICO controller 잡고 있어야 함** → 발 pedal 또는 음성 명령으로 close trigger 필요
- **운용 ergonomics 저하** — 사용자가 컨트롤러 잡은 채 키보드 누를 수 없음

### 9.3 구체적 패턴

```python
# run_teleop.py 추가
import keyboard

def _keyboard_thread():
    while True:
        if keyboard.is_pressed('c'):  # left close
            device.force_gripper_close('left')
        if keyboard.is_pressed('v'):  # right close
            device.force_gripper_close('right')
        time.sleep(0.05)

# OR pedal via vJoy / pyHID
```

### 9.4 위험

- **사용자 양손이 PICO controller 잡고 있는 한 키보드 누름 불편**
- **VR immersion 깨짐**

→ **다른 옵션 모두 차단 시 운용 가능 보장 위한 최후 fallback**. 운용 중에는 별도 발 pedal + vJoy 통합이 ergonomics 적으로 우수.

## 12. 우리 `vr_sampler.py` 의 대체/확장 패턴

새 backend 추가 시 권장 architecture:

```python
# teleop/base_sampler.py (신규)
class BaseSampler(ABC):
    @abstractmethod
    def snapshot(self) -> Dict[str, Any]:
        """Return the standard ust_hm_grip snapshot dict."""

# teleop/vr_sampler.py (기존, SteamVR/OpenVR backend)
class SteamVRSampler(BaseSampler):  # 기존 코드, 변경 없음
    ...

# teleop/xrobo_sampler.py (옵션 A 신규)
class XRoboSampler(BaseSampler):
    """XRoboToolkit gRPC client.  Emits the same snapshot dict format
    so retargeter + device need not change."""
    def __init__(self, cfg: XRoboSamplerCfg):
        self._stub = ...   # gRPC stub
    def snapshot(self) -> Dict[str, Any]:
        # convert gRPC response -> ust_hm_grip snapshot format
        return { "controllers": {"left": {"buttons": {"trigger": resp.left.trigger, "grip": resp.left.grip}, ...}, ...}, ... }

# teleop/keyboard_sampler.py (옵션 H 신규)
class KeyboardSampler(BaseSampler):
    """Fallback: synthesize controller buttons from keyboard state."""
    ...

# gr1t2_gripper_device.py 변경 (분기 추가)
def _create_sampler(backend: str, cfg) -> BaseSampler:
    if backend == "openvr":
        return SteamVRSampler(...)
    elif backend == "xrobotoolkit":
        return XRoboSampler(...)
    elif backend == "keyboard":
        return KeyboardSampler(...)

# run_teleop.py 추가
parser.add_argument("--input_backend", default="openvr",
                    choices=["openvr", "xrobotoolkit", "keyboard"])
```

→ retargeter (`gr1t2_gripper_retargeter.py`) 와 robot env config 는 **변경 0**. snapshot dict 의 형식이 유지되는 한 backend 만 swap.
