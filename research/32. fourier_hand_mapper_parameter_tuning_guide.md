# 32. UDCAP ↔ Isaac Lab 손가락 매칭 파라미터 튜닝 가이드

> 작성: 2026-05-03 (9.26차 fix 직후)
> 목적: 사용자 질문 "scale + rest cal 만 잘 잡히면 매칭이 거의 되는가? 파라미터 어떻게 조정하나?" 에 대한 정량 답변

---

## 0. 한 줄 답

> **부분적으로 맞다 — scale + rest cal 가 매칭의 60~70%를 결정한다. 나머지 30~40%는 (1) UDCAP 글러브 자체 캘리브레이션, (2) 사용자 시작 자세 안정성, (3) EMA alpha, (4) env step rate 가 결정한다. 100% 1:1 매칭은 quat→bend 변환의 비선형성 때문에 이론상 어렵고, 시각적으로 80~90% 매칭이 현실적 목표다.**

## 1. 매칭 정확도를 결정하는 6가지 요인 (영향력 순)

| # | 요인 | 영향력 | 조정 방법 | 현재 9.26 default |
|---|---|---|---|---|
| 1 | **UDCAP 글러브 자체 calibration** | ⭐⭐⭐⭐⭐ | UDCAP 트레이 > F1 calibration (open/fist/per-finger) | 사용자 측 |
| 2 | **VMC rest cal 정확도** | ⭐⭐⭐⭐⭐ | `--vmc_rest_frames` + 시작 자세 (손 펴고 가만히) | 10 (권장 60) |
| 3 | **finger_proximal_scale** | ⭐⭐⭐⭐ | `--finger_proximal_scale` | 2.5 |
| 4 | **사용자 시작 자세** | ⭐⭐⭐⭐ | 운영 가이드 (시작 시 손 완전히 펴고 1초 가만히) | — |
| 5 | **finger_lp_alpha** (EMA) | ⭐⭐ | `--finger_lp_alpha` | 0.4 |
| 6 | **env step rate** | ⭐⭐ | `decimation` (env_cfg) | 1 (120 Hz) |

**중요**: #1과 #2가 잘못되면 #3~#6를 아무리 조정해도 매칭이 안 됩니다. 항상 #1 → #2 → #3 순서로 확인.

## 2. 파라미터별 동작 메커니즘 (코드 레벨)

### 2.1 데이터 파이프라인

```
UDCAP 글러브 센서
   ↓ (UDCAP driver F1 calibration 적용)
VMC packet (qx, qy, qz, qw 양쪽 손 15 bones × 2)
   ↓ UDP port 39539 → VMCHandReceiver
mapper.map_hand_vmc(bones, is_right)
   ├─ _vmc_quat_relative_to_rest()  ← rest cal 적용
   │     out_quat = input_quat × inverse(rest_avg)
   ├─ _quat_to_bend(qx,qy,qz,qw)    ← quat → [0, 1] 굽힘 정도
   │     angle = 2 * acos(|qw|)
   │     raw01 = clamp(angle/π, 0, 1)
   ├─ _amplify(raw01, scale, limit) ← scale 적용
   │     tanh path: out = limit × tanh(raw × scale)
   │     linear path: out = raw × scale × limit
   ├─ _fill_mimic_inplace()         ← intermediate/distal 채우기
   │     intermediate = proximal × 0.85
   │     distal = thumb_pitch × 0.75
   └─ _clamp_array()                ← URDF range 안에 clip

Retargeter (gr1t2_retargeter.py)
   ├─ pack_22d(left_11, right_11)   ← 22D 액션 벡터로 패킹
   ├─ PACK_22D_SIGNS 적용           ← 부호 반전 (GR1T2 USD 음수 굽힘)
   └─ EMA: out = α × new + (1-α) × prev   ← finger_lp_alpha

Isaac Lab Pink IK + PD controller
   └─ 매 env_step (120 Hz) 마다 articulation 에 명령
```

### 2.2 핵심 상수 (mapper 내부)

| 상수 | 값 | 의미 |
|---|---|---|
| `_PROXIMAL_MAX` | **1.57 rad** (~90°) | GR1T2 USD 손가락 MCP 굽힘 한계 |
| `_THUMB_YAW_RANGE` | **(-0.5, 1.0)** | 엄지 opposition 범위 |
| `_THUMB_PITCH_MAX` | **1.2 rad** (~69°) | 엄지 굽힘 한계 |
| `intermediate_mimic` | **0.85** | PIP joint = proximal × 0.85 (mimic) |
| `distal_mimic` | **0.75** | thumb DIP = thumb pitch × 0.75 (mimic) |

**유의**: 사용자 손가락의 자연스러운 max 굽힘은 **약 90° (1.57 rad)** 입니다. GR1T2 USD limit 도 1.57 rad로 동일해서 1:1 매칭이 이론상 가능. 그러나 quat → bend 변환의 비선형성 (`2 × acos(|qw|)`) 때문에 실제 raw01 값은 사용자 90도 굽힘에서도 0.5 정도에 머무름.

### 2.3 quat → bend 변환의 비선형성 (수학)

```
사용자 손가락 굽힘 각도 θ (radian)
   ↓
VMC quat: qw ≈ cos(θ/2)
   ↓ _quat_to_bend(): angle = 2 × acos(|qw|) = θ
   ↓ raw01 = θ / π
   ↓
사용자 90° 굽힘 → θ = π/2 → raw01 = 0.5
사용자 180° 굽힘 → θ = π → raw01 = 1.0  ← 손가락은 180° 못 굽힘
```

→ **사용자 max 굽힘 (90°) 에서 raw01 ≈ 0.5** 가 일반적. scale=2.5 로 amplify 해야 robot 이 ~76° 굽힘.

## 3. 파라미터 상세 설명

### 3.1 `--finger_proximal_scale` (default 2.5)

#### 동작
`out = limit × tanh(raw01 × scale)` (tanh 활성 시) 의 `scale` 인자.

#### Scale 변화 시 robot 굽힘 (사용자 90° 굽힘 = raw01=0.5 기준)

| scale | tanh(0.5 × scale) | 로봇 굽힘 (radian) | 시각적 굽힘 (도) | 평가 |
|---|---|---|---|---|
| 1.0 | 0.462 | 0.73 | 42° | **❌ 굽힘 부족** (사용자 90° → 로봇 42°) |
| 1.5 | 0.635 | 1.00 | 57° | 굽힘 부족 |
| 2.0 | 0.762 | 1.20 | 69° | 약간 부족 |
| **2.5** | **0.848** | **1.33** | **76°** | **★ 자연스러움** (현재 default) |
| 3.0 | 0.905 | 1.42 | 81° | 거의 매칭 |
| 3.5 | 0.940 | 1.48 | 85° | 약간 saturate |
| 4.0 | 0.964 | 1.51 | 87° | 거의 saturate |
| 5.0 | 0.987 | 1.55 | 89° | full curl 도달 |
| 10.0 | 0.999+ | 1.57 | 90° | **❌ 약간 굽힘에도 즉시 saturate** |

#### 사용자 약 50° 굽힘 (raw01 ≈ 0.28) 기준

| scale | 로봇 굽힘 (도) | 평가 |
|---|---|---|
| 1.0 | 25° | 굽힘 부족 |
| 2.5 | 50° | **1:1 매칭** |
| 5.0 | 76° | 과민 반응 |

#### 너무 작을 때 (scale < 2.0)
- 사용자가 손을 굽혀도 로봇 손가락이 거의 안 굽혀짐
- 사용자가 풀로 굽혀야 로봇이 절반 정도 굽혀짐
- "로봇이 굽힘에 둔감해 보임"

#### 너무 클 때 (scale > 4.0)
- 사용자 약간 굽힘에도 로봇이 full curl 로 saturate
- 미세한 조작 (반쯤 잡기 등) 불가능
- "로봇이 항상 풀 fist 상태"

#### 권장 튜닝 절차
1. default=2.5 로 시작
2. 사용자 90° 굽힘 시 로봇이 시각적으로 1:1 가까우면 OK
3. 사용자 굽혔는데 로봇 부족 → +0.5 (3.0 시도)
4. 약간 굽혔는데 로봇 saturate → -0.5 (2.0 시도)

### 3.2 `--finger_thumb_scale` (default 2.5)

엄지의 `pitch` (굽힘) 에만 적용. 엄지 yaw (opposition) 는 별도 piecewise 매핑이라 scale 영향 없음.

엄지 limit `_THUMB_PITCH_MAX = 1.2 rad`(~69°). proximal 보다 작음 — 사용자 엄지 굽힘 max도 보통 60~70° 정도라 적절히 매칭.

권장: `--finger_proximal_scale` 와 동일한 값으로 시작. 엄지가 따로 saturate 되거나 부족하면 별도 조정.

### 3.3 `--finger_use_tanh` (default true) — **켜놓는 것 강력 추천**

#### True (tanh)
```
out = limit × tanh(raw01 × scale)
```
- 작은 raw01 에서 derivative ≈ scale × limit (작은 굽힘 amplify 잘됨)
- 큰 raw01 에서 limit 에 부드럽게 asymptote (saturation 매끄러움)
- **UDCAP RSSI 비대칭** (왼손 vs 오른손 신호 강도 차이) 에 강함

#### False (linear)
```
out = raw01 × scale × limit
```
- 모든 raw01 에서 derivative = scale × limit (균일)
- raw × scale > 1 시 hard-clip 으로 한 번에 saturate
- 한쪽 손이 일찍 saturate 하면 다른 쪽이 mid-range 인 상태로 굳음

#### 비교 예시 (scale=2.5)
| raw01 | tanh out | linear out | linear clamp 후 |
|---|---|---|---|
| 0.1 | 0.39 (25%) | 0.39 (25%) | 0.39 |
| 0.3 | 1.06 (68%) | 1.18 (75%) | 1.18 |
| **0.4** | **1.27 (81%)** | **1.57 (100%)** | **1.57** ← linear가 먼저 saturate |
| 0.5 | 1.33 (85%) | 1.96 → clip to 1.57 | 1.57 |
| 0.7 | 1.45 (92%) | 2.74 → clip to 1.57 | 1.57 |

→ **linear 는 raw 0.4 부터 saturate**, tanh 는 0.7 까지도 mid-range 유지. **tanh 가 거의 항상 좋음**.

### 3.4 `--vmc_subtract_rest` (default true) + `--vmc_rest_frames` (default 10, 권장 60)

#### 동작
- 첫 `vmc_rest_frames` 프레임 동안 사용자 "open hand" 자세 quat 평균
- 그 이후 `quat_relative = current_quat × inverse(rest_avg)` 로 변환
- → 사용자 시작 자세가 mapper 의 "0 굽힘" 기준 점

#### 수학적 효과 (rest cal 정확도가 baseline 결정)

```
사용자 시작 시 손가락이 약간 굽힌 상태 (예: index 10° 굽힘)
   ↓ vmc_rest_frames 동안 그게 rest 로 학습됨
사용자 90° 굽힘 시:
   ↓ relative_angle = 90° - 10° = 80° (NOT 90°)
   raw01 = 80/180 = 0.444
   tanh(0.444 × 2.5) = 0.804
   out = 1.57 × 0.804 = 1.26 rad (72°)
   → 사용자 90° → 로봇 72°  (10° 손해)

사용자 시작 시 손가락 펴진 상태 (rest = 0°):
   ↓ rest = 0
   사용자 90° 굽힘 → relative = 90°
   raw01 = 0.5
   tanh(0.5 × 2.5) = 0.848
   out = 1.57 × 0.848 = 1.33 rad (76°)
   → 사용자 90° → 로봇 76°  (정상)
```

#### `vmc_rest_frames` 값별 영향

| frames | 시간 (@120Hz) | 평가 |
|---|---|---|
| 5 | 42 ms | **너무 짧음** — 첫 잠깐의 손 떨림이 그대로 baseline |
| 10 | 83 ms | 짧음 — 9.18 default, 9.26 환경에선 부족 |
| 30 | 250 ms | 적당 |
| **60** | **500 ms** | **★ 권장** (안정적 평균, 사용자 0.5초 가만히) |
| 120 | 1 s | 안전하지만 사용자 대기 시간 길어짐 |
| 240 | 2 s | 너무 김 — 사용자가 가만히 있기 어려움 |

#### 너무 작을 때
- 첫 frame 의 손가락 noise / fidget 이 baseline 으로 학습됨
- 결과: 사용자 펴진 손에서도 robot 이 약간 굽혀진 상태로 시작
- 사용자 max 굽힘 시 robot 이 full curl 못 도달

#### 너무 클 때
- 사용자가 5~10초 가만히 손 펴고 있어야 함 (불편)
- 사용자가 중간에 손 움직이면 그 움직임도 평균에 들어가서 baseline 부정확

#### 사용자 운영 가이드
1. 시뮬 시작 직전 손가락 완전히 펴기 (다섯 손가락 사이 약간 벌리고)
2. 시뮬 시작 후 **1초 이상 가만히** 유지
3. 그 후 자연스러운 손가락 동작 개시
4. 만약 baseline 잘못 잡혔다고 느껴지면 → 시뮬 종료 후 재시작 (현재 hot-reload 미구현)

### 3.5 `--finger_lp_alpha` (default 0.4) — EMA Low-Pass

#### 동작
```
output[t] = α × current[t] + (1-α) × output[t-1]
```

#### α 값별 시간 상수 (env step 120 Hz, dt = 8.33 ms)

| α | tau ≈ -dt/ln(1-α) | 10~90% rise time | 평가 |
|---|---|---|---|
| 0.1 | 79 ms | 184 ms | **너무 강함** — 사용자 빠른 동작에 못 따라옴 |
| 0.2 | 37 ms | 86 ms | 강한 smoothing — jitter 심한 환경에 |
| 0.3 | 23 ms | 54 ms | 중간 |
| **0.4** | **17 ms** | **39 ms** | **★ 현재 default** (자연스러운 균형) |
| 0.6 | 9 ms | 21 ms | responsive |
| 0.8 | 5 ms | 11 ms | 거의 raw |
| 1.0 | — | 0 ms | **필터 비활성** |

#### 너무 작을 때 (α < 0.2)
- 사용자 빠른 손가락 동작에 robot 이 늦게 따라옴 (lag 100ms+)
- 그러나 노이즈 / jitter 는 매우 부드럽게 흡수
- "robot 손가락이 둔하게 움직임"

#### 너무 클 때 (α > 0.8)
- 거의 raw 신호 그대로 → 100ms 짜리 noise spike 도 그대로 robot 에 전달
- 사용자 손가락 자연 떨림이 robot 에 그대로 보임
- "robot 손가락이 떨림"

#### 권장 튜닝 절차
1. default 0.4 로 시작
2. lag 거슬리면 → 0.6 으로 (responsive)
3. 떨림이 심하면 → 0.2 로 (smoother)

### 3.6 `decimation` (env_cfg, default 1 since 9.24)

#### 동작
- env step rate = sim.dt × decimation 의 inverse
- 9.24 default: `decimation=1, sim.dt=1/120` → **120 Hz env step**
- 즉 매 8.33ms 마다 `teleop_device.advance()` 호출

#### 영향
| decimation | env step rate | sub-sample 대 UDCAP 140 Hz |
|---|---|---|
| 6 | 20 Hz | 7:1 (구식, 9.23 이전) |
| 3 | 40 Hz | 3.5:1 |
| 2 | 60 Hz | 2.3:1 |
| **1** | **120 Hz** | **1.17:1** ★ 현재 default |
| 0 (불가) | — | — |

#### 변경 권장 X
- 120 Hz 가 UDCAP 140 Hz / SteamVR 120 Hz 와 거의 1:1 매칭
- 240 Hz로 가도 input ceiling 초과로 효과 없음 (research/30 참조)
- Pink IK QP budget 8.33 ms 에 P99 5 ms 사용 — 안전 zone
- → 9.26 사용자 환경에선 그대로 두기

## 4. 단계별 튜닝 절차 (사용자 권장)

### Step 1: UDCAP 글러브 자체 calibration 확인 (가장 중요)
```
1. UDCAP 시스템 트레이 위젯 열기
2. "Not Calibrated" 표시 있으면 F1 누르기
3. 가이드 따라 open / fist / per-finger sequence 진행
4. 양쪽 글러브 모두 calibrated 상태 확인
```
**이게 안 되면 아래 모든 파라미터가 무의미합니다.**

### Step 2: 9.26 default 명령 실행
```powershell
# Lock cleanup
Get-ChildItem "$env:USERPROFILE\AppData\Local\ov" -Filter "*.lock" `
    -Recurse -Force -ErrorAction SilentlyContinue | Remove-Item -Force

# 9.26 기본 명령
python -X utf8 -m ust_ws.ust_fourier_260421.scripts.run_teleop `
    --env_variant robot_only --teleop_device pico_udcap `
    --finger_proximal_scale 2.5 --vmc_rest_frames 60 `
    --path_b_port 39539 `
    --ignore_trackers true `
    --finger_lp_alpha 0.4
```

### Step 3: 시작 직후 손 자세 (rest cal)
- 시뮬 부팅 후 콘솔에 `[GR1T2Retarget #1 first-call]` 메시지 보일 때까지 대기
- **두 손 완전히 펴고 (손가락 사이 약간 벌리고)**
- **1.5초 가만히 유지** (vmc_rest_frames=60 @ 120Hz)
- 그 후 자연스러운 손가락 동작 시작

### Step 4: 매칭 정확도 시각 검증
| 사용자 동작 | 로봇 기대 동작 |
|---|---|
| 손 펴기 (모든 손가락 펴짐) | 모든 손가락 0~10° 정도 (거의 펴짐) |
| 90° 굽힘 (반쯤 fist) | 70~85° 굽힘 (시각적으로 비슷) |
| 풀 fist (손가락 한껏 굽힘) | 85~90° 굽힘 (거의 full curl) |
| 엄지만 굽힘 | 엄지만 굽힘 |
| 엄지만 다른 손가락에 닿기 (opposition) | 엄지가 손바닥 쪽으로 회전 |

### Step 5: 매칭 안 되면 trouble matrix 적용

| 증상 | 원인 추정 | 조치 |
|---|---|---|
| 손가락 거의 안 굽혀짐 | scale 너무 작거나 rest cal 잘못 | `--finger_proximal_scale 3.5` 시도 |
| 약간만 굽혀도 full curl saturate | scale 너무 큼 | `--finger_proximal_scale 1.5` 시도 |
| 시작부터 일부 손가락 굽혀져 있음 | rest cal 시점 손이 굽혀짐 | 시뮬 종료, 다시 시작 시 손 정확히 펴고 가만히 |
| 사용자 빠른 동작 follow X | EMA α 너무 낮음 | `--finger_lp_alpha 0.6` |
| 손가락 떨림 / 진동 | EMA α 너무 높음 또는 raw 노이즈 | `--finger_lp_alpha 0.2` |
| 한 쪽 손만 매칭 잘 됨 | UDCAP RSSI L/R 비대칭 | tanh 켜져 있으면 그래도 균형 — 글러브 위치 점검 |
| 엄지만 안 굽혀짐 | thumb scale 부족 | `--finger_thumb_scale 3.5` |

## 6. 매칭 정확도 검증 — logs 에서 어떻게 확인

### 6.1 데이터 도착 확인
```
[GR1T2FourierUDCAPDevice][advance #100] VMC port=39539 bones_received=30
```
- **bones_received=30** 이면 정상 (15 bones × 2 hands)
- < 30 이면 packet 일부 손실 → UDCAP 측 문제

### 6.2 매핑 결과 확인
```
[GR1T2Retarget #100] L=default(disabled)/vmc R=default(disabled)/vmc | trackers=5 | ...
  L: l_idx=-0.71[-0.87,-0.00]Δ0.87 ...
```
- `l_idx = -0.71 [min=-0.87, max=-0.00] Δ=0.87` 의 의미:
  - 현재 left index proximal 굽힘 = 0.71 rad (약 41°)
  - 시작부터 max 굽힘 = 0.87 rad (50°) ← 사용자 max curl
  - 시작부터 max 폄 = 0.00 rad (rest cal 정확)
  - Δ = 0.87 (1.57 의 55%) ← 사용자가 충분히 굽힘 안 함 OR scale 더 필요

#### 좋은 매칭의 logs 예시
```
L: l_idx=-1.20[-1.45,-0.00]Δ1.45  ← max 1.45 rad (92%) ★ 좋음
   l_mid=-0.85[-1.40,-0.00]Δ1.40  ← max 1.40 rad (89%) ★ 좋음
   l_pky=-0.72[-1.35,-0.00]Δ1.35  ← max 1.35 rad (86%) 좋음
```

#### 부족한 매칭의 logs 예시 (현재 9.26 user 로그)
```
L: l_idx=-0.71[-0.87,-0.00]Δ0.87  ← max 0.87 rad (55%) ❌ 부족
   l_mid=-0.56[-0.95,-0.00]Δ0.95  ← max 0.95 rad (60%) 부족
   l_pky=-0.63[-0.69,-0.00]Δ0.69  ← max 0.69 rad (44%) ❌ 매우 부족
```

→ **scale 을 3.5~4.0 으로 올리면 max 가 1.30+ 에 도달할 수 있음**.

### 6.3 Pink IK / articulation 정상 확인
```
[FingerCmp #100] L_indexp: act_tgt=-0.707 jpt=-0.707 pos=-0.707
```
- **act_tgt = jpt = pos** 면 모든 단계 정상
- 한쪽이 다르면 아래 진단:
  - act_tgt ≠ jpt → action manager / Pink IK 측 문제
  - jpt ≠ pos → physics PD impedance / joint limit / friction 문제

## 7. 100% 1:1 매칭이 어려운 이유

### 7.1 quat → bend 비선형 변환
```
사용자 90° 굽힘 → quat qw ≈ cos(45°) ≈ 0.707
→ angle = 2 × acos(0.707) = π/2 ≈ 1.57 rad
→ raw01 = 1.57 / π ≈ 0.5  ← NOT 1.0
```
사용자 max 가 raw01 = 0.5 정도라 그대로 출력하면 robot 은 50% 만 굽힘.

### 7.2 tanh saturation
```
out = limit × tanh(raw × scale)
tanh(0.5 × scale) 는 scale → ∞ 일 때만 1.0 도달
```
즉 어떤 scale 을 써도 100% saturate 는 못함. 99% 도달은 가능 (scale=10) 하지만 그 scale 에선 raw=0.1 부근에서 이미 90% 도달 → 부드러운 mid-range 잃음.

### 7.3 GR1T2 USD limit (1.57 rad / 90°)
- 사람 손가락 MCP 굽힘 max 도 ~90° 라 1:1 가능해 보이지만
- 사용자 가 정확히 90°를 굽히기 어렵고 (보통 70~80°)
- robot 이 정확히 90° 도달 시 visual artifact 발생 (URDF 한계)

### 7.4 결론
- **80~90% 시각적 매칭** 이 현실적 목표
- 100% 매칭은 dex-retargeting (DexPilot) URDF + 사용자 손 model 이 정확히 맞춤화된 환경에서나 가능
- 9.26 의 fallback FourierHandMapper 는 그것의 80% 수준 trade-off
