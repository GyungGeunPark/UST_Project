# 30. Isaac Lab용 휴머노이드 로봇 Teleop 대안 — 전신 + 정밀 손가락 엄격 필터 (VR + Pink IK)

**저자 컨텍스트:** Windows 11 + SteamVR + Pico 4 Ultra + UDCAP VR Glove 환경에서 Isaac Lab 내부에 Unitree G1(29-DoF, Inspire FTP 5-손가락 핸드)을 구동 중인 연구자. 팔은 Pink IK로 구동하며 `num_hand_joints=24`, `base_link=pelvis`, 스폰 시 90도 Z-회전을 적용. 현재 증상: Pink IK가 조용히 수렴 실패, 손목 워크스페이스가 비좁게 느껴짐, 24-DoF 핸드 매핑이 불투명, Isaac Sim이 키친 정렬 씬을 부팅하는 데 ~150초 소요.

**날짜:** 2026-04-21 (v2 — 전신 + 정밀 손가락 엄격 필터 적용 재작성)
**범위:** 이 문서는 **휴머노이드 이족 로봇** 중에서 다음 두 조건을 **동시에** 충족하는 플랫폼만 평가한다:
1. **전신(full-body) 제어 가능**: 양 다리 + 토르소(허리) + 양팔을 단일 articulation 로 관절 제어할 수 있어야 함. 모바일 베이스나 고정 베이스 팔 단독은 제외.
2. **정밀 다관절 핸드**: 5-손가락(또는 최소 4-손가락) 다관절 핸드 탑재. 권장 DoF ≥ 10/핸드. 평행 그리퍼(Franka 2F), 패들/단순 엔드이펙터, 핸드 없음은 제외.

**이전 문서와 비교하여 의도적으로 제외된 플랫폼:** Franka Panda (팔 only), Agibot A2D (2-손가락 그리퍼), Unitree H1 (기본 USD 핸드 없음, 4-DoF 팔), Agility Digit v4 (패들형 EE), Kuka LBR iiwa (팔 only), PAL TIAGo (모바일 베이스 + 그리퍼), Booster T1 Standard/Gripper 변형 (핸드 없음 또는 그리퍼). 이들 중 Franka, Agibot, TIAGo는 이 문서 끝 **부록 A (파이프라인 디버깅용 단순 대체 팔)** 에 요건 미충족 전제로 짧게만 남긴다.

## 1. 현재 G1 셋업이 고통스러운 이유 (근본 원인 정리)

대체품을 고르기 전에 지금 보고 있는 증상들이 5-손가락 핸드를 가진 복잡한 휴머노이드에서 "예상되는 실패 모드"라는 점을 기억하자. 동일한 실패 유형은 다른 5-손가락 바이페달 플랫폼(GR1T2 포함)에도 그대로 넘어온다. 그러니 "다른 휴머노이드를 고른다"고 해서 자동으로 해결되지는 않는다 — 단지 더 우호적인 표면으로 고통을 옮기는 것일 수 있다.

G1의 구체적인 통증 포인트를 메커니즘별로:

1. **Pink IK가 조용히 수렴 실패.** `PinkIKControllerCfg(show_ik_warnings=False, fail_on_joint_limit_violation=False)`이 기본값 — `pickplace_unitree_g1_inspire_hand_env_cfg.py` 172-173줄에서 사용. 첫 디버깅 단계로 `show_ik_warnings=True`를 설정; LM 솔버가 포화하면 Pink가 잔차 비용을 출력한다. 또한 90도 Z-회전 후 VR 월드 프레임에서의 타겟 쿼터니언이 실제로 팔의 7-DoF 널스페이스 안에 놓이는지 확인하라 — 그렇지 않으면 `DampingTask(cost=0.5)` (또는 `NullSpacePostureTask`)가 FrameTask보다 높은 우선순위로 솔버를 유휴 자세로 끌어당기고 있다.
2. **좁은 손목 워크스페이스.** G1의 팔은 `left_shoulder_pitch → roll → yaw → elbow → wrist_yaw → wrist_roll → wrist_pitch` 순의 7-DoF 체인. Pink IK는 `left_wrist_yaw_link`를 추적 프레임으로 사용하는데, 이는 마지막 2개 손목 관절의 BEFORE — 즉 `wrist_roll_joint`와 `wrist_pitch_joint`가 방향 타겟 달성에 사용되지 않는다는 의미다. 실질적으로 5-DoF 팔 + 매달려 있는 2개 중복 손목 관절만 얻게 된다. 회전이 비좁게 느껴지는 이유는 거의 확실히 이것이다.
3. **90도 Z-회전 + pelvis 베이스.** `rot=(0.7071, 0, 0, 0.7071)` = `yaw=+90도`. 로봇 바디 프레임에서 "월드 +Y"는 "바디 +X"에 매핑된다. Pink IK는 URDF/바디 프레임에서 동작한다. VR 리타게터가 월드 프레임 쿼터니언을 퍼블리시하지만 `PinkInverseKinematicsActionCfg`는 바디 프레임을 기대하면, yaw에 따라 증가하는 드리프트가 보일 것이다. `UnitreeG1RetargeterCfg`는 내부적으로 이를 처리하지만, 커스텀 글루 코드(당신의 PICO 경로)는 그렇지 않을 수 있다.
4. **24-DoF Inspire 핸드 매핑의 불투명성.** Inspire FTP 핸드는 USD에 24개 관절을 노출하지만 진짜 드라이버 관절은 ~10개뿐이며, 나머지는 mimic 결합된 피치/원위 관절이다. Isaac Lab의 `hand_joint_names` 리스트(당신 env_cfg의 137-161줄)는 `UnitreeG1RetargeterCfg`가 의존하는 특정 순서를 따른다. "12 값 -> 24 값" 단순 복제 또는 브로드캐스트는 원위 관절을 한계까지 밀어 "조용한 실패" 증상을 유발한다 — 솔버가 손가락 PID 타겟과 손목 FrameTask를 동시에 만족시킬 수 없기 때문.

**요약:** 통증의 대부분은 5-손가락 핸드 + 좁은 손목 기구학 타겟 때문이다. 이 사실은 (a) 동일한 바이페달 + 5-손가락 이야기지만 더 관대한 널스페이스 정규화를 가진 쪽(Isaac Lab 2.3의 GR1T2 개선), 혹은 (b) 핸드 mimic 결합이 더 투명한 핸드(Fourier 6-DoF 또는 Dex5-1)로 옮기는 것을 가리킨다.

팔당 체인: `shoulder_pitch -> shoulder_roll -> shoulder_yaw -> elbow_pitch -> wrist_yaw -> wrist_roll -> wrist_pitch -> hand_pitch_link` (7-DoF 직렬 팔). **Pink IK는 `left_hand_pitch_link` / `right_hand_pitch_link`를 타겟으로 삼는다 — wrist_yaw가 아닌 PALM.** 이는 `wrist_yaw_link`를 타겟으로 하는 G1과의 핵심 차이점이다. 7개 팔 관절 모두가 EE 6-DoF 목표에 기여하므로 도달 가능한 손목 방향 엔벨로프가 G1보다 실질적으로 더 크다.

### 초기 포즈
`pos=(0, 0, 0.93)`, `rot=(0.7071, 0, 0, 0.7071)` — G1과 동일한 90도 Z-회전 (리타게터가 yaw를 제대로 처리 중이며, 당신은 같은 패턴을 재사용하면 된다). `base_link_name="base_link"` (`pelvis` 아님).

### Isaac Lab 2.3 (2025-11 릴리스)에서 추가된 개선사항 — 당신의 증상에 직접 적용됨
- **널스페이스 정규화 (`NullSpacePostureTask`)**: 바이메뉴얼 로봇의 팔꿈치 벌어짐 감소. GR1T2와 G1 모두 적용됨.
- **허리 활성화 환경 (`WaistEnabled`)**: 솔버가 `waist_yaw_joint`, `waist_pitch_joint`, `waist_roll_joint`를 손목 타겟이 팔만으로 도달 불가능할 때 사용할 수 있게 함 — 당신의 "좁은 워크스페이스" 증상의 직접 해결책.
- **Pink IK 튜닝 업데이트**: `position_cost=8.0`, `orientation_cost=1.0`, `lm_damping=12`, `gain=0.5`이 GR1T2 태스크의 새로운 2.3 기본값.
- **Manus Vive 장치 지원 env_cfg 통합**: `teleop_devices` 딕트에 `ManusViveCfg`가 이미 연결.
- **LocalFrameTask** (상대 포즈용, Pink IK 확장): 손목 절대 좌표 대신 상대 궤적 명령을 지원 — drift 감소.

### VR teleop 예제

## 21. 제안 (Priority 분류)

### 1순위 (즉시 적용): **Fourier GR1T2 + 6-DoF Fourier hand + `Isaac-PickPlace-GR1T2-WaistEnabled-Abs-v0`**

이유:
1. **Pink IK 설정이 Isaac Lab 2.3에 이미 작성되어 내장됨.** `pickplace_gr1t2_waist_enabled_env_cfg.py`의 `PickPlaceGR1T2WaistEnabledEnvCfg`는 `ust_ws`에 복사 붙여넣기할 수 있는 동작 참조다.
2. **전신 + 정밀 손가락 필터 완벽 통과**: 다리 12 DoF + 허리 3 DoF + 팔 14 DoF + 손 22 DoF (11/핸드) = 총 51 DoF.
3. **내장된 DexPilot 리타게팅 YAML이 있는 11-DoF 핸드** — mimic 결합을 역공학할 필요가 없다; dex-retargeting이 그것을 한다.
4. **Palm 추적 Pink IK 타겟 (`hand_pitch_link`)** 은 7개 팔 관절 모두를 사용 → G1보다 더 큰 손목 방향 워크스페이스.
5. **허리 활성화 변형**은 "팔이 너무 짧다"를 직접 해결.
6. **Manus Vive 장치가 내장 env_cfg에 연결됨**.
7. **널스페이스 정규화기 (`NullSpacePostureTask`)** 가 팔꿈치 벌어짐을 방지.
8. 휴머노이드 내러티브 유지; 170 cm GR1T2는 132 cm G1보다 높은 키친 카운터 씬에 더 잘 맞는다.

**주의:** GR1T2의 더 큰 토르소에 맞춰 kitchen_sorting 테이블과 피스처를 재배치하는 데 0.5-1일 소요.

### 2순위 (백업/병렬): **Unitree G1 29-DoF + Inspire FTP (현재) — `show_ik_warnings=True` + WaistEnabled 패턴 추가 적용**

이유:
1. 이미 구동 중. 투자된 `ust_260220` 작업을 폐기하지 않는다.
2. G1의 통증 원인 3가지 (Pink IK silent fail, 좁은 손목, 24-관절 매핑)을 직접 수정한다:
   - `PinkIKControllerCfg(show_ik_warnings=True)` 설정.
   - `pink_controlled_joint_names`에 `waist_yaw_joint`, `waist_pitch_joint`, `waist_roll_joint` 3개 추가 (GR1T2 `WaistEnabled` 패턴).
   - `FrameTask`의 `frame_name`을 `left_wrist_yaw_link` → `left_rubber_hand_link` (또는 palm 링크)로 이동 실험.
3. GR1T2로의 마이그레이션이 확정되면 G1 env_cfg는 회귀 테스트 기준선으로 유지.

### 3순위 (미래, 6~12개월): **Fourier GR-2 또는 Unitree G1 + Dex5-1 (공식 릴리스 대기)**

두 하드웨어 모두 12 DoF 이상의 5-손가락 핸드로 당신의 UDCAP 21-관절 데이터 활용률을 높인다. Isaac Lab 공식 `isaaclab_assets`에 `GR2_CFG` 또는 `G1_DEX5_CFG`가 나타나면 그 시점 GR1T2에서 마이그레이션.

### 장기 대기 (2027+): **1X NEO Gamma, XPeng IRON, Apptronik Apollo Gen 3**

파트너십 없이는 접근 불가. 연구 내러티브에서 "향후 확장성" 차원으로만 언급. 실제 구동은 GR1T2로 해결.

## 22. 마이그레이션 로드맵 (G1 Inspire → GR1T2 WaistEnabled)

**1단계 — 스톡 GR1T2 WaistEnabled 설정을 ust_ws에 복사** (30분):
```
cp C:/develop/IsaacLab/source/isaaclab_tasks/isaaclab_tasks/manager_based/manipulation/pick_place/pickplace_gr1t2_waist_enabled_env_cfg.py \
   C:/develop/IsaacLab/ust_ws/ust_260220/kitchen_sorting_gr1t2_waist_env_cfg.py
```
클래스 `PickPlaceGR1T2WaistEnabledEnvCfg` → `KitchenSortingGR1T2WaistEnvCfg`로 이름 변경.

**2단계 — `ust_260220/__init__.py`의 임포트 스왑:**
```python
# from .kitchen_sorting_env_cfg import KitchenSortingG1InspireEnvCfg as RobotEnvCfg
from .kitchen_sorting_gr1t2_waist_env_cfg import KitchenSortingGR1T2WaistEnvCfg as RobotEnvCfg
```

**3단계 — `ObjectTableSceneCfg`의 `robot`을 당신의 키친 씬 robocasa 에셋과 결합:**
GR1T2 `base_link_name="base_link"`, `pos=(0,0,0.93)`, `rot=(0.7071, 0, 0, 0.7071)`은 유지하되, `packing_table` 대신 당신의 robocasa 키친 피스처 삽입. GR1T2의 더 큰 도달 엔벨로프에 맞추려면 키친 카운터 높이를 ~0.2 m 높여야 할 것이다.

**4단계 — 액션 텐서 레이아웃 변경 (중요):**
GR1T2 WaistEnabled 액션은 `[left_pos(3), left_quat(4), right_pos(3), right_quat(4), left_hand(11), right_hand(11), waist(3)]` = 39 값 (vs G1 WaistDisabled의 `[..., left_hand(12), right_hand(12)]` = 38). 당신의 PICO 리타게터 글루가 38 대신 39값 (허리 3 포함)으로 내보내도록 업데이트하라 — 허리 3-DoF는 VR 헤드셋 루트 회전 차이에서 유도 (또는 UDCAP/Vive 트래커의 허리 트래커 있다면 그쪽).

**5단계 — UDCAP 글러브 손가락 각도 배관:**
UDCAP은 손당 21 관절 각도를 보고한다. `source\isaaclab\isaaclab\devices\openxr\retargeters\humanoid\fourier\data\configs\dex-retargeting\fourier_hand_right_dexpilot.yml`의 참조 매핑을 사용해, UDCAP의 21 각도 → 11 `R_*` / 11 `L_*` Fourier 드라이버로 매핑하는 작은 `UdcapToFourierRetargeter` 서브클래스를 작성. 이는 ~50 LoC 변경. `fourier_hand_6dof` URDF에서 드라이버 관절 이름을 확인하라 (`R_thumb_proximal`, `R_index_proximal`, `R_middle_proximal`, `R_ring_proximal`, `R_pinky_proximal`, `R_thumb_distal` 6개 드라이버 + mimic 5개).

**6단계 — 마이그레이션 후 첫 주 동안 Pink IK 설정에 `show_ik_warnings=True`를 설정:**
```python
controller=PinkIKControllerCfg(
    articulation_name="robot",
    base_link_name="base_link",           # GR1T2: base_link
    num_hand_joints=22,                    # 11*2
    show_ik_warnings=True,                 # 수렴 신뢰 획득 후 False로 전환
    fail_on_joint_limit_violation=False,
    variable_input_tasks=[
        FrameTask("left_hand_pitch_link",  position_cost=8.0, orientation_cost=1.0, lm_damping=12, gain=0.5),
        FrameTask("right_hand_pitch_link", position_cost=8.0, orientation_cost=1.0, lm_damping=12, gain=0.5),
        DampingTask(cost=0.5),
        NullSpacePostureTask(controlled_joints=[...]),  # GR1T2 stock 참조
    ],
    ...
)
```

**7단계 — 병렬 백업 진입점 (부록 A): Franka 스모크 테스트**
`scripts\environments\teleoperation\teleop_se3_agent.py`를 `ust_ws\teleop\franka_smoke.py`로 복사. 수용 기준: UDCAP + Pico 4 Ultra로, Franka EE가 당신의 오른쪽 손목 포즈를 2 cm RMS 이내로 추적하고 손가락을 쥐는 제스처로 그리퍼가 열리고 닫힌다. 이 조건이 통과하면 알려진 실패 고립: **VR 파이프라인은 정상; 남은 GR1T2 이슈는 당신의 글루가 아닌 휴머노이드 전용 env_cfg에 있다.**

**8단계 — (옵션) GR00T N1.5 finetuning 준비**
당신의 GR1T2 teleop 궤적을 HDF5로 저장 (Isaac Lab `RecordingCfg` 사용), `NVIDIA/Isaac-GR00T` 예제 형식에 맞춰 1000 에피소드 수집 후 finetuning 시도. 목표는 98.8% G1 결과와 유사한 수준의 자율 정책 확보.

**9단계 — 허리 DoF 확장 실험**
WaistEnabled가 허리 3-DoF를 Pink 제어에 추가해도 당신의 VR 헤드셋은 허리 포즈를 직접 제공하지 않음. 두 가지 해결 옵션:
- (a) 허리를 VR 헤드셋 루트 회전에서 파생 (머리 yaw → 허리 yaw + pitch 비례 감쇠).
- (b) Vive 허리 트래커 (HTC Vive Tracker 3.0) 추가 → ManusViveCfg 패턴 재사용.
옵션 (b)가 연구 품질 높음. `ManusViveCfg`의 `torso_tracker_serial` 필드가 이를 기대.

## 23. 하지 말아야 할 것들에 관한 참고

- **Apollo / Optimus / NEO / IRON / Phoenix / Walker S2 통합을 직접 굴리지 말라.** 공개 URDF 없음, USD 없음. 낭비되는 노력. 파트너십 공지가 나오면 재평가.
- **스톡 Unitree H1 (`H1_CFG`)으로 조작 실험하지 말라.** 4-DoF 팔 + 핸드 없음으로 손목 공간 6-DoF teleop 불가. H1-2 + Inspire/Dex5가 필요하며 이는 2026-04 시점 Isaac Lab 공식 미통합.
- **`show_ik_warnings=True`로 어떤 타겟이 실패하는지 볼 수 있기 전까지는 G1 Inspire를 YAML 리타게팅 변경만으로 고치려 하지 말라.** 24-관절 매핑 레이어는 레드 헤링일 가능성이 크다 — 진짜 버그는 아마도 손목 FrameTask 프레임(`wrist_yaw_link` vs `rubber_hand_link`)이 90도 Z-회전이 당신의 VR 타겟을 팔의 특이 원뿔에 매핑한 후 도달 불가능하다는 것이다.
- **부팅 시간을 로봇의 잘못으로 추정하지 말라.** 150초는 robocasa 키친 에셋 때문. 같은 씬에서 GR1T2로 전환해도 부팅 시간은 고쳐지지 않는다; 최소 에셋 스모크 테스트 씬으로 옮기는 것만이 해결한다.
- **Booster T1 / GR-2 / Dex5-1 기다리며 현재 진행을 멈추지 말라.** GR1T2로 먼저 파이프라인을 완성하면, 차후 하드웨어/소프트웨어 릴리스 시 매핑만 교체하면 되는 구조가 된다.

## 부록 A — 필터 미충족 파이프라인 디버깅용 단순 대체 팔

다음 로봇들은 "전신 + 정밀 5-손가락" 필터를 통과하지 못하지만, **VR teleop 글루 코드 디버깅 / CloudXR 핸드셰이크 검증 / UDCAP 손가락 매핑 검증**용 빠른 스모크 테스트 팔로 유용하다. 연구 플랫폼이 아닌 엔지니어링 도구로만 사용.

### A.1 Franka Panda + 2F 그리퍼
- `FRANKA_PANDA_CFG`, `FRANKA_PANDA_HIGH_PD_CFG`. Pink IK 바로 작성 가능 (`panda_link0` 베이스, `panda_hand` 타겟).
- 부팅 25-40초 (cold). VR 파이프라인 스모크 테스트 전용.
- **휴머노이드 연구 내러티브와 맞지 않음. 매일 아침 1회 구동하여 VR 배관 검증만.**

### A.2 Agibot A2D (바이메뉴얼 2F 그리퍼)
- `AGIBOT_A2D_CFG`. 바이메뉴얼 + 토르소 리프트, 2F 그리퍼 (5-손가락 아님).
- Pink IK 내장 태스크 없음 → ~1-2일 작성 필요.
- 필터 미충족이지만 바이메뉴얼 구조는 GR1T2와 유사, 스모크 테스트 가치 있음.

### A.3 PAL TIAGo++ (모바일 베이스 + 팔)
- Isaac Lab 내장 없음 (CASE 2025 논문의 외부 USD).
- 모바일 베이스 → 바이페달 필터 미충족. 참조용으로만.

**부록 A의 공통 사용 패턴:** 별도 터미널/씬에서 "스모크 테스트 전용" 진입점으로 열어두고, VR 배관 문제가 의심될 때 여기서 먼저 검증. 통과하면 GR1T2로 복귀하여 휴머노이드 고유 이슈에 집중.
