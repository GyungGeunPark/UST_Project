## 1. 사용자 현 시스템 진단 요약

```
사용자 (Pico 4 Ultra HMD + UDCAP 글러브 + Vive forearm trackers)
  ↓ Virtual Desktop (90 Hz)
SteamVR Sampler (120 Hz, pyopenvr)
  ↓ snapshot (latest only)
VMCHandReceiver (UDP 39539, ~140 Hz, latest only)
  ↓ FourierHandMapper.map_hand_vmc() — quat→bend→tanh
GR1T2FourierSteamVRRetargeter (22D + EMA α=0.4 [9.23 fix])
  ↓ 36D action tensor
Isaac Lab ManagerBasedRLEnv (decimation=6, sim.dt=1/120 → env.step 20 Hz)
  ↓ Pink IK (OSQP) + PD (stiffness 10000, damping 100)
PhysX 5.x → GR1T2 articulation (54 joints, 22 손가락)
```

### 1.1 검증된 사실
- `[FingerCmp]` 라인의 `act_tgt = joint_pos_target = joint_pos` 일치 → Pink IK, action manager, PD impedance, articulation 모두 정상
- `[GR1T2Retarget #N]` 의 22D 출력이 frame-to-frame 으로 0↔limit jump → retargeter 출력 자체가 jagged
- 9.23 EMA fix로 retargeter 출력에 single-pole low-pass 도입 (default α=0.4, lag ~30 ms)
- 잔존 문제: env.step 20 Hz가 UDCAP 140 Hz의 7:1 sub-sampling이라는 본질

### 1.2 9.23 fix로 해결된 부분 vs 남은 부분
| 문제 | 9.23 fix | 잔존 |
|---|---|---|
| 출력 22D의 frame-단위 spike | ✓ EMA로 흡수 | 없음 |
| Sub-sampling aliasing (140→20 Hz) | 부분적 (EMA가 일부 흡수) | env step rate 자체가 20 Hz |
| Quat noise → bend angle 증폭 | 부분적 (EMA가 흡수) | mapper내 비선형 변환은 그대로 |
| Pink IK QP 계산 시간 (50 ms tick) | 무관 | OSQP는 평균 1~2 ms 안에 수렴 |

## 2. Isaac Lab/Isaac Sim 손가락 텔레오퍼레이션 한계 분석

### 2.1 본질적 한계가 아닌 근거
1. **NVIDIA가 직접 dexterous teleop을 푸시 중**: GTC 2026에서 Isaac Teleop을 발표하며 MANUS를 공식 데이터 글러브로 채택. MANUS Quantum Mocap Metagloves로 22-DoF Sharpa Wave 손을 Isaac Lab 안에서 millimeter-level fidelity로 제어 ([NVIDIA Technical Blog](https://developer.nvidia.com/blog/streamline-robot-learning-with-whole-body-control-and-enhanced-teleoperation-in-nvidia-isaac-lab-2-3/), [MANUS x Sharpa Use Case](https://www.manus-meta.com/use-cases/teleoperating-a-22-dof-sharpa-hand-inside-nvidia-isaac-lab-using-manus-gloves)).
2. **Isaac Lab 2.3에 Fourier GR1T2 retargeter가 표준 모듈로 포함**: `isaaclab.devices.openxr.retargeters.humanoid.fourier.gr1t2_retargeter` 가 공식 API ([Isaac Lab Docs](https://docs.robotsfan.com/isaaclab_official/main/_modules/isaaclab/devices/openxr/retargeters/humanoid/fourier/gr1t2_retargeter.html)).
3. **TeleOpBench는 Isaac Sim에서 GR1-T2를 포함한 30개 dexterous task를 평가**: 시뮬-실기 강한 상관 입증 ([TeleOpBench](https://gorgeous2002.github.io/TeleOpBench/)).
4. **Isaac Lab Mimic가 GR1T2 1000-demo dataset을 자동 생성**: Isaac-NutPour-GR1T2-Pink-IK-Abs-Mimic-v0 ([Isaac Lab Mimic Docs](https://isaac-sim.github.io/IsaacLab/main/source/overview/imitation-learning/teleop_imitation.html)).

### 2.2 그러나 알려진 약점
| 약점 | 영향 | 완화책 |
|---|---|---|
| 단일-env physics throughput이 MuJoCo의 ~1/20 | 텔레오퍼레이션 시 env step rate 올리기 어려움 | Newton/MuJoCo Warp 백엔드로 교체 (Isaac Lab 3.0) |
| OpenXR/SteamVR 통합은 CloudXR 경유 (Linux Docker 필요) | Windows 환경에서 raw SteamVR 직결 불가 → 우리 시스템처럼 pyopenvr custom path 필요 | OpenXR runtime을 SteamVR로 강제 (`XR_RUNTIME_JSON`) |
| 기본 manager-based env step 20 Hz | 140 Hz 입력 7:1 down-sample | decimation 6→3 또는 2 (40~60 Hz step), Newton 활성화 후 안정성 ↑ |
| OSQP-based Pink IK가 step마다 QP 풀이 | step rate 올릴 시 GPU/CPU 부담 ↑ | DLS IK fallback 또는 cached Jacobian |

### 2.3 결론
> Isaac Lab은 dexterous teleop의 한계가 아니다 — NVIDIA의 공식 push 영역이며 SOTA 사례가 다수 존재. 다만 **PhysX 백엔드의 단일-env throughput, env step 20 Hz, 그리고 우리 케이스의 LP 누락이 결합**되어 손가락 jagged 현상이 보였던 것. 9.23 fix로 LP 누락은 해소됐고, 남은 sub-sampling 문제는 **환경 step rate 상향 + Newton 백엔드 마이그레이션**으로 추가 개선 가능.

## 4. SOTA 텔레오퍼레이션 파이프라인

### 4.1 OpenTeleVision (CoRL 2024)
- **Apple Vision Pro / Quest / VR 헤드셋 generic** + **active stereo camera** (head-mounted, 2~3 DoF actuated)
- 손 root 위치를 IK로 robot end-effector에 retarget, 손 finger pose는 다양한 retargeter 지원
- **Unitree H1 multi-finger hand**, **Fourier GR1 gripper** 모두 검증
- 강점: VR active visual feedback이 fine manipulation에 critical 입증
- 한계: SteamVR 직접 통합 X, Windows 비호환 (Linux + WebRTC 기반)
- 참조: [GitHub](https://github.com/OpenTeleVision/TeleVision), [arXiv 2407.01512](https://arxiv.org/html/2407.01512v2)

### 4.2 Bunny-VisionPro (2024)
- Apple Vision Pro hand pose → bimanual dexterous robot motion **real-time**
- 손가락 cot에 actuator를 탑재해 **vision + touch 양방향 피드백**
- Multi-stage long-horizon dexterous task에서 imitation learning success
- 참조: [Project Page](https://dingry.github.io/projects/bunny_visionpro.html), [arXiv 2407.03162](https://arxiv.org/abs/2407.03162)

### 4.3 Open TeleDex (2025/10)
- **ROS2 native, 3-tier decoupled architecture** ("TripleAny" — any arm × any hand × any input)
- 입력 신호를 `hand_retarget` ROS2 노드에서 표준 "intent signal"로 정규화 → 시뮬레이터 / 실기 / 어떤 hand든 동일 인터페이스
- 새로운 hand pose retargeting 알고리즘 (interoperability 강조)
- 우리 시스템에 직접 차용 가능한 reference architecture
- 참조: [arXiv 2510.14771](https://arxiv.org/abs/2510.14771)

### 4.4 TeleOpBench (RSS 2025 / 5월)
- **Isaac Sim 기반** 30 dexterous task, Unitree H1-2 / **Fourier GR1-T2** / Unitree G1
- 4 입력 modality: MoCap / VR / 외골격 / monocular vision
- 시뮬-실기 강한 상관 → benchmark 신뢰성
- 우리 GR1T2 환경의 evaluation 표준으로 채택 가능
- 참조: [Project Page](https://gorgeous2002.github.io/TeleOpBench/)

### 4.5 FARTS — Fourier Advanced Robot Teleop System
- Fourier 공식 OpenTeleVision 기반 GR1/GR2 텔레오퍼레이션
- VIVE Ultimate Tracker (wrist) + Xsens Metagloves (finger)
- 우리 stack(UDCAP)과 비교: 글러브/트래커가 다르지만 상위 layer (retarget/control)는 유사
- 참조: [GitHub FFTAI/teleoperation](https://github.com/FFTAI/teleoperation)

### 4.6 비교 요약 — 우리 시스템 차별점
| 항목 | 우리 (UDCAP+SteamVR+Isaac Lab) | OpenTeleVision | Bunny-VisionPro | Open TeleDex |
|---|---|---|---|---|
| HMD | Pico 4 Ultra (VD) | Quest/VP | Apple Vision Pro | hardware-agnostic |
| 글러브 | UDCAP (LucidVR-family) | Vision-based | finger-cot 햅틱 | any |
| 백엔드 | SteamVR (Windows native) | OpenXR + WebRTC | visionOS | ROS2 |
| 시뮬레이터 | Isaac Lab | various | real robot | various |
| Finger source | VMC OSC | vision | vision + Vision Pro | normalized intent |
| 강점 | Windows 직접 통합, Vive forearm tracker | Active stereo feedback | Touch feedback | Universal abstraction |
| 약점 | 손가락 frame rate (UDCAP→Isaac Lab pipeline) | Linux/macOS only | Vision Pro 종속 | 미적용 (reference only) |

## 5. Cross-Simulator 데이터 호환성

### 5.1 자산 포맷
| 포맷 | 사용 시뮬 | 변환 |
|---|---|---|
| **USD** | Isaac Sim/Lab (primary) | URDF importer (`isaacsim.asset.importer.urdf`), MJCF importer |
| **MJCF (XML)** | MuJoCo, MuJoCo Playground | URDF→MJCF 변환 (간단), USD→MJCF (제한적) |
| **URDF** | ROS, MuJoCo, SAPIEN, ManiSkill, Genesis | 가장 호환성 높은 중간 포맷 |
| **SDF** | Gazebo | URDF로 변환 |

> **권장 워크플로**: GR1T2 USD → URDF (Isaac Lab 자동 변환, Pink IK 용도) → MuJoCo MJCF (sim2sim 검증) → 양쪽 시뮬 모두에서 동일 robot 사용

### 5.2 데이터셋 포맷
| 포맷 | 주요 사용처 | 특징 |
|---|---|---|
| **LeRobotDataset v3.0** ★ | HuggingFace LeRobot, NVIDIA + HF 통합 | Parquet + MP4, episode-based, streaming, hub native |
| **Robomimic HDF5** | Isaac Lab Mimic, robosuite | env_args 메타데이터, demo_N groups, MuJoCo state vector |
| **HDF5 (custom)** | RoboCasa, ALOHA | 프로젝트 별 변형 |
| **TFDS / Open X-Embodiment** | Google 공동 연구 | TFRecord 기반 |
| **DROID** | Stanford ALOHA fork | HDF5 + camera videos |

> **권장 표준**: **LeRobotDataset v3.0**. NVIDIA-HuggingFace 공식 협력 (2025), Isaac Lab도 v3 reader 추가 예정. cross-sim 시 로컬 Parquet으로 episode 저장 → HF Hub로 push → 모든 학습 시뮬에서 streaming load 가능.

### 5.3 RoboVerse MetaSim — 다중 시뮬 추상화 (RSS 2025)
- 8개 시뮬 (Isaac Lab/Gym, MuJoCo, SAPIEN, PyBullet, Genesis, cuRobo, PyRep, Blender) 단일 인터페이스
- 시뮬레이터-agnostic configuration system
- HumanoidBench를 MuJoCo→RoboVerse 마이그레이션 검증 (Isaac Sim/MuJoCo 동시 학습)
- 우리 시스템 도입 시: GR1T2 자산 + KitchenSorting task 등록 후 학습은 PhysX(Isaac Lab)/MuJoCo Warp 양쪽 가능
- 참조: [RoboVerse](https://roboverseorg.github.io/), [arXiv 2504.18904](https://arxiv.org/abs/2504.18904)

## 6. 학습 프레임워크 (외부 teleop data 소비 가능 여부)

| 프레임워크 | 시뮬 종속성 | LeRobot 호환 | Robomimic HDF5 호환 | 추천 정책 |

## 7. Sim-to-Real / Sim-to-Sim 전이

### 7.1 Sim-to-Sim 표준 사례
- **Humanoid-Gym (2024)**: IsaacGym에서 train → MuJoCo에서 verify → 실기 zero-shot. dexterous 분야의 robust testing protocol.
- **MuJoCo Playground (2025)**: Leap Hand block re-orientation, contact-rich dexterous manipulation의 zero-shot sim2real 입증.
- **Newton (TUM 사례)**: 실기에서 검증된 dexterous policy를 **다시 sim에서** 재현 — "loop closure" 검증.

### 7.2 Sim-to-Real 격차 핵심 원인
1. Contact dynamics 차이 (PhysX TGS vs MuJoCo soft contact)
2. Joint friction / damping 모델링 차이
3. Sensor noise / latency 차이 (camera shutter, encoder quantization)
4. Domain randomization 부재 시 brittleness

### 7.3 권장 mitigations
- **Isaac Lab Mimic**: 1000-demo augmentation으로 데이터 다양성 ↑
- **Domain randomization**: `EventCfg`에 mass/friction/visual 랜덤화
- **DexMimicGen**: bimanual data automatic generation
- **TacMap**: 촉각 sim-to-real 갭 보정 (geometry-consistent penetration depth)

## 8. 권장 발전 방향 (단기 → 장기)

### 8.1 단기 (1~2 주, 코드 변경 ≤ 100 lines)
**목표: 손가락 정밀도를 잇따른 패치로 추가 개선**

1. **9.23 EMA fix 검증 후 alpha 튜닝**
   - 사용자 측 라이브 검증으로 0.4 / 0.2 / 0.6 비교
   - 영상 비교 후 가장 자연스러운 alpha를 default로 확정
2. **VMC packet측 EMA 추가** (selectable second-stage filter)
   - `VMCHandReceiver._on_bone()`에서 incoming quat에 EMA (140 Hz로 적용)
   - 두-단계 필터링은 cumulative lag을 늘리지만 더 부드러움
3. **env step rate 상향** (decimation 6 → 3)
   - 40 Hz step → sub-sampling 3.5:1로 개선
   - Pink IK QP 부담 ↑, GPU 사용량 ↑ 검증 필요
4. **adaptive alpha**
   - 손가락 정지 시 α=1.0 (lag 없음), 빠른 동작 감지 시 α=0.4 (smooth)

### 8.2 중기 (1~2 개월, 백엔드 변경)
**목표: Isaac Lab 안에서 더 빠르고 정확한 contact-rich physics**

1. **Newton / MuJoCo Warp 백엔드 마이그레이션** ★ 가장 권장
   - Isaac Lab 3.0 베타에서 MuJoCo Warp solver 사용
   - 검증: dexterous manipulation에서 PhysX 대비 65% 빠름, MJX 대비 313x 빠름
   - 변경 비용: env_cfg에 `sim.physx → sim.newton` 전환 + 일부 actuator/joint 설정 재검증
   - 참조: [Isaac Lab Newton Integration](https://isaac-sim.github.io/IsaacLab/main/source/experimental-features/newton-physics-integration/index.html)
2. **TeleOpBench 30-task subset 도입**
   - GR1T2 task 평가 표준 채택
   - 우리 KitchenSorting task와 함께 실행 → 정량 비교
3. **LeRobotDataset v3 export 추가**
   - 현재 ust_260502_win 의 HDF5 baselines 를 LeRobot v3 포맷으로 변환
   - HuggingFace Hub에 push (private repo 가능)

### 8.3 장기 (3~6 개월, 인프라 재구축)
**목표: 시뮬-분리형 + ROS2 추상 + multi-back-end**

1. **Open TeleDex 3-tier ROS2 architecture 차용**
   - `hand_retarget` ROS2 노드: UDCAP/MANUS/skeleton 어떤 입력이든 표준 intent signal로 변환
   - 시뮬 노드 (Isaac Lab / MuJoCo Playground / ManiSkill3) 와 robot 노드 (실기 GR1T2) 가 같은 토픽 구독
   - 우리 GR1T2FourierUDCAPDevice 와 GR1T2FourierSteamVRRetargeter 는 그대로 유지하되 **출력을 ROS2 토픽으로 발행**
2. **RoboVerse MetaSim 도입**
   - GR1T2 자산을 MetaSim configuration system에 등록
   - Isaac Lab(학습) + MuJoCo Warp(부분 데이터) + SAPIEN(고밀도 contact-rich validation) 동시 사용
3. **Cross-sim policy validation pipeline**
   - 학습은 Isaac Lab Newton에서, 검증은 MuJoCo Playground에서, 실기 배포 전 sim2sim gap 측정
4. **MANUS 글러브 도입 검토** (UDCAP 한계 시)
   - NVIDIA 공식 데이터 글러브, GTC 2026 announce
   - 22-DoF Sharpa hand 직접 제어 사례 — fidelity가 우리 UDCAP보다 1~2 order 높음
   - 비용 vs 효과 평가 필요 (UDCAP는 LucidVR DIY 계열, MANUS Quantum은 enterprise 가격)

## 9. "다른 시뮬에서 수집 → Isaac Lab 학습" 패턴의 합리성 평가

### 9.1 합리적인 경우 ✓
- **손가락 정밀제어가 실시간 텔레오퍼레이션의 critical metric** 인데 PhysX env throughput이 발목을 잡을 때
- 데이터 수집 속도가 문제일 때 (MuJoCo Warp는 313x faster)
- 다양한 robot/scene을 빠르게 prototyping해야 할 때 (MJX의 JAX speedup)
- Sim2Sim 검증을 정책 학습 일부로 통합하고 싶을 때 (RoboVerse, Humanoid-Gym 패턴)

### 9.2 비합리적인 경우 ✗
- 학습 시뮬과 수집 시뮬의 **물리 갭**이 robot policy 정확도에 직접 영향 (e.g. contact-rich dexterous task)
- 자산 (USD ↔ MJCF) 변환 부담이 학습 가속분보다 클 때
- 한 시뮬에서 이미 SOTA가 검증된 task (e.g. Isaac Lab Mimic의 NutPour)
- 팀이 single-sim 운영 인력 / 검증 capability만 가지고 있을 때

### 9.3 우리 케이스 평가
> **현재 상황 (9.23 EMA fix 직후)에서는 시뮬 분리는 비추천**. 이유:
> - 우리 EMA fix가 충분히 효과적일 가능성 (사용자 측 라이브 검증 대기 중)
> - GR1T2 USD 자산이 Isaac Lab에 최적화되어 있음 (Pink IK 36D, hand_joint_names 22)
> - Cross-sim 도입 시 USD↔MJCF 변환과 sim2sim gap 측정 비용이 작지 않음
> - **단, Newton/MuJoCo Warp 백엔드 활성화는 "사실상 cross-sim의 모든 이점을 Isaac Lab 안에서" 얻는 우회로** — 이게 가장 실용적

> **만약 9.23 후에도 손가락 매칭이 여전히 부족하다면**, **우선 Newton 백엔드 → 그래도 안 되면 ManiSkill3에서 데이터 수집 + Isaac Lab Mimic으로 학습** 순서로 escalate.

## 12. 결론 및 다음 단계

### 12.1 한 줄 요약
> **Isaac Lab은 dexterous teleop의 한계가 아니다 — 9.23 EMA fix가 첫 단추, Newton 백엔드 활성화가 두번째 단추, LeRobot/TeleOpBench가 장기 표준화. "다른 시뮬에서 수집 → Isaac Lab 학습" 패턴은 합리적이지만 우리 케이스에선 단일-sim Newton 마이그레이션이 ROI 가장 높다.**

### 12.2 즉시 실행 권장 작업 (사용자 검토 후 진행)
1. ✅ **9.23 EMA fix 라이브 검증 — 이미 적용됨, 사용자 측 평가 대기**
2. ⏳ alpha 튜닝 결과로 default 확정 (0.4 / 0.2 / 0.6 비교)
3. ⏳ Newton 백엔드 sanity check — Isaac Lab 3.0 dev branch에서 GR1T2 RobotOnly 환경 부팅 가능성 검증
4. ⏳ LeRobotDataset v3 변환 도구 — `ust_260502_win/baselines/baseline_2026-05-02_c8c10.vmc.jsonl` → Parquet 마이그레이션 PoC
5. ⏳ TeleOpBench 30-task 중 GR1T2 + KitchenSorting 인접 5개 task 채택

### 12.3 사용자 의사결정이 필요한 갈림길
- **A. 단일-sim 유지 + 점진적 개선 (8.1 + 8.2)**: 가장 안전, ROI 빠름, 코드 변경 최소
- **B. Newton 백엔드 마이그레이션 (8.2)**: 중간 위험, 시뮬 가속 큼, 베타 단계
- **C. 시뮬 분리 (8.3)**: 가장 큰 인프라 변경, 장기 ROI 큼, 단기 비용 큼
- **D. 글러브 교체 (8.3 부속)**: 하드웨어 비용 발생, 정량 정밀도 ↑

> 권장 순서: **A → 결과 미흡 시 B → 그래도 부족하면 C/D 병렬 검토**.
