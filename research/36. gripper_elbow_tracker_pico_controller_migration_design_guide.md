### 2.2 옵션 C 상세 — "Soft 그리퍼 모드" (즉시 가능)

#### 2.2.1 코드 변경 위치

`ust_ws/ust_fourier_260421/teleop/fourier_hand_mapper.py`

```python
def map_from_gripper_trigger(self, trigger_value: float, is_right: bool) -> np.ndarray:
    """그리퍼 트리거 값(0..1) → 11D Fourier 손 굽힘 벡터.
    
    PICO 컨트롤러 트리거 analog 값을 4 proximal joint 에 동시에 적용.
    Thumb 은 약간 적게 (oppositional motion 시 ring/pinky와 충돌 방지).
    
    Returns
    -------
    np.ndarray (shape=(11,)) — pack_22d() 가 요구하는 단방향 magnitude
    """
    t = float(np.clip(trigger_value, 0.0, 1.0))
    bend = t * 1.4  # 90% of joint limit (1.57 rad). 충돌/마찰 회피
    out = np.zeros(11, dtype=np.float32)
    # 11D layout (pack_22d 입력):
    # [0] index_proximal, [1] middle_proximal, [2] pinky_proximal,
    # [3] ring_proximal, [4] thumb_proximal_yaw,
    # [5] index_intermediate (mimic), [6] middle_int, [7] pinky_int,
    # [8] ring_int, [9] thumb_proximal_pitch,
    # [10] thumb_distal
    out[0] = bend           # index proximal
    out[1] = bend           # middle proximal
    out[2] = bend           # pinky proximal
    out[3] = bend           # ring proximal
    out[4] = t * 0.5        # thumb yaw (소폭 oppositional)
    out[5] = bend * 0.6     # intermediate mimic (joint mimic 비율 추정)
    out[6] = bend * 0.6
    out[7] = bend * 0.6
    out[8] = bend * 0.6
    out[9] = t * 1.0        # thumb proximal pitch (꼬집기 동작)
    out[10] = t * 0.8       # thumb distal
    return out
```

`ust_ws/ust_fourier_260421/teleop/gr1t2_retargeter.py` 의 `_resolve_hand_joints` 우선순위 chain 을 단순화:

```python
def _resolve_hand_joints(self, snapshot, udcap_bones, action_inputs):
    left_11 = np.zeros(HAND_DIM_PER_SIDE, dtype=np.float32)
    right_11 = np.zeros(HAND_DIM_PER_SIDE, dtype=np.float32)

    # GRIPPER MODE: 트리거 analog → 5-finger 동기 굽힘
    if action_inputs:
        left_act = action_inputs.get("left") or {}
        right_act = action_inputs.get("right") or {}
        left_trigger = float(left_act.get("trigger", 0.0))
        right_trigger = float(right_act.get("trigger", 0.0))
        left_11 = self.finger_mapper.map_from_gripper_trigger(
            left_trigger, is_right=False
        )
        right_11 = self.finger_mapper.map_from_gripper_trigger(
            right_trigger, is_right=True
        )
        self._finger_source_left = "gripper_trigger"
        self._finger_source_right = "gripper_trigger"
    return pack_22d(left_11, right_11)
```

### 4.4 그리퍼 매핑 — 옵션별 구현

#### 4.4.1 옵션 C 모드 (Soft 그리퍼, 22D 액션 유지)

§2.2.1 의 `map_from_gripper_trigger()` 사용. 트리거 [0,1] → 5-finger 동기 굽힘 [0, 1.4 rad]. **추가 코드 ~30줄**.

#### 4.4.2 옵션 B 모드 (정식 그리퍼, 16D 액션)

retargeter 의 22D 출력 자리 → **2D 그리퍼 binary** 로 교체:

```python
# gr1t2_retargeter.py
ACTION_DIM = 7 + 7 + 2   # 16

def retarget(self, snapshot, action_inputs=None):
    action = torch.zeros(self.ACTION_DIM, dtype=torch.float32)
    # ... wrist EEF (변경 없음)
    
    # 그리퍼 binary action
    if action_inputs:
        left_t = float(action_inputs.get("left",  {}).get("trigger", 0.0))
        right_t = float(action_inputs.get("right", {}).get("trigger", 0.0))
        # BinaryJointPositionAction 의 close = mask < 0
        # → 트리거 누름 (t > 0.5) = close = -1, 아니면 +1
        action[14] = -1.0 if left_t > self.cfg.gripper_threshold else 1.0
        action[15] = -1.0 if right_t > self.cfg.gripper_threshold else 1.0
    return action
```

`gripper_threshold` 는 cfg 의 기존 필드 (현재 0.5). hysteresis 추가 권장 (chattering 방지):

```python
@dataclass
class GR1T2GripperRetargeterCfg:
    ...
    gripper_close_threshold: float = 0.6   # 누를 때
    gripper_open_threshold: float  = 0.4   # 놓을 때
    
# retarget() 내부
self._left_gripper_state  = self._update_with_hysteresis(
    self._left_gripper_state, left_t,
    self.cfg.gripper_close_threshold, self.cfg.gripper_open_threshold,
)
```

### 4.5 트리거 analog 가 그리퍼 *open ratio* 도 표현하면? (Continuous mode)

옵션 B 의 binary 대신 continuous 매핑:
```python
# trigger 0.0 → 0.04 m (open), trigger 1.0 → 0.0 m (close)
gripper_pos = 0.04 * (1.0 - left_t)
```

→ `JointPositionActionCfg` (BinaryJointPositionActionCfg 가 아닌) 사용. action [14] = `gripper_pos`.

**추천**: 첫 단계에서는 **binary** (오프셋 / 마찰 / contact 안정성 좋음). Continuous 는 demo 데이터가 충분히 모였을 때 정밀도가 필요한 작업 (작은 물체) 에 적용.

### 4.6 GR1T2InterventionInterface 반응

현재 (gr1t2_udcap_device.py L1124):
```python

    """양 grip 누름 → 개입, 양 trigger → 재개, 양 menu → 리셋"""
```

⇒ 그리퍼 모드에서는 **trigger 가 그리퍼 close 시그널이므로 "양 trigger = resume" 매핑이 충돌**. 권장:

## 5. 변경 사항 4: PICO 컨트롤러 트리거의 화면 드래그 비활성화

### 5.1 "화면 드래그" 의 정체 — 3가지 가능 출처

|---|---|---|---|
| **1** | **SteamVR Dashboard pointer** | `vrcompositor` 가 frontmost 어플 인 dashboard 를 보고 있을 때 trigger pull → laser pointer 드래그 (오버레이 윈도우 이동) | 우리 액션 매니페스트 (`actions.json`) 에 `trigger_*` 가 binding 되어 있고 application 이 focus 잡으면 자동으로 우선순위가 우리 앱에 넘어옴 |

#### 5.2.5 단계 E — PICO Connect 설정 확인

PICO Connect 5.14+ UI:
- **Settings → General → Controller Type** = "Index Knuckles" (X) → "Default" 또는 "Original" 로 설정

#### 5.2.6 단계 F — UDCAP 드라이버 완전 비활성

마이그레이션 후 UDCAP 글러브 사용 안 함. 다음 중 하나:
- **권장**: Windows 미니 PC 의 `UdcapDriver.exe` 자동 시작 비활성 (서비스 설정)
- **임시**: `tasklist` 에서 종료 + SteamVR 재시작

UDCAP 드라이버가 살아있으면 가짜 knuckles 컨트롤러를 등록하여 Touch 입력을 마스킹할 수 있음 (CLAUDE.md gotcha #5 의 변형).

### 5.4 디버그 로그로 검증

```
  left:  trigger=0.000 grip=0.000 finger_curls=[...]
  right: trigger=0.000 grip=0.000 finger_curls=[...]

```

PICO Touch 트리거 1초 누른 상태로 launch 하면 첫 probe 에서 `trigger=1.000` 가 보여야 함. 0 이면 §5.2.3 단계 C 의 SteamVR Manage Controller Bindings 미설정.

`finger_curls` 는 옵션 B 마이그레이션 후 always 0 이어야 함 (UDCAP 글러브 제거됨, `finger_*_left/right` 액션 매니페스트에서 제거). 이것을 보면 UDCAP 가 죽었다는 신호.

## 7. 위험 요소 & 완화책

### 7.1 USD 변경 위험 (옵션 B)

| 위험 | 완화 |
|---|---|
| Fixed joint 의 localPos1 좌표 오차 → 그리퍼가 손목과 어긋나 보임 | Isaac Sim viewer 에서 1차 검증, `Sdf.CopySpec` reparenting 로 안전 |
| Visual mesh 가 `RigidBody` 의 자식이 아님 → 충돌 mesh 만 따라가고 visual 은 정지 | CLAUDE.md gotcha #5 적용 — visual prim 을 `RigidBody` prim 의 child 로 reparent |
| `apiSchemas` 가 `SdfTokenListOp()` 빈 리스트 → 상속된 PhysX schema block | `prim.ClearInfo("apiSchemas")` (CLAUDE.md gotcha #2) |
| 그리퍼 prismatic joint 의 sign convention 이 wrong → close 가 open 동작 | franka.py 와 동일 패턴: `localRot0=(0,1,0,0)` (180° X) 로 sign 통일, 양 finger 동일 부호 (gotcha #3) |

### 7.2 PICO 컨트롤러 trigger drag 잔존

| 증상 | 진단 | 해결 |
|---|---|---|
| 트리거 누르면 VR 환경 내 가상 PC 화면이 드래그됨 | Virtual Desktop 의 desktop overlay laser 가 활성 | VD UI → "Disable laser pointer in OpenVR games" |
| 트리거 누르면 SteamVR Home 가구가 잡힘 | SteamVR Home 가 frontmost (우리 앱이 fullscreen 안 잡음) | env_cfg 의 `xr_enabled=True` 확인 + render_mode = monitor 가 아닌 vr 로 launch |
| 트리거 입력이 우리 앱에 도달 안함 (probe 0.000) | binding 미적용 | Manage Controller Bindings 에서 `UST Teleop` → `UST Teleop — PICO controller binding` 활성화 (단계 C) |
| 트리거 누르면 PICO Connect 시스템 메뉴 토글 | PICO 시스템 단축키 활성 | PICO 4 Ultra 설정 → 일반 → Quick Settings 단축키 비활성 |

### 7.3 팔꿈치 트래커의 정확도 한계

PICO Motion Tracker 5cm 위치 편차 + 팔꿈치 단독 사용 시 손목 yaw/roll 추정 불가능. **컨트롤러 fallback 필수**.

만약 컨트롤러 잃었을 때 (battery 소진 / IR 가림) `_from_forearm()` 호출 → 28cm offset 로 손목 추정. 사용자 손목 비틀어 작업하면 misalignment 가시. **운영 중 컨트롤러 항상 양손에 들고 있도록 권장**.

### 7.4 Pink IK 안정성

GR1T2 팔만 (waist null-space 보존) + 16D 액션 → Pink IK QP 부담 거의 안 변함 (P99 ~5 ms 유지). 단:
- 22D finger 슬롯 0 으로 둔 상태에서는 hand_joint_names 가 비어있으면 `num_hand_joints=0` 으로 해야 함 (kitchen_sorting_gr1t2_env_cfg.py L427). 옵션 C 에서는 22D 그대로 유지하므로 변경 없음. 옵션 B 에서는 0 으로 변경 필수.
- `target_eef_link_names` 의 link 가 그리퍼 base 로 바뀜 (옵션 B). 충돌 mesh 가 비어있으면 `pickplace_gr1t2_env_cfg.py` 의 EEF observation 도 같이 변경 (이미 `GR1T2_EEF_LINK_NAMES` 변수 가 있음, L186-190).

### 7.5 데이터 호환성

기존 22D demo HDF5 (`./data/demos/...hdf5`) 와 16D 액션 비호환. 마이그레이션 후 새 데이터로 from-scratch 수집 필요. **이는 그리퍼 변경의 자연스러운 비용**.

## 9. 추가 권장 작업 (단계 1 마무리 후)

### 9.1 컨트롤러 햅틱 피드백 (research/34 §7.2 영감)

PICO Touch 의 vibration 채널을 Isaac Lab contact sensor 와 연결:
- `ContactSensor` on `*_gripper_finger_*` body
- contact force > threshold → `IVRSystem::triggerHapticPulse()` 호출
- 사용자에게 그립 성공 / 충돌 피드백
- **perceived latency ↓ + sample efficiency ↑** (현실 그리퍼 텔레오퍼레이션 reference: HRI 2023 "Haptic feedback in dexterous teleoperation")

### 9.2 그리퍼 closure 진행 시 visual cue

monitor mode 에서 그리퍼 닫힘 비율을 `VisualizationMarkers` 로 작은 bar 로 띄움 — 사용자가 fingertip 이 어디까지 닿았는지 가시화. `ust_260502_win` 의 marker 인프라 재사용.

### 9.3 demo 데이터 augmentation

옵션 B 16D action 으로 demo 수집 후 **MimicGen** (ust_260220 phase1) 적용:
- 그리퍼 binary 액션은 augmentation friendly (각도 jitter 영향 거의 없음)
- 같은 작업당 demo 5-10 개 → 50-100 augmented trajectories

### 9.4 SteamVR overlay 로 사용자 피드백 (선택)

`pyopenvr.IVROverlay` 로 그리퍼 상태 / EEF 위치 / Pink IK 수렴 여부를 사용자 시야 코너에 mini-overlay 로 띄움. UDCAP 시절의 `UDCAP_overlay.exe` 와 유사한 역할.
