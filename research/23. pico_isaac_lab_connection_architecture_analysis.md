# PICO ↔ Isaac Lab 연결 아키텍처 상세 분석

> **날짜**: 2026-04-05
> **관련 문서**: `17~22번` 리서치, GR00T-WBC 공식 문서, Isaac Lab Teleoperation 문서
> **핵심 질문**: CloudXR로 연결하는 것인가? XRoboToolkit으로 연결하는 것인가?

---

## 1. 결론 먼저

### CloudXR와 XRoboToolkit은 **동시에 사용**하며 역할이 완전히 다름

```
                    PICO 4 Ultra 헤드셋
                    ┌─────────────────────────────┐
                    │                             │
                    │  [CloudXR.js 브라우저]       │  ← VR 화면 표시 (렌더링 수신)
                    │  [XRoboToolkit App]          │  ← 트래킹 데이터 전송
                    │                             │
                    └──────┬──────────┬───────────┘
                           │          │
              렌더링 수신 ◀─┘          └─▶ 트래킹 전송
              (CloudXR)                 (XRoboToolkit)
                           │          │
                    ┌──────▼──────────▼───────────┐
                    │      Ubuntu 호스트            │
                    │                             │
                    │  CloudXR Runtime → 렌더링    │
                    │  XRoboToolkit → 트래킹 데이터 │
                    │  통합 브릿지 → Isaac Lab      │
                    │                             │
                    └─────────────────────────────┘
```

| 구성요소 | 역할 | 방향 | 없으면? |
|---------|------|------|--------|
| **CloudXR** | VR **렌더링** (Isaac Sim 화면 → 헤드셋 디스플레이) | Isaac Lab → PICO | 시뮬레이션 화면 안 보임 |
| **XRoboToolkit** | **트래킹 데이터** (머리/손/몸/MT → Isaac Lab) | PICO → Isaac Lab | 로봇 제어 불가 |

**둘 다 필요합니다.** 각각 독립적으로 동작하며 서로 간섭하지 않음.

## 2. 전체 데이터 흐름 상세도

### 2.1 렌더링 경로 (CloudXR): Isaac Lab → PICO 눈

```
Isaac Lab env.step()
    │ 물리 시뮬레이션 + 장면 렌더링
    ▼
Isaac Sim RTX 렌더러
    │ 스테레오 프레임 (좌/우 눈)
    ▼
CloudXR Runtime 6.0.1 (Docker)
    │ GPU H.264 인코딩 (49100 포트)
    ▼
HAProxy SSL 프록시 (WSS:48322)
    │
    ▼
CloudXR.js 웹서버 (HTTPS:8080)
    │ WebRTC 스트리밍
    ▼
PICO 4 Ultra 브라우저 (WebXR)
    │ 디코딩 + 렌더링
    ▼
PICO 디스플레이 (양쪽 눈)
    → 사용자가 시뮬레이션 장면을 VR로 봄
```

**프로토콜**: WebRTC (영상 스트리밍), WebSocket (시그널링)
**지연**: ~20-30ms (motion-to-photon)
**해상도**: 2048×1792 @90Hz (PICO 4 Ultra 최적)

### 2.2 트래킹 경로 (XRoboToolkit): PICO 센서 → Isaac Lab

```
PICO 4 Ultra 센서
    │ Head IMU, 카메라, IR 수신기
    ▼
XRoboToolkit App (PICO 내 APK)
    │ 트래킹 데이터 수집:
    │ ├── Head 6DoF (pose 7D)
    │ ├── Controller L/R (pose 7D + buttons)
    │ ├── Hand Tracking 26j × 2 (카메라 기반)
    │ ├── Body 24pt (Motion Tracker 기반)
    │ └── Motion Tracker ×3~5 (pose 7D each)
    │
    │ WiFi/TCP JSON (90Hz)
    ▼
XRoboToolkit PC Service (Ubuntu 호스트, 네이티브)
    │ C++ gRPC 서버 → JSON 콜백
    ▼
ConsoleDemo 또는 PyBind (TCP :7777)
    │
    ▼
통합 브릿지 (unified_bridge.py)
    │ + UDCAP VMC 핑거 데이터 (UDP :39539)
    │ = 통합 JSON
    │
    │ TCP :8888
    ▼
PICOFullBodyTeleopDevice (Docker, Isaac Lab)
    │ XRTDataParser → XRTFrame
    │ UDCAPFingerMapper → 12D × 2
    │ G1PICORetargeter → 38D 액션 텐서
    ▼
action = device.advance()  # (38,) torch.Tensor
    │
    ▼
env.step(action)  # Isaac Lab 환경에 액션 적용
    → 물리 시뮬레이션 실행
    → 새 관찰(obs) 반환
    → CloudXR로 렌더링 → PICO 화면 (루프 완성)
```

### 2.3 핑거 경로 (UDCAP): 글러브 → Isaac Lab

```
UDCAP VR Gloves (양손)
    │ 12 탄성 센서 × 2 (21 관절 각도/손)
    │ USB 2.4GHz 동글
    ▼
Windows 미니PC
    │ UDCAP Software → SteamVR 드라이버
    │ VMC/OSC 프로토콜 변환
    │
    │ UDP :39539 (VMC)
    ▼
통합 브릿지 (unified_bridge.py, Ubuntu 호스트)
    │ (XRoboToolkit 데이터와 병합)
    ▼
Isaac Lab (위 경로와 합류)
```

## 3. 세 경로의 독립성

```
       ┌─── Path A: CloudXR (렌더링) ───┐
       │    HTTPS/WSS/WebRTC            │
       │    포트: 8080, 48322, 49100    │
       │    방향: Isaac Lab → PICO       │
       │    없어도: 트래킹은 동작함       │
PICO ──┤                                ├── Isaac Lab
       │                                │
       ├─── Path B: XRoboToolkit ───────┤
       │    WiFi/TCP JSON               │
       │    포트: 7777 → 8888           │
       │    방향: PICO → Isaac Lab       │
       │    없어도: 렌더링은 동작함       │
       │                                │
       └─── Path C: UDCAP ─────────────┘
            UDP VMC/OSC
            포트: 39539
            방향: 글러브 → Isaac Lab
            없어도: A+B는 동작함
```

| 조합 | 결과 |
|------|------|
| A + B + C | **완전체**: VR 화면 + 풀바디 트래킹 + 핑거 |
| A + B | VR 화면 + 풀바디 트래킹 (핑거 없음, XRT hand tracking 폴백) |
| B + C | 트래킹 전체 동작, **VR 화면 없음** (모니터로만 확인) |
| B only | 트래킹만 (핑거/VR화면 없음) |
| A only | VR 화면만 (로봇 제어 불가) |

## 4. 기존 Quest 3S 시스템과의 차이

### 4.1 Quest 3S (기존)

```
Quest 3S
    │
    ├── CloudXR.js (WebXR) ──▶ CloudXR Runtime ──▶ Isaac Sim 렌더링
    │                                               ▲
    └── CloudXR OpenXR ──▶ OpenXR IPC ──▶ Isaac Lab OpenXRDevice
         (트래킹 + 렌더링이 하나의 CloudXR 경로로 통합)
```

Quest 3S에서는 **CloudXR가 렌더링과 트래킹 모두** 담당:
- 렌더링: CloudXR Runtime → 스트리밍 → Quest 브라우저
- 트래킹: Quest → CloudXR → OpenXR IPC → `omni.kit.xr.core.XRCore` → `OpenXRDevice`

### 4.2 PICO 4 Ultra (신규)

```
PICO 4 Ultra
    │
    ├── CloudXR.js (WebXR) ──▶ CloudXR Runtime ──▶ Isaac Sim 렌더링 (동일)
    │
    └── XRoboToolkit App ──▶ XRT PC Service ──▶ 통합 브릿지 ──▶ PICOFullBodyTeleopDevice
         (트래킹은 XRoboToolkit 별도 경로)
```

PICO에서는 **역할 분리**:
- **렌더링**: CloudXR (기존과 동일)
- **트래킹**: XRoboToolkit (새로운 경로, 더 많은 데이터)

### 4.3 왜 분리되었는가?

| 이유 | 설명 |
|------|------|
| **CloudXR OpenXR는 핸드/헤드만** | 52개 핸드 관절 + 헤드 6DoF만 전송. 풀바디/MT 없음 |
| **XRoboToolkit은 풀바디 지원** | 24포인트 바디 + MT ×5 + 핸드 + 컨트롤러 모두 포함 |
| **CloudXR는 Kit XR 플러그인 의존** | `omni.kit.xr.core` Kit 확장 필요 (복잡) |
| **XRoboToolkit은 독립 프로세스** | 표준 TCP JSON으로 어떤 프레임워크에도 연결 가능 |
| **UDCAP 통합** | CloudXR에는 핑거 글러브 지원 없음. XRT 경로에서 VMC와 병합 용이 |

## 5. 포트 및 네트워크 전체 맵

```
                    PICO 4 Ultra (192.168.x.y)
                    ├── 브라우저: HTTPS → 호스트:8080 (CloudXR.js)
                    └── XRoboToolkit App: TCP → 호스트 (자동 검색)

                    Windows 미니PC (192.168.x.z)
                    └── UDCAP VMC: UDP → 호스트:39539

┌────────────────── Ubuntu 호스트 (192.168.x.x) ──────────────────┐
│                                                                  │
│  [CloudXR.js 웹서버]        HTTPS :8080 ← PICO 브라우저         │
│  [HAProxy WSS 프록시]       WSS :48322 → WS :49100              │
│                                                                  │
│  [XRoboToolkit PC Service]  gRPC (PICO WiFi 수신)               │
│  [ConsoleDemo]              TCP :7777 (JSON 출력)               │
│  [VMC Receiver]             UDP :39539 (UDCAP 수신)             │
│  [unified_bridge.py]        TCP :8888 (통합 출력 → Docker)      │
│                                                                  │
│  ┌──────────── Docker (network_mode: host) ─────────────┐       │
│  │                                                       │       │
│  │  [CloudXR Runtime 6.0.1]  WS :49100                  │       │
│  │  ├── Isaac Sim 렌더링 → H.264 인코딩                   │       │
│  │  └── OpenXR IPC: /openxr/run/ipc_cloudxr              │       │
│  │                                                       │       │
│  │  [Isaac Lab]                                          │       │
│  │  ├── PICOFullBodyTeleopDevice (TCP :8888 수신)        │       │
│  │  ├── env.step(action) → 물리 시뮬레이션                │       │
│  │  └── 렌더링 → CloudXR Runtime → PICO 디스플레이        │       │
│  │                                                       │       │
│  └───────────────────────────────────────────────────────┘       │
└──────────────────────────────────────────────────────────────────┘
```

### 포트 요약

| 포트 | 프로토콜 | 방향 | 용도 |
|------|---------|------|------|
| **8080** | HTTPS | PICO → 호스트 | CloudXR.js 웹서버 (VR 렌더링 진입점) |
| **48322** | WSS | 프록시 | HAProxy SSL 터미네이션 |
| **49100** | WS | 내부 | CloudXR Runtime 시그널링 |
| **47998-48012** | UDP | 양방향 | CloudXR 미디어 스트리밍 (영상/오디오) |
| **7777** | TCP | XRT → 브릿지 | XRoboToolkit JSON 데이터 |
| **39539** | UDP | 미니PC → 호스트 | UDCAP VMC 핑거 데이터 |
| **8888** | TCP | 브릿지 → Docker | 통합 데이터 → Isaac Lab |

## 6. 대안 아키텍처: CloudXR 없이 가능한가?

### 6.1 CloudXR 없이 (트래킹만, 렌더링 없음)

```
PICO 4 Ultra
└── XRoboToolkit App → WiFi → PC Service → 통합 브릿지 → Isaac Lab

결과:
  ✓ 로봇 제어 가능
  ✗ VR 화면 없음 (PICO 디스플레이에 시뮬레이션 안 보임)
  → 별도 모니터로 확인하거나 PICO 패스스루 카메라로 실제 환경만 봄
```

**사용 가능한 경우**:
- 실제 로봇 텔레오퍼레이션 (시뮬레이션 렌더링 불필요)
- 시연 데이터 수집 시 모니터로 시뮬레이션 확인 가능
- NVIDIA GR00T WholeBodyControl이 이 방식 사용

### 6.2 XRoboToolkit 없이 (CloudXR만, Quest 호환 방식)

```
PICO 4 Ultra
└── CloudXR.js 브라우저 → CloudXR Runtime → OpenXR IPC → OpenXRDevice

결과:
  ✓ VR 화면 있음
  ✓ 핸드 트래킹 (52관절) + 헤드 6DoF
  ✗ 풀바디 트래킹 없음
  ✗ Motion Tracker 데이터 없음
  ✗ UDCAP 통합 경로 없음 (별도 구현 필요)
```

**사용 가능한 경우**:
- 팔+손만 사용하는 단순 텔레오퍼레이션
- Quest 3S와 동일 수준의 기능만 필요할 때

### 6.3 둘 다 사용 (현재 설계, 추천) ★

```
PICO 4 Ultra
├── CloudXR.js 브라우저 → 렌더링 (VR 화면)
└── XRoboToolkit App → 트래킹 (풀바디 + MT + 핑거)

결과:
  ✓ VR 화면 있음
  ✓ 풀바디 트래킹 (24pt)
  ✓ Motion Tracker ×5 (손, 허리, 발목)
  ✓ UDCAP 핑거 (21관절 × 2)
  ✓ 컨트롤러 버튼 (개입/그리퍼)
```

## 7. GR00T WholeBodyControl 참조: NVIDIA 공식 방식

NVIDIA GR00T-WBC는 PICO 4 Ultra를 공식 지원하며, **XRoboToolkit만 사용** (CloudXR 없음):

### 7.1 GR00T-WBC PICO 데이터 흐름

```
PICO 4 Ultra
└── XRoboToolkit App (v1.1.1 APK)
    └── WiFi → XRoboToolkit PC Service
        └── Python ZMQ Publisher (port 5556, topic "pose")
            └── C++ 로봇 제어 프로세스 (ZMQ Subscriber)
```

### 7.2 GR00T-WBC 데이터 프로토콜

```python
# GR00T-WBC ZMQ 메시지 (v3 프로토콜)
{
    "smpl_joints": (24, 3),      # SMPL 바디 관절 위치
    "smpl_pose": (21, 3),        # SMPL 관절 각도
    "body_quaternion": (4,),     # 몸통 쿼터니언
    "timestamp": float,
}
```

### 7.3 시사점

- NVIDIA 공식 로봇 텔레오퍼레이션에서 **CloudXR 없이 XRoboToolkit만으로 동작**
- 하지만 **실제 로봇** 대상 (시뮬레이션 VR 화면 불필요)
- **시뮬레이션 VR 렌더링이 필요하면 CloudXR가 추가로 필요**

## 8. 실행 시퀀스 다이어그램 (시간순)

```
시간 →

[호스트] CloudXR Runtime Docker 시작
[호스트] XRoboToolkit PC Service 시작
[호스트] ConsoleDemo (TCP :7777) 시작
[호스트] 통합 브릿지 (TCP :8888) 시작
         │
         │ 서비스 준비 완료
         ▼
[PICO] XRoboToolkit App 실행 → 호스트 IP 연결
         │ WiFi/TCP 연결 (트래킹 시작)
         ▼
[PICO] 브라우저 → https://호스트IP:8080 접속
         │ WebRTC 연결 (렌더링 스트리밍 시작)
         ▼
[미니PC] UDCAP Software → VMC 전송 시작
         │ UDP :39539 연결
         ▼
[Docker] Isaac Lab 실행:
         ./isaaclab.sh -p run_teleop.py --teleop_device pico --use_usd_scene
         │
         │ PICOFullBodyTeleopDevice.start()
         │ → TCP :8888 연결 (통합 브릿지)
         ▼
[루프 시작]
         │
    ┌────┴────────────────────────────────────────────────┐
    │                                                      │
    │  PICO → XRT App → PC Service → 통합 브릿지           │
    │  → TCP :8888 → PICOFullBodyTeleopDevice              │
    │  → G1PICORetargeter → 38D action                    │
    │  → env.step(action) → 물리 시뮬레이션                 │
    │  → Isaac Sim 렌더링 → CloudXR 인코딩                  │
    │  → PICO 브라우저 → 사용자 눈                          │
    │  → 사용자가 보고 손/몸 움직임 → PICO 센서              │
    │  → XRT App → (루프 반복)                              │
    │                                                      │
    └──────────────────────────────────────────────────────┘
    ~90Hz (트래킹) / ~60Hz (렌더링)
```

## 9. 요약 비교표

| 질문 | 답변 |
|------|------|
| **CloudXR로 연결?** | CloudXR는 **렌더링 전용** (Isaac Sim → PICO 디스플레이) |
| **XRoboToolkit으로 연결?** | XRoboToolkit은 **트래킹 전용** (PICO 센서 → Isaac Lab) |
| **둘 중 하나만?** | **둘 다 동시 사용** (서로 독립, 다른 역할) |
| **CloudXR 없이 가능?** | 가능 (트래킹만, VR 화면 없음 → 모니터로 확인) |
| **XRoboToolkit 없이 가능?** | 가능 (CloudXR OpenXR로 핸드/헤드만, 풀바디 없음) |
| **Quest 3S와 다른 점?** | Quest는 CloudXR가 렌더링+트래킹 모두 담당. PICO는 역할 분리 |
| **PICO 공식 Isaac Lab 지원?** | 직접 지원 없음. 커스텀 DeviceBase 구현 (이미 완료) |
| **GR00T에서는?** | XRoboToolkit만 사용 (CloudXR 없음, 실제 로봇 대상) |
