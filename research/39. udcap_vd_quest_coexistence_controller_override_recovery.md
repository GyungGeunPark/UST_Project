# 39. UDCAP + Virtual Desktop (Quest emulation) 공존 + 컨트롤러 인식 정정 가이드

> 작성: 2026-05-06
> 사용자 새 보고: research/38 의 Plan A (oculus driver 비활성화) 시도 → "Quest 까지 비활성화하면 헤드셋 자체가 인식 안 된다" + Manage Add-Ons 스크린샷 (Virtual Desktop Streamer (Quest) = Off / prism = Off / udcap = On / Gamepad Support = Off) 제공
> 정정 사항: research/38 의 "SteamVR 내장 driver_oculus 비활성화" 권장은 부분적으로 잘못됐음. 사용자의 "오큘러스 vr" 는 **SteamVR 내장 driver_oculus 가 아니라 Manage Add-Ons 의 "Virtual Desktop Streamer (Quest)" 항목** — 이건 Virtual Desktop 이 PICO 4 Ultra 를 Meta Quest 3 으로 emulate 하는 driver 이고, 끄면 헤드셋 자체가 SteamVR 에 안 보인다.

---

## 0. 한 줄 요약 (TL;DR)

> **결론**: 사용자가 끈 "오큘러스 vr" 는 정확히 **`Virtual Desktop Streamer (Quest)`** add-on 이다. 이건 PICO 4 Ultra 가 SteamVR 에 인식되는 **유일한 통로** (PC 측 Virtual Desktop Streamer 가 PICO 를 Meta Quest 3 + Oculus Touch 로 emulate). 끄면 헤드셋도 컨트롤러도 사라진다. 또 다른 통로는 **`prism`** (= PICO Connect 의 SteamVR-side driver) 인데 사용자는 이것도 Off — 즉 두 통로 다 막은 상태로는 SteamVR 가 PICO 를 못 본다.
>
> **올바른 Plan**: VD 또는 prism 중 **하나는 반드시 ON 유지** + udcap ON + UDCAP 의 SteamVR-side enable 플래그들 활성화. UDCAP 는 oculus_touch 를 "교체" 하는 게 아니라 **자기 자신의 udcap-type controller 를 새로 만들고 underlying controller (oculus_touch) 의 pose 를 빌려온다**. 그러려면 (1) `driver_udcap.enable: true` (Steam steamvr.vrsettings 와 UDCAP default.vrsettings 둘 다), (2) **`pose_settings.controller_override: true`** (이게 빠진 게 핵심), (3) UDCAP UI 의 Controller Priority HIGH 가 모두 충족돼야 한다.
>
> **권장 Add-Ons 토글** (사용자 환경 기준):
> | Add-On | 추천 | 비고 |
> |---|---|---|
> | **Virtual Desktop Streamer (Quest)** | **ON** ⭐ | 끄면 헤드셋 사라짐. UDCAP 는 이 driver 의 oculus_touch 컨트롤러 pose 를 빌려옴 |
> | **prism** | **OFF** | PICO Connect 안 쓸 때.  사용자는 VD 사용 중 → OFF 권장 (prism + VD 동시 활성 시 두 driver 가 PICO HMD 두 번 등록 → 충돌) |
> | **udcap** | **ON** ⭐ | UDCAP 글러브 사용 |
> | **Gamepad Support** | OFF | Xbox 게임패드 등 — 무관, OFF 유지 |
>
> **즉시 적용 가능한 5-단계 복구**:
> 1. SteamVR + VD Streamer + UdcapDriver 모두 종료
> 2. Manage Add-Ons : VD Streamer (Quest) = **ON** / prism = OFF / udcap = ON 으로 복귀
> 3. **`steamvr.vrsettings.driver_udcap.enable: true`** + **`default.vrsettings.driver_UDCAP.enable: true`** + **`default.vrsettings.pose_settings.controller_override: true`** (가장 중요한 변경)
> 4. UDCAP UI → Settings → Controller Priority **HIGH** 재확인 + UDCAP UI 한 번 OFF → ON 토글로 driver 재로드 강제
> 5. SteamVR + VD Streamer 재시작 → SteamVR Settings → Devices 에서 컨트롤러 type 이 "udcap" 또는 "knuckles" 로 표시되는지 확인
>
> 이 절차로 안 되면 **prism (PICO Connect) path 전환** 을 §6 의 Plan B 로 대체. 이 경우 우리 앱 actions.json 에 `pico_controller` binding 을 추가하거나 RVRPlugin.ini 의 `controllertype=1` (oculus_touch emulation) 으로 강제하면 현재 binding 그대로 사용 가능.

## 1. 사용자 스크린샷의 정확한 해석

### 1.1 Manage Add-Ons 의 4개 항목

사용자가 첨부한 SteamVR Manage Add-Ons 화면:

| Add-On | 사용자 설정 | 정확한 정체 | 역할 |
|---|---|---|---|
| **Virtual Desktop Streamer (Quest)** | Off | `Virtual Desktop Streamer\OpenVRDriver` (external_drivers 등록) | PC ↔ PICO 4 Ultra 무선 스트리밍 + PICO 를 Meta Quest 3 + Oculus Touch 로 SteamVR 에 emulate |
| **prism** | Off | `<SteamVR>\drivers\prism` (SteamVR 번들이 아닌 PICO Connect 가 설치하는 SteamVR driver) | PICO Connect path — PICO 4 Ultra 를 PICO native (controller_type: pico_controller) 로 SteamVR 에 emulate |
| **udcap** | **On** | `C:\Program Files\UdcapDriver\udcap` (external_drivers 등록) | UDCAP 글러브 driver |
| **Gamepad Support** | Off | `<SteamVR>\drivers\gamepad` | Xbox/Playstation 게임패드 → SteamVR controller emulation. 무관 |

### 1.2 사용자가 말한 "오큘러스 VR" = "Virtual Desktop Streamer (Quest)" 확정

확실한 증거 (research/38 §1 의 LastKnown 분석):
```json
"LastKnown": {
    "ActualHMDDriver": "oculus_virtualdesktop",   ← VD 가 만드는 driver instance
    "HMDManufacturer": "Oculus",                  ← Oculus 로 위장
    "HMDModel":        "Meta Quest 3"             ← Quest 3 로 위장
}
```

→ Virtual Desktop Streamer 의 ".Streamer (Quest)" 이름 자체가 **Quest 모드 emulation 을 위한 add-on** 임을 명시한 거고, Manage Add-Ons UI 에서 "Quest" 라는 단어가 사용자에게 "오큘러스" 로 인지된 것.

→ research/38 의 "SteamVR 내장 `driver_oculus` 비활성화" 권장은 **사용자의 케이스엔 무관**. 내장 driver_oculus 는 **실제 Oculus Quest 를 USB Link 로 연결할 때만** 활성화되는 것이고, VD 사용 시엔 SteamVR 가 그것 대신 `driver_VirtualDesktop` 의 oculus emulator 인스턴스를 사용한다.

### 1.3 prism 이 SteamVR drivers 폴더에 있는 이유

`C:\Program Files (x86)\Steam\steamapps\common\SteamVR\drivers\` 의 폴더 목록:
```
gamepad/  htc/  indexcontroller/  indexhmd/  lighthouse/  null/
oculus/   oculus_legacy/  prism/   tundra_labs/  vrlink/
```

→ **prism** 이 SteamVR 의 drivers 폴더에 들어있음. 이건 SteamVR 에 번들된 게 아니라 **PICO Connect 설치 시 그 위치로 자동 복사**됨 (또는 사용자가 과거 설치 흔적). 즉 SteamVR 가 prism 을 인식할 수 있는 환경. Manage Add-Ons 에서 Off 만 하면 비활성.

### 1.4 사용자 시도의 결과 — 4개 모두 Off 시 헤드셋 미인식

스크린샷의 상태 (VD=Off, prism=Off, udcap=On, gamepad=Off):
- VD off → PICO 4 Ultra 가 SteamVR 에 안 보임 (PC 가 PICO 와 통신할 path 없음)
- prism off → PICO Connect 도 안 씀
- 결과: SteamVR 가 HMD 를 못 찾음 → Test Controller 화면 자체 진입 불가 → 사용자 보고와 일치

## 2. UDCAP 의 driver architecture — passthrough vs swap

### 2.1 UDCAP 는 underlying controller 를 "교체" 하지 않는다

`C:\Program Files\UdcapDriver\udcap\driver.vrdrivermanifest`:
```json
{
    "alwaysActivate": true,
    "name": "udcap",
    "directory": "",
    "resourceOnly": false,
    "prefersUpperDeviceIndices": false,
    "hmd_presence": []
}
```

| 키 | 값 | 의미 |
|---|---|---|
| `alwaysActivate` | true | **HMD 유무 관계없이 항상 활성화** (SteamVR 가 시작되면 무조건 로드) |
| `prefersUpperDeviceIndices` | false | UDCAP 가 만드는 device 들에 낮은 device index 우선 할당 |
| `hmd_presence` | `[]` (empty) | 특정 HMD 에 종속되지 않음 — 어떤 HMD 든 사용 가능 |

→ UDCAP 는 SteamVR Driver API 의 **`IServerTrackedDeviceProvider`** 를 구현해 **자기 자신의 udcap-type virtual controllers 를 새로 만들어 SteamVR 에 등록**하는 driver. underlying oculus_touch controllers 를 "swap" 하거나 "intercept" 해서 그것의 controller_type 을 udcap 으로 바꾸는 게 아님.

### 2.2 그럼 UDCAP 는 pose 를 어디서 받나? — `pose_settings.controller_override`

`C:\Program Files\UdcapDriver\udcap\resources\settings\default.vrsettings`:
```json
"pose_settings": {
    "hardware_calibration_button_enabled": false,
    "right_x_offset_position": -0.1,
    "right_y_offset_position": -0.08,
    "right_z_offset_position": -0.03,
    "left_x_offset_position":   0.1,
    "left_y_offset_position":  -0.08,
    "left_z_offset_position":  -0.03,
    "pose_time_offset": -0.01,
    "controller_override":         false,        ← 핵심 토글
    "controller_override_left":    3,
    "controller_override_right":   4
}
```

| `controller_override` 값 | UDCAP 의 동작 |
|---|---|
| **false (현재)** | UDCAP 는 자기 pose 를 만들어 emit. 단, pose 소스가 없으면 (예: 위 트래커 pose 가 없으면) **fake static pose** (= gotcha #24 의 그 합성 stub 위치) 로 보고 → 글러브 위치 frozen |
| **true** | UDCAP 가 underlying controller (= VD 의 oculus_touch) 의 pose 를 **borrow** 해서 자기 udcap-type controller 의 pose 로 set. 이렇게 만들어진 udcap controller 는 PICO Touch 의 실제 위치 + UDCAP 글러브의 finger 데이터를 함께 가짐 |

`controller_override_left/right: 3, 4` 의 정확한 enum 값은 UDCAP-Driver 소스가 비공개라 미공개. **3 ≈ "first detected oculus_touch left"**, **4 ≈ "first detected oculus_touch right"** 추정 (또는 device index 직접 매핑).

→ **사용자 시스템은 `controller_override: false`** 라서 UDCAP 가 PICO Touch 의 pose 를 못 받고, 자체 fake pose 를 만들거나 무 pose 상태 → SteamVR 에 udcap controller 자체가 표시 안 되거나 0 좌표에 stuck.

### 2.3 SteamVR 측 `driver_udcap.enable` 의 의미

`steamvr.vrsettings` 의 `driver_udcap.enable: false` 는 **SteamVR 가 UDCAP driver 를 로드하지 않는다** 는 의미가 아님 — Manage Add-Ons 의 udcap=On 이 그 역할.

대신 **driver 가 로드는 되지만 자체적으로 비활성 상태로 머문다** 는 internal feature flag. UDCAP driver 가 startup 시 이 flag 를 읽고 "false 면 device 등록 skip" 하는 자기-차단 로직.

| Manage Add-Ons (udcap) | `driver_udcap.enable` | 결과 |
|---|---|---|
| Off | (무관) | UDCAP driver 로드 안 됨, 글러브 사용 불가 |
| On | **false (현재)** | UDCAP driver 로드되지만 device 등록 skip → SteamVR 에 udcap controller 없음 |
| On | true | UDCAP driver 정상 동작 → udcap controllers 등록 |

### 2.4 정상 흐름 (수정 후)

```
PICO 4 Ultra (HMD + Touch 컨트롤러)
       │
       ▼ (Wi-Fi 6/6E)
Virtual Desktop Streamer (PC 측, Add-Ons "Virtual Desktop Streamer (Quest)" = ON)
       │
       ├─ HMD: Meta Quest 3 emulation (oculus_virtualdesktop)
       │
       └─ Controllers: oculus_touch type emulation
              │
              │  ── 이 oculus_touch 의 pose 를 SteamVR 가 보유
              ▼
       UDCAP driver (Add-Ons udcap = ON, driver_udcap.enable = TRUE,
                     pose_settings.controller_override = TRUE)
              │
              │  ── SteamVR 가 두 set 의 controllers 를 동시 등록:
              │     1) oculus_touch (VD 의 원본)
              │     2) udcap (UDCAP 의 새 controller, oculus_touch pose 빌림 + UDCAP 글러브 finger 데이터)
              │
              ▼
       SteamVR 에 두 set 등록된 controllers
              │
              ├─ Test Controller 화면: 어느 set 가 표시되는지는 LastKnown 매핑에 따라 다름 (보통 udcap 이 후위 등록)
              └─ 우리 앱: actions.json 의 controller_type=udcap 매칭으로 바인딩 적용
```

→ **두 set 가 동시에 등록되는 게 정상**. SteamVR 의 device list 에 4개 controllers (left oculus_touch, right oculus_touch, left udcap, right udcap) 가 보일 수 있음.

## 4. 실제 driver 활성화 4-단계 모델

SteamVR 의 driver 활성화는 사실상 4-단계 모두 통과해야 함:

```
Step 1: openvrpaths.vrpath 의 external_drivers 에 등록 (SteamVR 가 driver 를 찾는 단계)
        + SteamVR drivers 폴더에 직접 있는 경우도 자동 인식
        ↓
Step 2: Manage Add-Ons UI 에서 토글 ON
        ↓
Step 3: steamvr.vrsettings 의 driver_<name>.enable = true (driver 측 feature flag)
        ↓
Step 4: 각 driver 의 default.vrsettings 의 추가 옵션 (controller_override 등) 활성화
        ↓
드디어 driver 가 fully functional
```

UDCAP 의 경우:
- Step 1 ✓ (external_drivers 에 등록)
- Step 2 ✓ (Manage Add-Ons → udcap = On)
- **Step 3 ❌** (driver_udcap.enable = false)
- **Step 4 ❌** (pose_settings.controller_override = false)

→ Step 3 + 4 가 현재 누락 → UDCAP 가 unfunctional 상태로 단순 idle.

이전에 만든 [`research/27. SteamVR 기반 휴머노이드 텔레오퍼레이션 구현 가이드.md`](27.%20SteamVR%20기반%20휴머노이드%20텔레오퍼레이션%20구현%20가이드.md) / [`research/28. SteamVR 휴머노이드 텔레오퍼레이션 구현 가이드.md`](28.%20SteamVR%20휴머노이드%20텔레오퍼레이션%20구현%20가이드%20%28Windows%20단일%20PC%20%2B%20Virtual%20Desktop%20%2B%20UDCAP%20VR%20Glove%29.md) 같은 파일에선 Step 1+2 까지만 다뤘고 Step 3+4 는 빠져있었음 — 이게 사용자 long-term 디버깅 painful 했던 root cause.

## 5. Plan A (정정판) — VD ON 유지 + UDCAP 4-단계 활성화 (5–10분)

### Step 0. Manage Add-Ons 복구 (사용자 즉시 행동)

스크린샷의 4개 토글을 다음과 같이 변경:
- **Virtual Desktop Streamer (Quest) = ON** ⭐ (현재 Off → On 으로 변경)
- **prism = Off** (현재 Off, 그대로)
- **udcap = On** (현재 On, 그대로)
- **Gamepad Support = Off** (현재 Off, 그대로)

→ 이러면 헤드셋이 다시 인식됨.

### Step 1. SteamVR + VD Streamer + UdcapDriver 모두 종료

```powershell
Get-Process | Where-Object { $_.ProcessName -in @(
    "vrserver","vrcompositor","vrdashboard","vrmonitor","vrwebhelper",
    "UdcapDriver","UDCAP_overlay",
    "VirtualDesktop.Streamer","VirtualDesktop.Service"
)} | Stop-Process -Force -ErrorAction SilentlyContinue
```

### Step 2. `steamvr.vrsettings` 의 `driver_udcap.enable = true`

```powershell
$cfg = "C:\Program Files (x86)\Steam\config\steamvr.vrsettings"
Copy-Item $cfg "${cfg}.bak.$(Get-Date -Format yyyyMMdd_HHmmss)" -Force

$json = Get-Content $cfg -Raw | ConvertFrom-Json
if (-not $json.driver_udcap) {
    $json | Add-Member -NotePropertyName driver_udcap -NotePropertyValue ([pscustomobject]@{ enable = $true }) -Force
} else {
    $json.driver_udcap.enable = $true
}
$json | ConvertTo-Json -Depth 32 | Set-Content $cfg -Encoding UTF8
Write-Host "[OK] steamvr.vrsettings.driver_udcap.enable = true"
```

### Step 3. **UDCAP `default.vrsettings`** 의 두 키 활성화 (★ 핵심)

```powershell
$dcfg = "C:\Program Files\UdcapDriver\udcap\resources\settings\default.vrsettings"
Copy-Item $dcfg "${dcfg}.bak.$(Get-Date -Format yyyyMMdd_HHmmss)" -Force

$json = Get-Content $dcfg -Raw | ConvertFrom-Json
$json.driver_UDCAP.enable = $true                       # Step 3
$json.pose_settings.controller_override = $true         # Step 4 (★ 가장 중요)
# controller_override_left/right 는 default 3,4 그대로 유지 (변경 시 시도해 볼 값: 0,1 / 1,2)
$json | ConvertTo-Json -Depth 32 | Set-Content $dcfg -Encoding UTF8
Write-Host "[OK] default.vrsettings.driver_UDCAP.enable = true, pose_settings.controller_override = true"
```

> **주의**: `default.vrsettings` 는 `C:\Program Files` 아래라 일반 PowerShell 권한으로는 쓰기 거부됨. **PowerShell 관리자 권한**으로 실행하거나 메모장 관리자로 직접 수정.

### Step 4. UDCAP UI 의 한 번의 OFF→ON 토글로 driver 재로드 강제

1. 시스템 트레이의 UDCAP UI (UdcapDriver.exe) → 우클릭 → 종료

### 6.4 컨트롤러 type 결정 — RVRPlugin.ini 의 `controllertype`

`C:\Users\<user>\AppData\Local\PICO Link\driver\bin\win64\RVRPlugin.ini` (또는 `C:\Program Files (x86)\Pico Link\driver\bin\win64\RVRPlugin.ini`) 의 `[PICO]` 섹션:

| `controllertype=N` | 결과 controller_type | 우리 앱 binding 매칭 |
|---|---|---|
| 0 | pico_controller (PICO native) | **❌ — bindings_pico_controller.json 추가 작업 필요** |
| 1 | oculus_touch | △ — `ust_260504_win` (gripper) 만 매칭, `ust_fourier_260421` 은 추가 작업 필요 |
| 2 | vive_wands | ❌ |
| 3 (default) | pico_controller | ❌ |

→ 가장 간단: **`controllertype=1`** 로 설정 → oculus_touch 로 emulate → UDCAP 가 그것을 borrow → udcap controller 등록 → 우리 앱의 udcap binding 매칭.

```powershell
$ini = "$env:LOCALAPPDATA\PICO Link\driver\bin\win64\RVRPlugin.ini"
if (-not (Test-Path $ini)) { $ini = "C:\Program Files (x86)\Pico Link\driver\bin\win64\RVRPlugin.ini" }
if (Test-Path $ini) {
    Copy-Item $ini "${ini}.bak" -Force
    (Get-Content $ini) -replace '^controllertype=\d+', 'controllertype=1' | Set-Content $ini -Encoding UTF8
    Write-Host "[OK] RVRPlugin.ini controllertype=1"
} else {
    Write-Host "[WARN] PICO Link RVRPlugin.ini not found — install PICO Connect first"
}
```

## 7. 진단 체크리스트 — 어떤 step 이 실패했나

### 7.1 Plan A 적용 후 SteamVR 진입했는데 udcap controller 가 안 보임

| 증상 | 진단 | 조치 |
|---|---|---|
| Devices 에 udcap controller 0 개 | UDCAP driver 가 device 등록 못 함 | UDCAP UI → Devices : 글러브 "Connected" 인지 확인. 미연결이면 페어링 / 배터리 / USB 동글 점검 |
| Devices 에 oculus_touch 만 보임 | UDCAP 의 controller 등록 실패 | `default.vrsettings.driver_UDCAP.enable = true` 재확인. Step 3 의 PowerShell 명령 다시 실행 |
| UDCAP UI 의 글러브 "Calibration: No" | 캘리브레이션 미완료 | UDCAP UI → 글러브 윗부분의 F1 또는 Calibration 버튼 → Open / Fist / Per-finger 시퀀스 진행 |
| UDCAP UI 의 "IsSteamOpen = false" 표시 | UDCAP 가 SteamVR 못 봄 | SteamVR 가 정상 동작 중인지 확인. UDCAP UI 한 번 종료 후 SteamVR 시작 후 UDCAP 다시 시작 |

### 7.2 udcap controllers 는 보이는데 pose 가 0,0,0 또는 frozen

| 증상 | 원인 | 조치 |
|---|---|---|
| UDCAP controllers 가 0,0,0 위치에 stuck | `pose_settings.controller_override = false` (Step 4 누락) | Step 3 의 PowerShell 다시 실행해 controller_override = true 적용 |
| UDCAP controllers 위치는 정상이지만 buttons 무반응 | binding 미적용 | SteamVR Settings → Controllers → Manage Controller Bindings → 우리 앱 선택 → **"Save Personal Binding"** 클릭 (research/36 gotcha #24) |
| 한쪽 controller 만 정상 (다른 쪽 frozen) | `controller_override_left` 또는 `right` 의 enum 값이 underlying controller 와 매칭 안 됨 | `default.vrsettings` 의 `controller_override_left/right` 를 다른 값으로 시도 (예: 3,4 → 0,1 → 1,2) |

### 7.3 우리 앱의 `_probe_openvr_skeletal()` 결과 `bActive = false`

| 증상 | 원인 | 조치 |
|---|---|---|
| `bActive = false` 모두 | UDCAP 가 Skeletal Input 2.0 advertise 안 함 | UDCAP-Driver 버전 확인. v0.1.8.x 미만이면 [최신 release](https://github.com/Udexreal/Udcap-Driver/releases) 로 업데이트 |
| `bActive = false`, `getBoneCount = 0` | binding 의 skeleton path 매칭 실패 | `bindings_udcap.json` 의 skeleton path (`/user/hand/left/input/skeleton/left`) 가 UDCAP_profile.json 의 정의와 일치하는지 확인 |
| `bActive = true` 지만 모든 bone 0 | 글러브 캘리브레이션 / 페어링 문제 | UDCAP UI → Devices : 글러브 FPS > 30 인지 + 캘리브레이션 완료된 상태인지 |

### 7.4 모든 step 통과해도 트리거/그립 무반응

| 증상 | 원인 | 조치 |
|---|---|---|
| skeletal 은 정상이지만 trigger/grip action 0 | 우리 앱의 action API 에서 trigger/grip 이 binding 안 됨 | `bindings_udcap.json` 의 `/user/hand/*/input/trigger` mode = "button" + click → 우리 actions.json 의 trigger_left/right 매칭 확인. 변경 후 SteamVR 재시작 |
| binding 에 trigger 가 mode "button" 으로 돼있는데 analog 값 필요 | UDCAP 의 `/input/trigger/click` 은 binary, analog pull 별도 path 필요 | `bindings_udcap.json` 에 `/input/trigger` mode "trigger" 추가 (지금은 "click" only) |

## 9. Long-term 개선 — `diagnose_steamvr_drivers.py` 신규 제안

research/38 §10.2 에서 제안한 진단 스크립트를 더 구체화:

```python
"""ust_ws/ust_fourier_260421/scripts/diagnose_steamvr_drivers.py
SteamVR 의 4-단계 driver 활성화 모델을 검증하는 진단 스크립트.

usage:  python -X utf8 -m ust_ws.ust_fourier_260421.scripts.diagnose_steamvr_drivers
"""
import json, os, sys
from pathlib import Path

OPENVR_PATHS = Path(os.environ["LOCALAPPDATA"]) / "openvr" / "openvrpaths.vrpath"
STEAMVR_CFG  = Path(r"C:\Program Files (x86)\Steam\config\steamvr.vrsettings")
UDCAP_DEFAULT = Path(r"C:\Program Files\UdcapDriver\udcap\resources\settings\default.vrsettings")
UDCAP_DLL_CFG = Path(r"C:\Program Files\UdcapDriver\UdcapDriver.dll.config")
SVR_DRIVERS_DIR = Path(r"C:\Program Files (x86)\Steam\steamapps\common\SteamVR\drivers")

def check_step1():
    """openvrpaths.vrpath 의 external_drivers 등록 + SteamVR drivers/ 폴더 검사"""
    paths = json.loads(OPENVR_PATHS.read_text())
    ext = paths.get("external_drivers", [])
    has_udcap = any("UdcapDriver" in p for p in ext)
    builtin = [p.name for p in SVR_DRIVERS_DIR.iterdir() if p.is_dir()]
    print(f"[Step 1] external_drivers count={len(ext)} udcap_present={has_udcap}")
    print(f"         SteamVR builtin drivers: {builtin}")
    print(f"         prism present: {'prism' in builtin}")
    return has_udcap

def check_step2():
    """Manage Add-Ons 토글 (steamvr.vrsettings 에 일부 반영)"""
    cfg = json.loads(STEAMVR_CFG.read_text())
    udcap_drv = cfg.get("driver_udcap", {})
    print(f"[Step 2] (Manage Add-Ons UI 직접 확인 필요 — 자동 진단 불가)")
    print(f"         사용자가 UI 에서 확인해야 함:")
    print(f"           - Virtual Desktop Streamer (Quest) = ON")
    print(f"           - prism = OFF")
    print(f"           - udcap = ON")
    print(f"           - Gamepad Support = OFF")
    return None

def check_step3():
    """driver_udcap.enable in steamvr.vrsettings"""
    cfg = json.loads(STEAMVR_CFG.read_text())
    udcap_drv = cfg.get("driver_udcap", {})
    enable = udcap_drv.get("enable", None)
    print(f"[Step 3] steamvr.vrsettings.driver_udcap.enable = {enable!r}")
    if enable is True:
        print("         ✓ UDCAP driver feature flag enabled")
    else:
        print("         ❌ UDCAP driver disabled — set to true (research/39 §5 Step 2)")
    return enable is True

def check_step4():
    """UDCAP default.vrsettings 의 controller_override + driver_UDCAP.enable"""
    cfg = json.loads(UDCAP_DEFAULT.read_text())
    drv_enable = cfg.get("driver_UDCAP", {}).get("enable", None)
    pose = cfg.get("pose_settings", {})
    override = pose.get("controller_override", None)
    print(f"[Step 4] default.vrsettings.driver_UDCAP.enable = {drv_enable!r}")
    print(f"         default.vrsettings.pose_settings.controller_override = {override!r}")
    print(f"         controller_override_left = {pose.get('controller_override_left')!r}")
    print(f"         controller_override_right = {pose.get('controller_override_right')!r}")
    ok = (drv_enable is True) and (override is True)
    if ok:
        print("         ✓ UDCAP pose override active")
    else:
        print("         ❌ UDCAP not yet pose-overriding — set both to true (research/39 §5 Step 3)")
    return ok

def check_dll_cfg():
    """UdcapDriver.dll.config (UI 측 설정)"""
    txt = UDCAP_DLL_CFG.read_text()
    import re
    keys = ("Controller_Priority", "Controller_Module", "IsSteamOpen", "VMC_State", "VMC_PORT")
    for k in keys:
        m = re.search(rf'<add key="{k}"\s+value="([^"]+)"', txt)
        v = m.group(1) if m else "(missing)"
        print(f"[UI cfg] {k} = {v}")

def main():
    print("=" * 72)
    print("SteamVR 4-단계 driver 활성화 검증 (research/39)")
    print("=" * 72)
    s1 = check_step1()
    print()
    check_step2()
    print()
    s3 = check_step3()
    print()
    s4 = check_step4()
    print()
    check_dll_cfg()
    print()
    print("=" * 72)
    if s1 and s3 and s4:
        print("VERDICT: ✓ 모든 자동 진단 통과 — Manage Add-Ons UI 확인 후 SteamVR 시작")
    else:
        print("VERDICT: ❌ 누락된 step 있음 — research/39 §5 Plan A 실행")
    print("=" * 72)
    return 0

if __name__ == "__main__":
    sys.exit(main())
```

→ 이 스크립트는 9.29 fix 시 신규 추가 권장.

## 10. 결론 — 사용자에게 전달할 한 줄

> **Quest = Virtual Desktop Streamer (Quest) 항목이며 PICO 가 SteamVR 에 보이는 유일한 통로이므로 절대 끄지 말 것. 진짜 켜야 할 것은 (1) Manage Add-Ons : VD ON + prism OFF + udcap ON, (2) `steamvr.vrsettings.driver_udcap.enable = true`, (3) `default.vrsettings.driver_UDCAP.enable = true` + **`pose_settings.controller_override = true`** 이 4단계. 이전 보고서 (research/38) 에서 권장했던 "오큘러스 비활성화" 는 사용자 환경에선 잘못된 안내였다 — UDCAP 는 oculus_touch 를 swap 하는 게 아니라 자기 자신의 udcap-type virtual controller 를 새로 만들고 oculus_touch 의 pose 를 borrow 하는 방식이라, oculus_touch (= VD 의 emulator) 가 살아있어야 정상 동작한다. controller_override = true 를 켜면 PICO Touch 의 실제 위치 + UDCAP 글러브 finger 데이터가 합쳐진 udcap controller 가 SteamVR 에 등록되고, 우리 앱의 actions.json 이 controller_type=udcap binding 을 적용한다. 4단계 모두 활성 후 `_probe_openvr_skeletal()` 의 `bActive=True` 가 보이면 research/37 의 Phase X1 (Skeletal primary) 즉시 진행 가능.**
