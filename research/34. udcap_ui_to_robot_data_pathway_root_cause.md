### 답: **세 층 모두 원인이 있고, 모두 해결 가능하다 — H/W 는 정상이다.**

### 한 줄 답
> **PICO 핸드트래킹으로 전환할 필요 없음**. UDCAP UI 의 두 가지 설정(Space Plan = "Custom", Controller_Priority = Low/False) 변경 + Isaac Lab 측 0.5~1일치 추가 fix(VMC mimic 임계값, rest cal 윈도우 복원) 만으로 GIF 의 UDCAP UI 정밀도가 로봇에 그대로 반영된다.

### 2.3 결정적 사실 — UDCAP UI ≠ UDCAP export

```
UDCAP UI 의 정밀도            >>>>>>>>>>>>>>>>>>>>>>>      UDCAP export 채널의 정밀도
(internal IPC, full sensor)                                  (SteamVR Skeletal=죽음, Index curl=죽음, VMC=유일)

→ 이 격차가 GIF 의 핵심 미스터리의 정체.
→ UDCAP UI 는 GIF 의 영광스러운 손가락 모션을 보여주지만,
   외부 어플(=Isaac Lab) 이 받을 수 있는 것은 **VMC 채널 하나뿐**.
```

### 2.4 VMC 채널의 잠재적 lossy 지점 (가설 검증 필요)

VMC OSC 채널이 정확히 무엇을 송출하는지가 본 분석의 핵심.  세 가지 가능성:

| 가설 | 의미 | 검증법 |
|---|---|---|
| **H1** — 모든 15 finger bone × 2 hand 가 정확한 quat 으로 송출 | 정밀도는 UDCAP UI 와 동일.  Isaac Lab 코드 측이 100% 원인 | `sniff_vmc_finger_motion.py --seconds 8` 실행 → 15/15 finger live |
| **H2** — Proximal bone 만 송출, Intermediate/Distal 은 identity | UDCAP 가 1-DoF-per-finger 로 quantize.  중간/원위 마디 상실 | sniff 결과: Proximal 만 live, Intermediate/Distal 은 static |
| **H3** — 일부 bone 만 송출, 일부는 frozen | UDCAP UI 가 보여주는 model 보다 export 가 sparse | sniff 결과: 일부 finger 는 live 일부는 static |

→ 이 검증은 사용자가 1분 (sniff_vmc_finger_motion.py 실행) 만에 끝낼 수 있다.  본 문서가 다음 조치를 즉시 갈라낸다.

## 4. 채널별 상세 진단 — 무엇이 정밀도를 잠식하는가

### 4.1 UDCAP UI 측 정밀도 (참조 기준)

UDCAP 의 12 elastic sensor 가 송출하는 raw 데이터:
- 각도 해상도: 0.01° (claim)
- 송출 속도: 120Hz, <10ms 지연
- 21 joint angles per glove
- USB 동글 → UdcapDriver.exe 까지 lossless

UI 가 보여주는 hand model 은 이 21 angle 을 anatomically 일관된 5 finger × 다관절 hand skeleton 으로 reconstruct 한 것.  → **5 손가락 articulate 모션이 정확히 보이는 이유**.

### 4.2 SteamVR Skeletal Input 2.0 채널 (이론상 31-bone, 실제 죽음)

UDCAP 가 SteamVR 에 등록하는 driver_UDCAP 가 OpenVR Skeletal API 에 31-bone hand skeleton handle 을 publish 하는 것이 표준 흐름.

memory.md §10.22 (9.13) 의 진단:
```
left_finger: idle, right_finger: idle      ← 두 손 모두 finger 소스 미해결
action curls=[thb=0.00 idx=0.00 mid=0.00 rng=0.00 pnk=0.00]   ← SteamVR Input curl 모두 0
Skeletal: bActive=False                    ← UDCAP가 Skeletal Input 2.0 미구현
```

→ **bActive=False 는 UDCAP 측이 등록은 하나 실제로 frame data 를 push 안 한다는 의미**. UDCAP 펌웨어 V1.6.0 (GIF 에 표시됨) 의 한계로 추정.

UDEXREAL 공식 문서는 "Skeletal Input 2.0 perfectly supports VRChat" 이라 광고하나, 사용자 환경 (Pico 4 Ultra + Virtual Desktop) 에서는 작동 안 함.  이는 LucidVR-family (Lucas VR Glove, UDCAP 등) 의 알려진 이슈로, VRChat 자체에서는 OSC fallback 으로 우회한다.

→ **이 채널 활용은 UDCAP 펌웨어 업그레이드 또는 다른 VR plugin 환경 (e.g. SteamVR direct + Vive Tracker)** 이 필요. 현 환경에서는 사용 불가.

### 4.5 우리 코드 측 — VMC quat → bend 변환의 잠재 누락

`fourier_hand_mapper._quat_to_bend()`:
```python
def _quat_to_bend(qx, qy, qz, qw) -> float:
    angle = 2.0 * math.acos(max(-1.0, min(1.0, abs(qw))))
    return float(max(0.0, min(1.0, angle / math.pi)))
```

→ 임의 축 회전의 **총 회전 magnitude** 를 [0, 1] 로 정규화.  손가락 flex 가 1축 회전이라면 정확.  thumb 처럼 다축 (yaw + pitch + ...) 인 본은 magnitude 가 분리되지 않음 (별도 `_quat_to_yaw` 보조).

`_fill_mimic_inplace()`:
```python
def _fill_mimic_inplace(self, out: np.ndarray) -> None:
    for prox, inter in (...):
        if abs(float(out[inter])) < 1e-6:           # ← 너무 엄격
            out[inter] = out[prox] * self.intermediate_mimic
```

문제: UDCAP VMC 가 Intermediate 본을 emit 할 때 그 quat 이 거의 identity 면 `_quat_to_bend` 가 ~0.001 rad 같은 작은 값을 반환.  `abs(0.001) > 1e-6` 이므로 **mimic 채우기를 skip** → intermediate 슬롯은 거의 0 으로 남음 → robot 손가락이 PIP 굽힘이 거의 없는 모습.

이것이 사용자가 "GIF 의 UDCAP UI 는 finger 가 휘는데 robot 은 펴진 채" 보이는 한 가지 이유.

#### 4.5.1 검증법

`fourier_hand_mapper.py` map_hand_vmc 에 임시 디버그 print 추가:
```python
for finger, prox_idx, int_idx in finger_pairs:
    ...
    if inter is not None:
        inter_rel = self._vmc_quat_relative_to_rest(inter_name, inter)
        bend = _quat_to_bend(*inter_rel)
        print(f"VMC {inter_name} bend={bend:.4f}")
        out[int_idx] = self._amplify(bend, ...)
```

→ 만약 모든 intermediate bend 값이 < 0.05 같은 작은 값이면 → UDCAP 가 intermediate quat 을 1-DoF 추정으로 emit → **mimic 임계값 0.05 로 키워야 함**.

### 4.6 vmc_rest_frames 의 양날 — 9.18 의 30→10 단축 부작용

memory.md §10.27 (9.18) 변경:
```python

```

이론상: 사용자가 0.5초만 가만히 있으면 됨 → 사용자 fidget 영향 줄어듦.

실제: UDCAP VMC bone quat 은 자체 noise 가 있고 (~5° per frame), 10 frame (0.5s) 안에 사용자 손이 미세하게 움직일 수 있어 **rest 가 사용자 motion 을 흡수**.

#### 6.2.1 `fourier_hand_mapper.py` — mimic 임계값 키움

```python
def _fill_mimic_inplace(self, out: np.ndarray) -> None:
    """Fill intermediate / distal slots when they are still ZERO OR TINY.

    9.19: 임계값 1e-6 → 0.05 rad (~3°).  UDCAP VMC 가 intermediate 본을
    near-identity quat 으로 emit 할 때 (PIP 센서가 1-DoF-per-finger 로
    quantize) `_quat_to_bend` 가 작은 nonzero 값을 반환 → 기존 코드는
    mimic skip → robot intermediate slot 거의 0 → 손가락 PIP 굽힘 시각적 부재.
    이제 0.05 rad 미만이면 mimic 적극 채움.
    """
    MIMIC_THRESHOLD = 0.05    # rad, ~3°
    for prox, inter in (
        (IDX_INDEX_PROX, IDX_INDEX_INT),
        (IDX_MIDDLE_PROX, IDX_MIDDLE_INT),
        (IDX_RING_PROX, IDX_RING_INT),
        (IDX_PINKY_PROX, IDX_PINKY_INT),
    ):
        if abs(float(out[inter])) < MIMIC_THRESHOLD:
            out[inter] = out[prox] * self.intermediate_mimic
    if abs(float(out[IDX_THUMB_DIST])) < MIMIC_THRESHOLD:
        out[IDX_THUMB_DIST] = out[IDX_THUMB_PITCH] * self.distal_mimic
```

검증: 기존 `tests/test_fourier_hand_mapper.py` 의 `TestVMCRestPoseCalibration` 케이스에서 intermediate slot 출력이 prox × 0.85 로 일관되는지 추가 assert.

## 7. PICO XRT 전환 비교 (한 번 더 — 본 GIF 영상 관점에서)

### 7.1 만약 PICO XRT 로 전환한다면 본 격차가 해결되는가?

|---|---|---|

| 손가락 정밀도 | UDCAP UI 수준 (글러브 hardware spec) | XRT 카메라 60Hz, occlusion 의존 |

| 위험 | 낮음 | 높음 (research §33 cascade) |

### 7.2 만약 9.19 패치 적용 후에도 부족하면?

UDCAP UI 와 robot 사이 격차가 9.19 후에도 잔존하는 경우 결정적 원인은:
1. UDCAP H/W 결함 (해당 글러브 unit) — 보증 교환 (research §33 §6.2 참조)
2. UDCAP 펌웨어 V1.6 한계 — Udexreal 펌웨어 업그레이드
3. UDCAP 자체 spec 한계 — Manus Quantum 등 mocap-grade glove 로 업그레이드 (research §33 §6.3 참조)

이 단계에서도 PICO XRT 전환은 ROI 가 가장 낮은 옵션이다.
