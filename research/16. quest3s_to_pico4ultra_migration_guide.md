### Phase 1: PICO 4 Ultra 기본 설정 (Day 2 AM)

#### 1.1 PICO 4 Ultra 초기 설정

```
1. 헤드셋 전원 ON → 초기 설정 마법사 진행
2. WiFi 연결:
   - 서버(Isaac Lab PC)와 동일한 5GHz WiFi 네트워크에 연결
   - WiFi 6 (802.11ax) 라우터 권장
   - 전용 5GHz 대역 사용 권장 (2.4GHz 간섭 회피)
3. PICO 계정 로그인
4. PUI 소프트웨어 업데이트:
   - 설정 → 일반 → 소프트웨어 업데이트
   - PUI 5.12+ 필요 (XRoboToolkit 최소 요구사항)
```

#### 1.2 개발자 모드 활성화

```
1. 설정(Settings) → 일반(General) → 개발자(Developer)
2. 개발자 모드 ON
3. USB 디버깅 ON
4. PC에서 adb 연결 확인:
   $ adb devices
   # PICO 디바이스 ID가 표시되어야 함
```

#### 1.3 PICO Connect (PC 스트리밍 소프트웨어) 설치

**PC 측:**
```bash
# PICO Connect 다운로드 (공식)
# https://www.picoxr.com/global/software/pico-link
# Windows PC에 설치

# 설치 후:
1. PICO Connect 실행
2. 연결 모드 선택: WiFi (무선 권장) 또는 USB
3. WiFi: PICO 헤드셋과 동일한 네트워크인지 확인
```

**PICO 헤드셋 측:**
```
1. PICO Store에서 "PICO Connect" 앱 설치
2. 앱 실행 → PC와 연결
3. 연결 성공 확인
```

#### 1.4 SteamVR 연결 확인

```
1. PC에서 PICO Connect 실행 → 연결 완료
2. PC에서 SteamVR 실행
3. PICO 헤드셋에서 SteamVR Home 화면 확인
4. 컨트롤러 트래킹 정상 동작 확인
```

> **⚠ 주의**: PICO Connect는 높은 권한으로 실행되며, SteamVR 애드온을 초기화할 수 있음. 최신 버전 사용 필수.

### Phase 2: Motion Tracker 셋업 (Day 2 AM)

#### 2.1 Motion Tracker 페어링

```
1. PICO 4 Ultra 헤드셋에서 "Motion Tracker" 앱 실행
2. 발목 트래커 페어링:
   a. 트래커의 상단 버튼을 6초간 길게 누름 (LED가 빨간색+파란색 깜빡)
   b. 앱에서 "Pair" 클릭
   c. 두 번째 발목 트래커도 동일 과정
3. 허리 트래커 페어링:
   a. 동일 과정 (6초 길게 누름 → "Pair")
```

#### 2.2 트래커 장착

```
발목 트래커 (2개):
├── 발목 스트랩에 트래커 삽입
├── 버튼/LED가 위쪽(상방)을 향하도록
├── 트래커 전면이 앞쪽(전방)을 향하도록
└── 양 발목에 스트랩 고정 (흔들리지 않도록)

허리 트래커 (1개):
├── 허리 스트랩에 트래커 삽입
├── 허리 중앙-뒤쪽(등 쪽)에 장착
└── 스트랩 고정
```

#### 2.3 Body Tracking 캘리브레이션

```
1. Motion Tracker 앱에서 "Calibrate" 클릭
2. 서 있는 자세에서 5초간 가만히
3. 캘리브레이션 완료 확인
4. 양다리를 번갈아 들어보며 Body Tracking 동작 확인
```

#### 2.4 Body Tracking 설정 확인

```
설정 → Body Tracking:
├── Full-Body Tracking 모드 선택
├── 트래커 3개 연결 확인 (발목 2 + 허리 1)
└── 캘리브레이션 상태: 완료
```

### Phase 3: UDCAP VR Gloves 셋업 (Day 2 PM)

#### 3.1 UDCAP 소프트웨어 설치 (PC)

```bash
# 1. UDCAP 소프트웨어 다운로드
#    https://udcap-vr-gloves-document.gitbook.io/udcap/software-setup/software-installation-and-update-log

# 2. PC에 설치 (관리자 권한)

# 3. SteamVR 드라이버 설치 확인:
#    SteamVR → 설정 → Startup/Shutdown → Manage Add-ons

```

#### 3.2 UDCAP 글러브 하드웨어 연결

```
1. 2.4GHz USB 동글을 PC USB 포트에 삽입
2. 양손 글러브 전원 ON
3. UDCAP 소프트웨어 실행 (관리자 권한으로!)
4. 글러브 연결 상태 확인 (녹색 LED)
```

#### 3.3 PICO Controller Tracking Plan 설정

**이것이 핵심: PICO 컨트롤러를 UDCAP 글러브에 마운트하여 손 공간 위치 추적**

```
UDCAP Software:
1. Spatial Positioning 메뉴
2. "Custom Solution" 선택
3. ± 버튼으로 글러브 위치 미세 조정
4. "Controller Priority" → "High" 설정
   (PICO 컨트롤러 입력을 글러브가 우선 대체)
```

#### 3.4 PICO 컨트롤러 글러브 마운트

```
방법 A: 3D 프린트 어댑터 (추천)
├── UDCAP 공식 3D 프린트 파일 다운로드
│   https://udcap-vr-gloves-document.gitbook.io/udcap/hardware-setup/other-adapter-3d-print-file
├── Quest Controller 어댑터를 기반으로 PICO Controller 규격에 맞게 수정
└── 글러브 등판의 Data Box에 어댑터 고정

방법 B: 벨크로/고무밴드 임시 고정
├── PICO 컨트롤러를 글러브 등판에 벨크로로 부착
└── 컨트롤러 IR 링이 외부로 노출되도록 (헤드셋 카메라가 인식 가능하게)
```

> **⚠ 중요**: PICO 컨트롤러의 IR 링이 헤드셋 카메라에 보여야 위치 추적이 됨. 글러브에 마운트할 때 IR 링이 가려지지 않도록 주의.

#### 3.5 UDCAP 캘리브레이션

```
1. UDCAP Software에서 "Calibrate" 클릭
2. 3가지 핸드 제스처 순서대로 수행:
   a. 손 완전히 펼치기 (Open Hand)
   b. 주먹 쥐기 (Fist)
   c. 자연스러운 손 (Relaxed)
3. 캘리브레이션 완료 확인
4. SteamVR Home에서 글러브 아이콘이 하이라이트(활성) 상태인지 확인
```

#### 3.6 트러블슈팅

```
문제: SteamVR에서 글러브 아이콘이 회색(비활성)
해결:
1. udcap_overlay.exe를 관리자 권한으로 수동 실행:
   경로: Steam설치폴더/steamapps/common/SteamVR/drivers/udcap/bin/win64/
2. PICO Connect, Steam, SteamVR, UDCAP 모두 동일한 권한(관리자) 레벨로 실행
3. PICO Connect를 최신 버전으로 업데이트 (구버전은 SteamVR 애드온을 초기화함!)
```

### Phase 4: CloudXR 연결 테스트 (Day 2 PM)

#### 4.1 기존 CloudXR 인프라 확인

```bash
# 서버(Isaac Lab PC)에서:

# 1. Docker 컨테이너 확인
docker ps | grep cloudxr
# cloudxr-runtime 6.0.1-webrtc 가 실행 중인지 확인

# 2. 실행 중이 아니면 시작
cd /workspace/isaaclab
docker compose -f docker/docker-compose.cloudxr-runtime.patch.yaml \
               -f ust_ws/ust_260207/docker-compose.cloudxr-ust.patch.yaml up -d

# 3. 환경변수 설정
source ust_ws/ust_260207/setup_cloudxr_env.sh

# 4. CloudXR.js 개발 서버 시작
cd ust_ws/cloudxr_js/isaac
npm run dev-server:https
# → https://서버IP:8080 에서 접속 가능
```

#### 4.2 PICO 4 Ultra에서 CloudXR 접속

```
1. PICO 4 Ultra의 내장 브라우저 열기
2. 주소 입력: https://서버IP:8080
3. 자체 서명 SSL 인증서 수락 (CloudXR.js 서버)
4. CloudXR 접속 폼에서:
   - Server IP: 서버의 LAN IP (예: 192.168.0.117)
   - Port: 48322 (HTTPS + HAProxy 모드)
   - "Connect" 클릭
5. HAProxy SSL 인증서도 수락 (포트 48322)
6. "Enter VR" 버튼 클릭
7. Isaac Sim 시뮬레이션 화면이 PICO 헤드셋에 표시되는지 확인
```

#### 4.3 변경 불필요 항목 확인

| 항목 | 파일 | 변경 | 이유 |
|------|------|------|------|
| CloudXR Runtime Docker | docker-compose.*.yaml | **변경 없음** | 디바이스 무관, WebRTC 표준 |
| CloudXR.js 소스코드 | cloudxr_js/isaac/src/ | **변경 없음** | WebXR가 PICO 프로필 자동 감지 |
| 해상도/프레임레이트 | CloudXR2DUI.tsx | **변경 없음** | 2048x1792@90Hz 이미 PICO 최적 |
| OpenXR 매니페스트 | openxr_cloudxr.json | **변경 없음** | CloudXR Runtime측 설정 |
| 환경변수 | setup_cloudxr_env.sh | **변경 없음** | XR_RUNTIME_JSON, IPC 동일 |
| HAProxy 프록시 | cloudxr_js/proxy/ | **변경 없음** | WSS→WS 프록시 디바이스 무관 |
| WebXR Input Profiles | cloudxr_js/isaac/public/npm/ | **변경 없음** | `pico-4u/profile.json` 이미 존재 |

> **핵심**: 기존 CloudXR 인프라는 **100% 그대로 재사용**한다. Quest 3S 전용 설정은 존재하지 않았으며, WebXR 표준으로 디바이스 무관하게 동작한다.

### Phase 5: XRoboToolkit 셋업 (Day 3 AM) — Full-Body Teleop용

XRoboToolkit은 NVIDIA GR00T WBC에서 **PICO의 전신 Body Tracking 데이터를 Isaac Lab으로 전달**하는 데 사용된다.

#### 5.1 XRoboToolkit PC Service 설치

```bash
# Isaac Lab PC (Ubuntu)에서:

# 1. XRoboToolkit 클론
git clone https://github.com/XR-Robotics/XRoboToolkit-PC-Service.git
cd XRoboToolkit-PC-Service

# 2. 의존성 설치 (Ubuntu 22.04/24.04)
# 설치 가이드 참조: https://github.com/XR-Robotics/XRoboToolkit-PC-Service

# 3. PC Service 시작
# (상세 명령은 공식 문서 참조)
```

#### 5.2 XRoboToolkit PICO App 설치

```bash
# PC에서 adb로 APK 설치:

# 1. XRoboToolkit APK 다운로드 (v1.1.1 이상)
#    https://github.com/XR-Robotics 릴리즈 페이지

# 2. adb로 설치
adb install XRoboToolkit-v1.1.1.apk

# 3. PICO 헤드셋의 "알 수 없는 소스(Unknown)" 라이브러리에서 앱 확인
```

#### 5.3 XRoboToolkit 연결

```
PICO 헤드셋에서:
1. XRoboToolkit 앱 실행
2. "PC Service" 필드에 PC의 IP 주소 입력
3. 연결 상태가 "WORKING"으로 표시되는지 확인
4. Motion Tracker 데이터가 PC Service로 전송되는지 확인
```

#### 5.4 XRoboToolkit 캘리브레이션


## 5. 운영 모드 전환 (Quest 3S ↔ PICO 4 Ultra)

두 헤드셋을 상황에 따라 전환하며 사용할 수 있다:

```
서버(Isaac Lab PC)측: 변경 없음
├── CloudXR Runtime: WebXR 디바이스 자동 감지
├── Isaac Lab: OpenXRDevice 디바이스 무관
└── HAProxy: WebSocket 프록시 디바이스 무관

클라이언트측만 전환:
├── Quest 3S 사용 시:
│   └── Quest 브라우저 → https://서버IP:8080
│       → CloudXR.js → "meta-quest-touch-plus" 프로필 자동 감지
│
└── PICO 4 Ultra 사용 시:
    └── PICO 브라우저 → https://서버IP:8080
        → CloudXR.js → "pico-4u" 프로필 자동 감지
```

**핵심**: 서버측을 전혀 건드리지 않고, **헤드셋만 바꿔 쓰면** 된다.

## 6. 잠재적 이슈 및 대응

### 6.1 알려진 주의사항

| 이슈 | 원인 | 대응 |
|------|------|------|
| PICO Connect가 SteamVR 애드온 초기화 | PICO Connect 높은 권한 | 최신 PICO Connect 사용, UDCAP 재활성화 |
| UDCAP 글러브 SteamVR 비활성 | 권한 레벨 불일치 | 모든 소프트웨어 관리자 권한 실행 |
| SSL 인증서 2개 수락 필요 | 자체 서명 인증서 | 8080(CloudXR.js) + 48322(HAProxy) 둘 다 수락 |
| Motion Tracker IMU drift | IMU 센서 특성 | 주기적 재캘리브레이션 (Motion Tracker 앱) |
| 컨트롤러 글러브 마운트 무게 | ~170g 추가 | 3D 프린트 경량 어댑터 사용, 장시간 시 휴식 |
| PICO PUI 업데이트 후 호환성 | OS 업데이트 | PUI 5.12+ 유지, 자동 업데이트 주의 |
