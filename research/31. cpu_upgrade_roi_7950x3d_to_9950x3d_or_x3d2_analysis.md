# 31. 7950X3D → 9950X3D / 9950X3D2 업그레이드 ROI 분석 — 우리 teleop task에서 체감 변화 폭

> 작성: 2026-05-03 (§30 보고서 후 사용자가 CPU 업그레이드가 도움 될지 정량 답변 요청)
> 결론 한 줄: **단일 env teleop 시나리오에서는 체감 변화가 거의 0이다.** 현재 한계는 input pipeline ceiling (UDCAP 140 Hz / SteamVR 120 Hz / HMD 90 Hz)이지 CPU가 아니기 때문. 9950X3D2는 RL training/multi-env에서만 큰 효과.

## 0. Executive Summary

### 핵심 답변
| 질문 | 답 |
|---|---|
| CPU가 부족해서 그 이상 frame rate가 못 나오는가? | **아니다.** 진짜 한계는 input pipeline ceiling (UDCAP 140 Hz). 7950X3D Pink IK QP는 8.33 ms budget의 18~60% 만 사용. |

## 1. 비교 대상 CPU 정확 스펙 (2026-05 기준)

| 항목 | **7950X3D** (현재) | **9950X3D** | **9950X3D2 Dual** |
|---|---|---|---|
| 출시 | 2023-02 | 2025-03 | **2026-04-22** |
| 아키텍처 | Zen 4 | Zen 5 | Zen 5 |
| 코어/스레드 | 16C/32T | 16C/32T | 16C/32T |
| Base / Boost | 4.2 / 5.7 GHz | 4.3 / 5.7 GHz | 4.3 / **5.6 GHz** |
| Total L3 | 128 MB (V-Cache 64MB on **1 CCD only**) | 144 MB (V-Cache on 1 CCD, 2nd-gen below cores) | **192 MB (V-Cache on BOTH CCDs)** |
| TDP | 120 W | 170 W | 200 W |
| Single-thread vs 7950X3D | baseline | **+8.5%** | 비슷 (boost 0.1 GHz 낮음, V-Cache 활용도 ↑로 상쇄) |
| Multi-thread vs 7950X3D | baseline | **+22% avg, +32% peak** | 더 높음 (양 CCD parity) |
| MSRP | $699 | $699 | **$899** |
| 핵심 차별점 | 1세대 V-Cache, V-Cache CCD scheduling 필요 | 2세대 V-Cache (코어 아래 배치 → 46% 열 저항 ↓) | **양쪽 CCD 모두 V-Cache** → scheduling 문제 자동 해결 |

### 1.1 세대별 V-Cache 진화
- **1세대 (Zen 3/4 X3D)**: V-Cache가 **코어 위에** stack → 열 차폐, clock 500 MHz 강제 hold
- **2세대 (Zen 5 X3D)**: V-Cache가 **코어 아래에** 배치 → 열 직결, **5.7 GHz boost 유지** 가능
- **Dual-cache (9950X3D2)**: 양쪽 CCD 모두 V-Cache 탑재 → CCD scheduling 무의미해짐

### 1.2 CCD scheduling 이슈 (7950X3D 특유)
[Overclock.net 가이드](https://www.overclock.net/threads/how-does-the-amd-7950x3d-and-9950x3d-ccds-work.1814692/)에 따르면:
- 7950X3D는 **V-Cache CCD (CCD0)**에만 64 MB extra L3 → 8 코어만 cache 혜택
- Windows 스케줄러가 cache-heavy 작업을 V-Cache CCD로 보내야 효과 발휘
- 필수 설정:
  1. BIOS CPPC = "driver"
  2. AMD chipset driver 최신
  3. **AMD 3D V-Cache Performance Optimizer Service** 실행 중
  4. Windows Game Bar / Game Mode 활성
- 만약 Pink IK가 non-V-Cache CCD (CCD1)로 schedule되면 → 7950X와 같은 성능 (V-Cache 효과 0)

→ **이 점이 우리 환경에서 검증되어야 함**. 만약 잘못 schedule되고 있다면 9950X3D2가 즉시 큰 차이를 만들 수 있다.

## 2. 우리 Task의 CPU Bottleneck 진단

### 2.1 Pink IK QP는 우리 시스템의 single-thread CPU work
- **Pink IK 호출 빈도**: env step 마다 1회 → 20 Hz / 60 Hz / 120 Hz
- **단일 스레드**: numpy/scipy + Pinocchio C++ + osqp 모두 single-thread
- **Cache footprint**: Pinocchio kinematics tree (~2 MB), osqp QP matrix (~1 MB) — V-Cache (96 MB)에 충분히 fit

### 2.2 우리 task의 다른 CPU work
| 작업 | 스레드 | 영향 |
|---|---|---|
| **Pink IK QP** | 1 (main) | env step rate 종속 |
| **VMC OSC receiver** | 1 (background) | 140 Hz UDP packet decode |
| **SteamVR Sampler thread** | 1 (background) | 120 Hz pose query |
| **Isaac Sim main loop** | 1 (Python) + 8 (PhysX worker) | 단일 env면 8 thread는 거의 무사용 |
| **Render thread** | 1 + GPU offload | RTX PRO 6000으로 GPU 종속 |
| **VMC packet jitter handling** | 1 | 우리 EMA는 main loop에 |

### 2.3 우리 시스템에서 진짜 CPU bottleneck인가?
[Isaac Sim Performance Optimization Handbook](https://docs.isaacsim.omniverse.nvidia.com/6.0.0/reference_material/sim_performance_optimization_handbook.html):
> "Environment throughput can be dependent on single-core CPU performance due to bottlenecks in some parts of PhysX simulation and the main training loop."

[Isaac Lab GitHub Issue #3043](https://github.com/isaac-sim/IsaacLab/issues/3043):
> "Low GPU Utilization vs High Single-Core CPU Usage During RL Training"

**우리 시스템 평가**:
- **Teleop (단일 env, 9.23 fix 이후)**: Pink IK QP 1.5~5 ms / 8.33 ms budget → **CPU 종속이지만 budget 내에서 완전히 처리 가능**
- **RL training (1024+ envs)**: **CPU bottleneck 진짜 발생** — 단일 코어가 모든 env의 main loop 처리

→ **현재 teleop에서는 CPU bottleneck이 진짜 한계가 아님**.

## 3. 진짜 한계는 Input Pipeline Ceiling

### 3.1 우리 시스템의 frame rate ceiling 계층

```
┌─────────────────────────────────────────────────────────┐
│ Layer 1: Hardware sensors                              │
│   UDCAP gloves      : ~140 Hz max (UDCAP driver 한계)    │
│   Vive forearm      : 250 Hz raw                       │
│   Pico HMD pose     : 90 Hz (display refresh)           │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│ Layer 2: Streaming                                     │
│   Virtual Desktop   : 90 Hz lock (HMD bound)            │
│   USB UDP (UDCAP)   : 140 Hz                            │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│ Layer 3: SteamVR Sampler                               │
│   rate_hz=120 (default)                                 │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│ Layer 4: VMCHandReceiver / latest_bones()              │
│   140 Hz UDP packets, latest only                      │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│ Layer 5: Isaac Lab env.step()                          │
│   sim.dt × decimation                                   │
│   현재: 1/120 × 6 = 50 ms = 20 Hz                       │
│   변형 C: 1/120 × 1 = 8.33 ms = 120 Hz ★ 권장 최대       │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│ Layer 6: Pink IK QP (CPU)                              │
│   warm-start avg 1.5 ms, P99 5 ms (7950X3D)            │
│   9950X3D 추정 : avg 1.4 ms, P99 4.5 ms                 │
│   9950X3D2 추정: avg 1.4 ms, P99 4.0 ms                 │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│ Layer 7: PhysX articulation step (GPU)                 │
│   RTX PRO 6000 단일 env: ~0.5 ms                        │
└─────────────────────────────────────────────────────────┘
```

### 3.2 핵심 통찰
- **Layer 1~4는 hardware/protocol bound** — CPU 업그레이드로 풀리지 않음
- **Layer 5는 우리가 조정 가능** — 그러나 Layer 1~4의 ceiling 이상 의미 없음
- **Layer 6~7은 우리 PC HW 종속** — 하지만 8.33 ms budget의 18~60% 만 사용 중

### 3.3 240 Hz로 올리려면?
- env step 240 Hz 시도 시:
  - Layer 4 (UDCAP 140 Hz): 절반의 step은 같은 packet 두 번 읽음 → 정보 0% 추가
  - Layer 5: budget 4.17 ms
  - Layer 6: P99 5 ms (7950X3D) → **violation**, 4.5 ms (9950X3D) → 가끔 violation, 4.0 ms (9950X3D2) → safe
  - **그러나 Layer 4의 ceiling이 풀리지 않으므로 의미 없음**

### 4.4 시각화 — "업그레이드해도 변화 없는 이유"

## 5. 9950X3D2가 진짜 빛나는 시나리오

### 5.1 단일 env teleop (우리 현재 use case)
- **체감 변화**: 거의 0
- 이유: input ceiling이 진짜 한계, CPU는 이미 충분

### 5.2 RL training (1024~4096 env)
- 매 step마다 4096 envs의 main loop가 단일 코어에서 처리
- **8.5% IPC 향상 + dual-CCD V-Cache → step rate ~25~30% ↑**
- 24시간 training이 18~19시간으로 단축
- **체감 변화**: 매우 큼

### 5.3 동시 작업 (teleop + screen recording + Discord)
- 7950X3D는 V-Cache CCD에 teleop process가 schedule 안 되면 성능 ↓
- 9950X3D2는 어느 CCD든 V-Cache 사용 가능 → **모든 작업 동시에 일관 성능**
- **체감 변화**: 중간 (특히 OBS 스트리밍 + sim 동시 시)

### 5.4 Imitation learning policy training (BC-RNN, Diffusion Policy)
- numpy/scipy/PyTorch CPU work 비중 ↑ (특히 dataset loading)
- **체감 변화**: 작음~중간

### 5.5 RTX PRO 6000 활용 극대화
- RTX PRO 6000의 GPU work를 supply하는 CPU side가 한계가 될 수 있음
- 9950X3D2의 dual-CCD V-Cache가 PCIe traffic + Python overhead 처리에 효과
- **체감 변화**: 작음 (대부분 GPU bound이라 미세)

## 7. CCD Scheduling 검증 (7950X3D 사용자 즉시 점검)

### 7.1 V-Cache CCD에 Pink IK가 올라가는지 확인
**Windows 환경 점검**:
```powershell
# AMD 3D V-Cache Performance Optimizer Service 상태
Get-Service | Where-Object {$_.Name -match "AMD3D"}
# 결과: Status = Running 이어야 함

# AMD chipset driver 버전
Get-WmiObject Win32_PnPSignedDriver | Where-Object {$_.DeviceClass -eq "PROCESSOR"} | Select DriverVersion

# Game Mode 활성 확인 (Settings > Gaming > Game Mode)
# 또는 Process Affinity 직접 강제
```

### 7.2 Process Affinity 강제 (의심 시)
Pink IK가 V-Cache CCD에 안 올라가면 → Python 프로세스를 CCD0 (cores 0~7)에 강제:
```powershell
# python.exe PID를 cores 0~7 (CCD0)에 묶기
$pid = (Get-Process python | Where-Object {$_.Path -match "ust"}).Id
Start-Process powershell -ArgumentList "-Command Set-ProcessAffinity -PID $pid -Affinity 0xFF"
```
또는 Process Lasso / Process Hacker 같은 도구로 영구 affinity 설정.

### 7.3 검증 후 결과별 권장
| 검증 결과 | 권장 |
|---|---|
| V-Cache CCD 정상 활용 | **현재 7950X3D 그대로** — 업그레이드 ROI 0 |
| V-Cache CCD 미활용 (CCD1로 schedule) | **Process Affinity로 CCD0 강제** → 그대로 7950X3D 활용 |
| 위 둘 다 적용 후에도 P99 violation | **9950X3D2가 가치 있을 수 있음** (그래도 input ceiling 때문에 작음) |

## 8. 사용자 specific 질문에 대한 정확한 답변

### Q1. CPU 성능이 부족해서 그 이상의 frame rate를 못 올리는 것인가?
**답: 아니다 (단일 env teleop 기준)**.

- **현재 한계**: input pipeline ceiling (UDCAP 140 Hz / SteamVR 120 Hz / HMD 90 Hz / VD 90 Hz)
- **120 Hz env step (변형 C)에서 7950X3D Pink IK는 budget의 18~60%만 사용** — CPU가 한계가 아니다
- 240 Hz로 올리면 CPU가 빠듯해지지만 **동시에 input ceiling 초과로 정보가 추가되지 않음**
- → 결론: **CPU는 충분, input pipeline이 진짜 한계**

### Q2. 9950X3D 또는 9950X3D2로 업그레이드 시 체감?
**답: 단일 env teleop 시나리오에선 매우 작음 (거의 0)**.

- 9950X3D: single-thread +8.5%, Pink IK P99 5 ms → 4.5 ms
- 9950X3D2: single-thread 비슷, dual-CCD V-Cache로 scheduling 안정성 ↑
- **120 Hz env step에서 둘 다 budget 안에 들어가므로 체감 0**
- 240 Hz는 input ceiling 초과로 효과 자체가 없음 → CPU 업그레이드 효과도 0
- **체감하려면 input pipeline을 먼저 넓혀야 함** (글러브 / HMD 교체)

### Q3. 9950X3D2가 의미 있는 시나리오?
**답: RL training, multi-env simulation, 동시 멀티태스킹**.

- 4096 envs RL training: ~25~30% 가속 (24h → 18~19h)
- Imitation learning dataset loading + 학습: 중간 가속
- VR teleop + OBS streaming + Discord 동시: dual-CCD V-Cache가 일관성 보장
- 단일 env teleop 자체엔 효과 미미

## 9. 핵심 결론 + 실용 권장

### 9.1 한 줄
> **현재 한계는 input pipeline ceiling (UDCAP 140 Hz)이지 CPU가 아니다. 9950X3D / 9950X3D2 업그레이드는 단일 env teleop 손가락 매칭 개선엔 ROI 거의 0**.

### 9.2 우선순위 권장

**Tier 1 (즉시, 무비용)**:
1. ✅ 9.23 EMA fix (이미 완료)
2. ⏳ 변형 B (decimation=2) → 변형 C (decimation=1) 점진 적용
3. ⏳ 7950X3D V-Cache CCD scheduling 검증 — Process Lasso로 Python을 CCD0에 묶기

**Tier 2 (CPU 업그레이드보다 우선)**:
4. ⏳ MANUS Quantum 글러브 trial (UDCAP 140 Hz 한계 해소)
5. ⏳ 또는 Xsens Metagloves 도입 (FARTS 표준, 240 Hz)
6. ⏳ Quest 3 PCVR 120Hz 시도 (HMD ceiling 90 → 120 Hz)

**Tier 3 (장기 + RL training 비중 ↑ 시)**:
7. 9950X3D2 검토 — 단, **teleop 자체 개선이 아니라 RL training 가속이 목적일 때**
8. Newton 백엔드 마이그레이션 (Ubuntu 분리 box)

### 9.3 결정 트리
```
"손가락 매칭이 더 부드러워지길 원하는가?"
   ├─ Yes → Tier 1, 2 (글러브/HMD 교체) ★ 직접 효과
   └─ No → 해당 없음

"RL training 시간이 길어 줄이고 싶은가?"
   ├─ Yes (4096 envs, 24시간 단위) → 9950X3D2 검토
   └─ No → 7950X3D 그대로

"동시 작업 (sim + 녹화 + 통신) 시 stutter가 보이는가?"
   ├─ Yes → 9950X3D2 검토
   └─ No → 7950X3D 그대로
```

### 9.4 최종 권고
> **CPU 업그레이드는 우리 specific use case (단일 env teleop)에선 후순위. 같은 예산이면 글러브/HMD 또는 별도 Linux Newton dev box 투자가 ROI 훨씬 높다.**
>
> **만약 동시에 RL training이 주 task라면** 9950X3D2가 의미 있음 — 단 그 ROI는 teleop 매칭 개선과는 무관.
