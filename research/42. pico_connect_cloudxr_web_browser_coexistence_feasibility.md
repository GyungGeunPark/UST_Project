## 0. TL;DR — 결론 한 줄

> **불가능합니다.** PICO Connect 안에서 PC 브라우저의 NVIDIA CloudXR 웹을 띄우는 시나리오는 (1) **PICO OS 5.15.4 의 단일 immersive 세션 제약**, (2) **CloudXR.js 가 PICO 브라우저 / Quest 브라우저 의 native WebXR 세션을 요구하는 별도 immersive 앱이라는 점**, (3) **PICO Connect 가 SteamVR 로 노출하는 트래커 데이터는 CloudXR Runtime 의 OpenXR 액션 시스템과 직접 호환되지 않는다는 점** 세 가지 구조적 이유로 동작하지 않습니다. PCVR 스트리밍 화면 안의 PC Chrome 으로 CloudXR.js 페이지를 띄워도 그것은 **2D 데스크톱 미러링**일 뿐, WebXR 세션을 시작할 수 없으며, 그 안에서 클릭한 "Enter VR" 도 PC OpenXR 슬롯이 이미 PICO Connect 에게 점유되어 있어 `XR_RUNTIME_FAILURE` 로 거부됩니다.
>
> **그러나 — 사용자의 본질적 목표(VR 뷰 + 헤드/컨트롤러/모션트래커 → Isaac Lab)** 는 **현재 운영 중인 `--vr_runtime pico_connect` 셋업 그대로** 달성 가능합니다 (모니터 뷰 또는 추후 XRoboToolkit 내장 비디오 스트리밍 추가). CloudXR 을 PICO Connect 위에 겹쳐서 띄울 필요가 없습니다.

| 시나리오 | 결과 | 핵심 차단 요인 |
|---|---|---|
| PICO Connect 안에 PC Chrome 띄워 CloudXR.js 페이지 표시 + WebXR 진입 | ❌ | PC Chrome 의 WebXR 은 PC OpenXR 런타임을 호출하며, 그 슬롯은 이미 PICO Connect 가 점유 |
| PICO Connect 종료 후 PICO 브라우저로 CloudXR.js 접속 (제대로 된 사용법) | ⚠️ 부분적 가능 | HMD + 컨트롤러 + (PICO 4 Ultra) 핸드트래킹 만 전달 — Motion Tracker 펑크 미지원 |
| PICO Connect (SteamVR) **단독** (현재 검증된 셋업) | ✅ | HMD + 컨트롤러 + Motion Tracker 5종이 SteamVR/OpenVR 로 모두 노출됨 (현재 `ust_hm_grip` 운영 중) |
| PICO Connect + XRoboToolkit APK 동시 | ❌ | 두 immersive 앱 동시 점유 불가 — memory.md `26번` 문서 결론 재확인 |
| PICO Connect + Isaac XR Teleop Sample Client (CloudXR 네이티브) 동시 | ❌ | 동일 — 두 immersive 앱 |

## 1. 사용자가 그리는 시나리오의 정확한 해석

질문을 분해하면:

> "**PICO Connect 로 들어가고** (헤드셋이 PCVR 스트리밍 세션 진입) **PC 화면에서 NVIDIA CloudXR 웹을 띄워 접속하면** (사용자가 PC 데스크톱 Chrome 으로 CloudXR.js 페이지를 열고) **PICO VR 에서 PICO Connect 안에서 CloudXR 이 실행 될 수 있는지** (그 결과 헤드셋 내부에서 PICO Connect 의 PCVR 화면 일부에 CloudXR 의 VR 뷰가 함께 표시되거나 별도 immersive 모드로 진입할 수 있는지), **그리고 PICO Connect 로 VR 헤드, 컨트롤러, 모션트래커 정보가 전부 CloudXR 통해서 전송되어 Isaac Lab 로봇 제어가 가능한지**"

세 개의 하위 질문으로 정리합니다:

```
Q1. (디스플레이 계층)  PICO Connect 의 PCVR 화면 안에서 PC 브라우저로 CloudXR.js 페이지가
                    렌더링되며 그 페이지가 immersive-vr 모드로 진입하는가?

Q2. (런타임 계층)     PC OpenXR 런타임 슬롯을 PICO Connect 가 차지한 상태에서 동일 PC 의
                    Chrome WebXR / 또 다른 CloudXR Runtime 인스턴스가 추가 immersive
                    세션을 만들 수 있는가?

Q3. (트래킹 계층)     PICO Connect 가 SteamVR 에 노출 중인 HMD + 2 controllers + 5 trackers
                    데이터가 CloudXR (Web) 경로로 흘러 Isaac Lab 까지 전달되는가?
```

답은 **세 질문 모두 No** 입니다. 이유를 계층별로 정리합니다.

## 2. 계층 1 — 디스플레이: PCVR 안의 "브라우저"는 그냥 2D 윈도우

### 2.1 PICO Connect 가 헤드셋에 보여주는 것의 정체

PICO Connect 의 헤드셋 클라이언트는 PCVR 게임/SteamVR 콘텐츠를 위한 **단일 fully-immersive OpenXR 앱**입니다 (PICO Store 배포). 사용자가 헤드셋 안에서 보는 것은 세 가지 중 하나:

1. **SteamVR 콘텐츠**: PC 의 SteamVR-OpenXR 게임 화면이 H.264/H.265/AV1 로 인코딩되어 스테레오로 스트림
2. **PCVR 데스크톱 미러링**: Windows 데스크톱이 가상 평면 모니터(들)에 표시 — `panoramic` 멀티 데스크톱 모드 포함
3. **PICO Connect 메뉴**: 연결 상태, 환경 설정 등 자체 UI

**핵심**: 이 셋 모두 PICO Connect 라는 단일 OpenXR 세션 안에서 렌더링되는 콘텐츠입니다. 헤드셋의 fully-immersive 슬롯은 PICO Connect 가 단독으로 점유.

### 2.2 "PC 화면에서 NVIDIA CloudXR 웹을 띄운다" 가 의미하는 것

PICO Connect 가 PCVR 모드로 진입한 상태에서 **PC 모니터(또는 PCVR 데스크톱 미러링 뷰) 위에서 Windows Chrome 을 열고 `https://localhost:8080` (CloudXR.js 페이지) 을 띄우는** 행위입니다. 이 경우 헤드셋이 보게 되는 것은:

```
[PICO 4 Ultra HMD]
└── PICO Connect Client (immersive OpenXR session)
     └── PCVR 데스크톱 미러링 뷰  ← 단순 2D 영상 스트림
         └── Windows Chrome 창
             └── CloudXR.js 페이지 (HTML)
                 └── [Enter VR] 버튼
                       │
                       │ 사용자가 클릭하면 navigator.xr.requestSession('immersive-vr')
                       ▼
                 (Chrome 이 PC 측 OpenXR 런타임에 immersive 요청)
```

여기까지의 시점에서, **CloudXR.js 페이지의 HTML 은 표시됩니다**. 사용자는 헤드셋 안에서 "NVIDIA CloudXR" 웹페이지를 볼 수 있습니다 — 텍스트, 버튼, "Enter VR" 컨트롤 등. **하지만 그것은 PCVR 미러링된 2D 콘텐츠이며, 헤드셋의 VR 시점/포즈와 무관한 평면 픽셀입니다.**

CloudXR.js 가 정상 동작하려면 **클라이언트 측 브라우저가 WebXR 세션(`immersive-vr`)을 자체적으로 만들고**, 그 세션을 통해 head/controller/hand pose 를 캡처해 WebSocket 으로 CloudXR Runtime 에 송신해야 합니다 ([NVIDIA CloudXR.js Tech Blog](https://developer.nvidia.com/blog/build-and-stream-browser-based-xr-experiences-with-nvidia-cloudxr-js/)). 즉:

- **CloudXR.js 의 정상 사용법**: PICO 헤드셋의 **PICO 브라우저** 에서 직접 `https://<server>:8080` 접속 → 브라우저 자체가 WebXR 세션 생성 → 헤드셋 OpenXR 런타임(PICO 네이티브 또는 SteamVR)에 pose 요청 → CloudXR Runtime 으로 송신.
- **시나리오의 사용법(잘못된 경로)**: PC 데스크톱 Chrome 으로 페이지 띄움 → 그 Chrome 이 PC 모니터에 렌더 → PICO Connect 가 그 PC 화면을 PCVR 로 헤드셋에 스트림. **PC 측 Chrome 이 WebXR 으로 진입하려면 PC OpenXR 런타임(이미 PICO Connect 점유)을 호출해야 함**.

### 2.3 이 단계에서 이미 시나리오가 깨지는 이유

> PICO Connect 의 PCVR 미러링 안에 표시되는 CloudXR.js 페이지는 **그 자체로는 WebXR 을 시작할 수 없습니다**. WebXR 호출은 그 페이지가 떠 있는 **호스트 브라우저** (PC Chrome) 의 것이고, PC Chrome 의 WebXR 은 PC OpenXR 런타임을 거치는데, PC OpenXR 슬롯은 이미 PICO Connect 가 차지하고 있습니다.

결과적으로 사용자가 헤드셋 안에서 본 "CloudXR 웹페이지" 는 그저 정적인 2D 콘텐츠이며, [Enter VR] 버튼을 클릭하면 `XR_ERROR_RUNTIME_FAILURE` 또는 "another XR session already active" 류의 거부가 발생합니다. CloudXR Runtime 으로 향하는 WebSocket 자체가 열리지 않습니다.

## 3. 계층 2 — 런타임: PC 측 OpenXR 슬롯 경쟁

### 3.1 PC 측 OpenXR 런타임이 한 번에 하나만 활성화되는 구조

Windows OpenXR 은 시스템 레지스트리의 `HKEY_LOCAL_MACHINE\SOFTWARE\Khronos\OpenXR\1\ActiveRuntime` 에서 **단일 active runtime 경로**를 읽어 모든 OpenXR 앱이 그 런타임을 통해 동작하도록 설계되어 있습니다. PICO Connect 가 실행되면 `PicoStreamingXR` (Virtual Desktop 의 VDXR 코드베이스를 fork 한 PICO 내장 런타임, [DCS Forum 분석](https://forum.dcs.world/topic/372463-pico-headsets-pico-connect-built-in-experimental-openxr-runtime/)) 또는 SteamVR-OpenXR 로 ActiveRuntime 이 전환됩니다.

| 모드 | PC 측 ActiveRuntime | 비고 |
|---|---|---|
| PICO Connect "Stream OpenXR directly" 모드 | `PicoStreamingXR` (`C:\Program Files\PICO Connect\openxr\` 등) | SteamVR 우회 |
| PICO Connect "SteamVR" 모드 (`prism`/`pico` add-on 활성) | `SteamVR` (`C:\Program Files (x86)\Steam\steamapps\common\SteamVR\bin\win64\vrclient.dll`) | 현재 `ust_hm_grip` 운영 모드 |
| CloudXR Runtime (Docker / Windows Service) | `CloudXR Runtime` (Docker 컨테이너 내부 또는 native 서비스가 ActiveRuntime 점유) | Isaac Teleop 공식 경로 |

**문제**: PICO Connect 가 PCVR 모드로 켜져 있는 동안, PC 의 ActiveRuntime 은 이미 `PicoStreamingXR` 또는 `SteamVR` 에 묶여 있습니다. 이 상태에서 PC 의 Chrome 이 WebXR 을 요청하면, 그 요청은 "현재 PC ActiveRuntime" 을 사용하려 시도하지만:

1. **Chrome WebXR 는 OpenXR 1.0 generic 호출을 사용하며, PicoStreamingXR/SteamVR 은 이미 PICO Connect 클라이언트와 단일 세션을 형성한 상태** 입니다. 두 번째 `xrCreateSession` 요청은 `XR_ERROR_LIMIT_REACHED` 또는 `XR_ERROR_SESSION_RUNNING` 로 거부됩니다 ([Khronos Forum: xrCreateInstance XR_ERROR_RUNTIME_FAILURE](https://community.khronos.org/t/xrcreateinstance-xr-error-runtime-failure-with-pico-4-and-steamvr-runtime/110009)).

2. **CloudXR Runtime 을 별도로 띄우려 해도**, NVIDIA 공식 문서에 따르면 "The CloudXR Runtime must be set as the active OpenXR runtime before your application creates an XrInstance" 라고 명시되어 있어 PICO Connect 와 ActiveRuntime 슬롯이 충돌합니다 ([NVIDIA CloudXR Runtime Getting Started](https://docs.nvidia.com/cloudxr-sdk/latest/usr_guide/cloudxr_runtime/getting_started.html)).

### 3.2 결과: 추가 immersive 세션 생성 불가

> PICO Connect 가 활성화된 상태에서 PC 의 어떤 다른 OpenXR/WebXR 앱도 자체 immersive 세션을 만들 수 없습니다. 따라서 PC 측 Chrome 으로 CloudXR.js 페이지를 띄우고 [Enter VR] 을 누르는 행위 자체가 런타임 레벨에서 차단됩니다.

## 4. 계층 3 — 헤드셋: PICO OS 단일 immersive 슬롯

설령 PC 측 런타임 문제가 해결된다고 가정해도, **헤드셋 측 PICO OS 5.15.4** 에서 한 단계 더 막힙니다 (memory.md `26번` 문서의 결론 재확인):

```
PICO OS 5.15.4 헤드셋
┌─────────────────────────────────────────────────────┐
│ Home / Panoramic Workspace (2D 윈도우 멀티태스킹)    │
│   - 2D PICO 앱 (브라우저, 설정, etc.)                │
│   - 절대 fully-immersive VR 앱은 띄울 수 없음        │
└─────────────────────────────────────────────────────┘
              │ 사용자가 VR 앱 실행
              ▼
┌─────────────────────────────────────────────────────┐
│ Fully-Immersive VR Session (PRIMARY)                │
│  ★ 한 번에 ONE 앱만 슬롯 점유 ★                      │
│                                                      │
│   - PICO Connect Client          OR                  │
│   - PICO Browser (WebXR immersive-vr 모드)  OR       │
│   - XRoboToolkit Unity Client    OR                  │
│   - Isaac XR Teleop Sample Client (CloudXR native)   │
│                                                      │
│   이 모드 진입 시 Panoramic Workspace 는 suspended   │
└─────────────────────────────────────────────────────┘
```

- **PICO Browser 의 WebXR `immersive-vr`** 도 fully-immersive 앱입니다. PICO Browser 가 PRIMARY 슬롯을 가져가는 순간 PICO Connect 의 PCVR 스트리밍 세션은 `XR_SESSION_STATE_STOPPING → IDLE` 로 밀립니다 — 즉 화면이 꺼지거나 PICO Home 으로 돌아갑니다.
- 반대로 PICO Connect 가 PRIMARY 슬롯을 잡고 있는 동안 PICO Browser 의 WebXR 호출은 거부됩니다 (PICO Connect 종료 후 PICO Home 으로 복귀한 뒤에야 PICO Browser 를 immersive 로 전환 가능).

### 4.1 PICO OS 6 라면 다를까?

PICO 가 2026년 3월 발표한 PICO OS 6 의 **Spatial Multitasking / Shared Space** 는 정확히 이 문제 — "다수의 3D + 2D 콘텐츠가 한 공간에 공존" — 를 해결하려고 재설계된 SDK 입니다 ([Pico OS 6 Announcement](https://www.picoxr.com/global/about/newsroom/os6), [Pico Spatial Engine New Atlas](https://newatlas.com/sponsored-content/pico-os-6-inside-look-shift-to-general-purpose-spatial-computing/)). 하지만:

1. **OS 6 는 2026년 후반 Project Swan 헤드셋 위주 출시** 예정. PICO 4 Ultra 로의 OTA 업데이트 일정 미확정.
2. **Shared Space 가 "두 PCVR 클라이언트" 까지 허용하는지 불확실**. 현재까지 공개된 데모는 1개의 3D 앱 + N개의 2D 윈도우 조합 (예: "게임 + 영상통화 윈도우 + 브라우저 윈도우") 입니다. PICO Connect 같은 PCVR 스트리밍 앱과 PICO Browser 의 WebXR 세션 같은 또 다른 PRIMARY immersive 앱을 동시에 띄우는 시나리오는 시연되지 않음.

→ **현재 (2026-05-12, PICO OS 5.15.4) 기준으로는 본 시나리오는 불가능. 추후 OS 6 수급 시 재평가 가능하지만 보장 없음.**

## 5. 계층 4 — 트래킹 데이터: SteamVR ↔ CloudXR Runtime 사이의 비호환

이 시나리오가 (가상으로라도) 성립한다고 가정해도, **트래킹 데이터가 CloudXR 경로로 흘러갈 수 없습니다**.

### 5.1 PICO Connect 가 노출하는 트래커 데이터의 행선지

현재 `ust_hm_grip --vr_runtime pico_connect` 셋업에서:

```
[PICO 4 Ultra] (PICO Connect 클라이언트, headset)
    │ HMD pose + 컨트롤러 + Motion Tracker 5종
    │ Wi-Fi/USB 스트리밍 (PICO Connect 프로토콜)
    ▼
[PC: PICO Connect Server]
    │ openvr_driver 등록 → SteamVR 에 device 등록
    │   - HMD (Prop_ControllerType=pico_hmd_or_similar)
    │   - 2x controllers (Prop_ControllerType=pico_controller)
    │   - 5x trackers (PMT_* 시리얼, AI body tracking inferred segments)
    ▼
[SteamVR] (PC 측)
    │ OpenVR Action Manifest → /actions/teleop/in/{trigger,grip,...}
    │ Pose stream → IVRSystem::GetDeviceToAbsoluteTrackingPose()
    ▼
[Isaac Lab: ust_hm_grip Device]
    │ OpenVR Python bindings 호출 → 데이터 수신
    └── Pink IK → 16D action → env.step()
```

이 경로는 **SteamVR 의 OpenVR API 를 직접 호출** 합니다. CloudXR Runtime 과 무관합니다.

### 5.2 CloudXR Runtime / CloudXR.js 가 받는 데이터

CloudXR Runtime 은 **자체적인 OpenXR 런타임** 이며, 클라이언트(PICO/Quest 브라우저 또는 native APK)로부터 다음 데이터만 WebRTC/WebSocket 으로 수신합니다 ([NVIDIA CloudXR Controller and Hand Tracking](https://docs.nvidia.com/cloudxr-sdk/latest/usr_guide/cloudxr_runtime/controller_hand_tracking.html)):

| 데이터 | CloudXR 지원 | 비고 |
|---|---|---|
| Head pose (6DoF) | ✅ | WebXR `viewer` reference space 로부터 캡처 |
| Controller pose × 2 + buttons | ✅ | WebXR Gamepad API + XRInputSource |
| Hand tracking 26 joints × 2 | ✅ | WebXR Hand Input Module |
| **Motion Tracker / Body Tracker (펑크)** | ❌ | **CloudXR Runtime 의 OpenXR 액션 시스템은 표준 controller + hand 만 지원. 추가 트래커는 별도 OpenXR 확장(`XR_EXT_full_body_tracking` 등)이 필요한데 CloudXR 미지원** |
| Eye tracking, Face tracking | 부분적 | NVIDIA 발표 이후 일부 추가됨, PICO 4 Ultra 한정 |

→ **CloudXR 경로로는 PICO Motion Tracker 의 풀바디(허리/발목/팔뚝) 데이터가 절대 전달되지 않습니다.** 이는 PICO 4 Ultra 의 AI Body Tracking 가상 트래커도 마찬가지 (AI Body Tracking 은 PICO Connect → SteamVR 의 inferred segment 으로만 노출됨).

NVIDIA Developer Forum 의 공식 답변에서도 "Additional trackers beyond HMD and 2 controllers" 는 CloudXR 의 우선순위 외 기능으로 언급됩니다 ([NVIDIA Forum: Additional trackers](https://forums.developer.nvidia.com/t/additional-trackers/199969)).

### 5.3 결과 — 트래킹 측면에서의 불가능 이유 요약

| 트래킹 채널 | PICO Connect → SteamVR 경로 (현재) | CloudXR 경로 (시나리오 가정 시) |
|---|---|---|
| HMD 6DoF | ✅ OpenVR pose | ✅ WebXR viewer pose |
| Controller × 2 (pose + buttons) | ✅ OpenVR action API | ✅ WebXR XRInputSource |
| Hand tracking | ⚠️ udcap 글러브 시 OpenVR `/input/skeleton/*` (현재 미사용) | ✅ WebXR Hand Input |
| **Motion Tracker × 5 (waist, forearm × 2, ankle × 2)** | ✅ OpenVR tracker device (`TrackedDeviceClass_GenericTracker`) | ❌ **CloudXR 미지원** |
| **AI Body Tracking 24 keypoints** | ⚠️ inferred segment 가상 트래커로 노출 (PICO Connect 설정에 의존) | ❌ **CloudXR 미지원** |

PICO 4 Ultra 의 풀바디 트래킹을 활용하려면 **반드시 SteamVR 경로 또는 XRoboToolkit 경로** 를 사용해야 하며, CloudXR 은 표준 HMD+컨트롤러+핸드 셋업 외의 데이터는 처리하지 않습니다.

## 6. CloudXR.js 의 정상 사용 시나리오 (참고용)

오해를 방지하기 위해 CloudXR.js 가 **PICO 4 Ultra 에서 정상 동작하는 경로** 를 정리합니다 (Isaac Lab 공식 문서 [Setting up CloudXR Teleoperation](https://isaac-sim.github.io/IsaacLab/main/source/how-to/cloudxr_teleoperation.html) 기준):

```
[PICO 4 Ultra, PICO OS 15.4.4U+]
└── PICO Browser 직접 실행
     └── https://<server>:8080 (CloudXR.js HTTPS 페이지) 로 이동
         └── 페이지 내 [Enter VR] 버튼 클릭
              └── navigator.xr.requestSession('immersive-vr', ...)
                  └── PICO Browser 가 PRIMARY immersive 슬롯 점유
                       ┃
                       ┃ WebRTC + WebSocket 연결
                       ▼
[PC: CloudXR Runtime (Windows native or Docker)]
    ├── 헤드/컨트롤러/핸드 pose 수신
    ├── Isaac Lab 에 OpenXR action 전달
    ├── Isaac Sim 렌더링 결과를 AV1/HEVC/H.264 인코딩
    └── PICO Browser 에 스트림 (60-90 FPS 스테레오)
```

이 시나리오에서 **PICO Connect 는 실행되지 않습니다** (또는 종료된 상태). PICO Browser 가 단독으로 immersive 슬롯을 차지합니다.

| 비교 항목 | PICO Connect → SteamVR 경로 (현재) | CloudXR.js (PICO Browser) 경로 |
|---|---|---|
| 헤드셋 PRIMARY immersive 앱 | PICO Connect Client | PICO Browser (WebXR) |
| PC OpenXR ActiveRuntime | `SteamVR` (또는 `PicoStreamingXR`) | `CloudXR Runtime` |
| HMD/컨트롤러/핸드 데이터 | OpenVR action API | WebRTC → CloudXR Runtime → OpenXR action |
| Motion Tracker 5종 | ✅ SteamVR generic tracker | ❌ 미지원 |
| Isaac Lab 연결 | `ust_hm_grip` device → OpenVR | `IsaacTeleop` retargeter graph |
| 셋업 복잡도 | 중 (SteamVR + PICO Connect 설치) | 고 (CloudXR Early Access 신청 + Docker + HTTPS proxy) |
| 현재 검증 상태 | ✅ 9.37+ 운영 중 | 🟡 Early Access (PICO 4 Ultra OS 15.4.4U+ 필요) |

## 7. "그럼 어떻게 해야 하는가" — 실제로 가능한 경로

memory.md `26번` 문서에서 정리한 4가지 경로를 재인용하고, **현재 9.37+ 의 PICO Connect 셋업** 을 기준점으로 합쳐 권장순으로 다시 제시합니다.

### 경로 A — 현재 운영 중 ⭐⭐ (가장 안전)

**PICO Connect (SteamVR) → `ust_hm_grip` device → Isaac Lab + 외부 모니터 뷰**

```
[PICO 4 Ultra]
└── PICO Connect Client (PCVR immersive)
     └── 헤드셋 화면 = PCVR 데스크톱 미러링 (또는 SteamVR 게임 화면)
          + 외부 모니터에서 Isaac Lab Viewport 보면서 작업

[PC]
└── PICO Connect Server
     └── SteamVR 에 HMD + 2 controllers + 5 trackers 노출
          └── Isaac Lab ust_hm_grip device (OpenVR API)
               └── Pink IK 16D action → env.step()
```

- **장점**: 현재 9.37+ 에서 검증 완료 (memory.md §10.45, §10.47~§10.49). Motion Tracker 5종 전부 활용 가능. Pink IK 와 컨트롤러 그리퍼가 정상 작동.
- **단점**: 헤드셋에는 Isaac Sim 뷰포트가 직접 표시되지 않음 (PCVR 미러링 모드로 외부 모니터의 viewport 를 헤드셋 화면에 띄울 수는 있지만 몰입감 낮음). 본격 VR 몰입 텔레오퍼레이션은 어렵습니다.
- **현재 상태**: `--vr_runtime pico_connect` flag 로 즉시 실행 가능 (`ust_hm_grip/scripts/run_teleop.py`).

### 경로 B — XRoboToolkit 내장 비디오 스트리밍 ⭐

**XRoboToolkit APK (PICO 단독) + Isaac Sim 카메라 H.264 → UDP → 헤드셋**

memory.md `26번` 문서의 "경로 1". 현재 미구현 — 아직 어댑터 레이어가 작성되지 않았습니다.

- **장점**: VR 몰입 + 풀바디 트래킹 모두 확보. PICO Connect 불필요.
- **단점**: Isaac Sim camera 출력을 XRT 프로토콜에 맞춰 NVENC 인코딩하는 브리지를 추가로 구현해야 함 (2-3일 작업 예상).

### 경로 C — CloudXR.js (PICO Browser) 단독 ⚠️ 제한적

**PICO Connect 종료 → PICO Browser 로 CloudXR.js 접속 → Isaac Lab IsaacTeleop**

- **장점**: VR 몰입 뷰 + HMD + 컨트롤러 + 핸드트래킹 확보. NVIDIA 공식 경로.
- **단점**: **Motion Tracker 5종 미지원**. PICO 4 Ultra 풀바디 트래킹 기능을 활용하지 못해 본 프로젝트(GR1T2 + 그리퍼 / G1 휴머노이드) 의 트래킹 요구를 만족시키지 못합니다.
- **현재 상태**: CloudXR Early Access 신청 필요. PICO OS 15.4.4U+ 필요 (현재 5.15.4 로 가능). Isaac Lab IsaacTeleop framework 마이그레이션 필요.

### 경로 D — PICO Connect + CloudXR 동시 시도 (시나리오) ❌ 불가능

본 문서의 5절까지 분석한 시나리오. 추진하지 말 것을 권장합니다.

## 9. 핵심 차단 사실 다섯 가지 (정리)

1. **PICO OS 5.15.4 는 fully-immersive OpenXR 앱을 한 번에 1개만 허용**. PICO Connect 가 슬롯 점유 시 PICO Browser 의 WebXR `immersive-vr` 진입 불가 (memory.md `26번` 문서, [PICO Developer Multitasking 문서](https://developer.picoxr.com/document/web/introduce-multitasking/)).

2. **PC 측 OpenXR ActiveRuntime 도 단일**. PICO Connect 가 `PicoStreamingXR` 또는 `SteamVR` 로 슬롯 점유 중일 때 PC Chrome 의 WebXR / 별도 CloudXR Runtime 의 `xrCreateSession` 는 `XR_ERROR_LIMIT_REACHED` 또는 `XR_ERROR_RUNTIME_FAILURE` 로 거부 ([NVIDIA CloudXR Getting Started](https://docs.nvidia.com/cloudxr-sdk/latest/usr_guide/cloudxr_runtime/getting_started.html), [Khronos Forum 토픽](https://community.khronos.org/t/xrcreateinstance-xr-error-runtime-failure-with-pico-4-and-steamvr-runtime/110009)).

3. **PCVR 미러링 안에 표시된 브라우저는 그저 2D 윈도우**. PC Chrome 으로 띄운 CloudXR.js 페이지는 헤드셋에 픽셀로 나타나지만 WebXR 세션 자체를 시작할 수 없음. 클라이언트 측 immersive 진입은 호스트 브라우저(이 경우 PC Chrome)의 책임이며 PC OpenXR 슬롯이 막혀 있음.

4. **CloudXR Runtime 은 Motion Tracker (펑크) 데이터를 받지 않음**. 표준 OpenXR action 시스템의 `/user/hand/{left,right}` 인터랙션 프로필만 처리하며, PICO Motion Tracker 의 `TrackedDeviceClass_GenericTracker` 또는 PICO AI Body Tracking 의 inferred body segment 는 CloudXR 전송 페이로드에 포함되지 않음 ([NVIDIA Controller and Hand Tracking 문서](https://docs.nvidia.com/cloudxr-sdk/latest/usr_guide/cloudxr_runtime/controller_hand_tracking.html), [NVIDIA Forum: Additional trackers](https://forums.developer.nvidia.com/t/additional-trackers/199969)).

5. **CloudXR.js + Isaac Lab 의 공식 경로는 PICO Browser 에서 직접 접속하는 형태**. PICO Connect 와는 mutually exclusive ([Isaac Lab CloudXR Teleoperation 문서](https://isaac-sim.github.io/IsaacLab/main/source/how-to/cloudxr_teleoperation.html)).

## 10. 만약 그래도 시험해보고 싶다면 — 빠른 실측 방법

머리로만 결론을 내리기보다 실제로 부딪혀 보고 싶다면, 다음 순서로 5분이면 시나리오 D 의 실패를 재현할 수 있습니다:

```powershell
# 1) PICO Connect 가 정상 작동 중 (PICO 4 Ultra 가 PCVR 모드로 연결됨)
Get-Process | Where-Object { $_.Name -match "PICO|Streaming|vrserver" }

# 2) PC OpenXR ActiveRuntime 확인
Get-ItemProperty -Path "HKLM:\SOFTWARE\Khronos\OpenXR\1" -Name ActiveRuntime
# → SteamVR 또는 PicoStreamingXR 가 보이면 정상

# 3) PC Chrome 으로 WebXR 진단 페이지 띄우기
Start-Process "chrome.exe" "https://immersive-web.github.io/webxr-samples/immersive-vr-session.html"
# 또는 NVIDIA CloudXR.js 데모 URL

# 4) 페이지의 "Enter VR" 클릭 시 콘솔 에러 확인
# 예상: "Failed to start immersive session: another XR session is already running"
#       또는 "WebXR not supported in this context"

# 5) PICO Connect 종료 후 같은 시도 → PICO Browser 에서 직접 접속하면 진입 성공
```

이 실험은 PC 측에서만으로도 시나리오 D 의 차단이 OpenXR 런타임 슬롯 경쟁에 의한 것임을 확인할 수 있습니다.

## 11. 결론 및 권장

| 질문 | 답 |
|---|---|
| PICO Connect 안에서 PC 브라우저로 CloudXR 웹을 띄워 CloudXR 이 실행될 수 있는가? | **❌ 불가능**. PCVR 미러링 안의 페이지는 2D 영상이며 WebXR 세션을 시작할 수 없음. 시작하려 해도 PC 측 OpenXR 슬롯이 이미 PICO Connect 가 점유. |
| 이 경로로 헤드/컨트롤러/모션트래커 데이터가 Isaac Lab 까지 전달되어 로봇 제어가 가능한가? | **❌ 불가능**. CloudXR Runtime 은 Motion Tracker 펑크 데이터를 받지 못함. 풀바디 트래킹은 SteamVR/OpenVR 경로 또는 XRoboToolkit 경로에서만 가능. |
| 현재 PICO Connect → SteamVR → ust_hm_grip 셋업 (9.37+) 은 어떻게 되는가? | **✅ 유지 권장**. 이미 검증된 경로이며 Motion Tracker 5종 전부 사용 가능. CloudXR 을 추가로 얹을 필요 없음. |
| PICO 4 Ultra 에서 VR 몰입 + 풀바디 트래킹 두 가지 모두 원하면? | **경로 B (XRoboToolkit 내장 비디오 스트리밍)** 가 정답. 별도 어댑터 구현 필요. CloudXR 은 이 시나리오의 답이 아님. |
| PICO OS 6 가 풀리면 시나리오 D 가 풀릴까? | 불확실. Spatial Multitasking 이 "두 immersive 앱 공존" 을 어디까지 허용하는지 미공개. 현재로서는 기대하지 말 것을 권장. |

### 작업 권장 순서

1. **즉시**: 현재 `--vr_runtime pico_connect` 셋업 유지. CloudXR 위에 얹는 작업은 시작하지 말 것.
2. **향후 (몰입감 개선 필요 시)**: XRoboToolkit 내장 비디오 스트리밍 어댑터 (경로 B) 의 구현 검토 (2-3일).
3. **참고**: NVIDIA 공식 IsaacTeleop framework 의 retargeter graph 구조는 현재 `gr1t2_gripper_retargeter.py` 와 호환 가능한 패턴이므로, **CloudXR 자체는 도입하지 않고 retargeter API 만 부분 참조** 하는 옵션도 검토 가치 있음.
