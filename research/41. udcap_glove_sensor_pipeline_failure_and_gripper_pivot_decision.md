# 41. UDCAP 글러브 sensor → finger pose pipeline 단절 — 종합 진단 + Gripper Pivot 결정

> 작성: 2026-05-06
> 사용자 보고: research/40 의 9.29 fix (oculus_touch binding 추가) + UDCAP UI Controller_Priority HIGH→LOW + 캘리브레이션 재수행 + 앱 재시작 모두 적용했지만 **모든 액션 여전히 0**.  결정적 단서: **UDCAP UI 의 hand capture preview (상단 글러브 사진) 에서도 손가락 굽힘이 시각화 안 됨**.
> 컨텍스트: research/27 ~ 40 의 9.13 ~ 9.29 fix 시리즈가 모두 SteamVR/Isaac Lab layer 의 binding/path 문제를 다뤘으나, 본 분석은 **UDCAP 자체의 sensor → finger pose 변환 pipeline 이 깨진 상태** 라는 결론에 도달.

---

## 0. 한 줄 요약 (TL;DR)

> **결론**: 모든 SW layer (SteamVR binding, action manifest, retargeter, VMC fallback) 가 정상 동작하는데도 finger 데이터가 0 인 이유는 **UDCAP 가 sensor RF data 는 받지만 finger pose 변환에 실패** 하는 상태이기 때문이다. 결정적 증거: **UDCAP UI 자체의 hand capture preview (제일 위 글러브 사진) 에서 손가락이 움직이지 않는다**. UDCAP UI 가 자기 데이터를 자기 UI 에 표시 못 하는 상태이므로 **하류 layer (VMC OSC, Skeletal Input 2.0, finger curl actions) 가 모두 0 인 게 일관된다**. RF/배터리/USB dongle 은 정상 (UDCAP UI 는 "Working / FPS 90/143 / 배터리 80/100% / RSSI -55 ~ -60 dBm" 표시).
>
> **이 문제는 우리 codebase 변경으로 해결 불가** — UDCAP 글러브 자체 또는 UDCAP-Driver v0.1.8.2 자체 버그. 가능 원인 (우선순위):
> 1. 글러브 펌웨어 ↔ Driver v0.1.8.2 사이 버전 불일치 (Driver 최신 / 글러브 펌웨어 구버전)
> 2. v0.1.8.2 Driver 자체 버그 (이전 v0.1.3.x → 0.1.8.x 사이 큰 점프 — finger pose pipeline 깨졌을 가능성)
> 3. 글러브 finger flex sensor 12개 중 일부 단선/노화 (양손 모두 발생이라 가능성 낮지만)
> 4. Calibration data 손상 (재캘 후에도 hand preview 가 안 따라오면 sensor raw 가 deadline)
> 5. Windows 측 USB driver 또는 RF dongle 의 finger packet drop (이건 RF "Working" 표시와 모순이라 가능성 낮음)
>
> **사용자 결정**: 손가락 제어 디버깅 일단 보류 → **`ust_260504_win` 의 2-finger gripper 형태로 전환**. PICO Touch 컨트롤러의 grip pull 을 직접 사용 — 글러브 finger sensor 불필요. 이미 research/36 에서 구현 완료. 추후 손가락 제어는 별도 트랙으로 재개.
>
> **9.29 fix 의 의의 (네거티브 결과지만 가치 있음)**: research/40 의 oculus_touch binding 추가는 vrserver.txt 의 auto-remap SKIP 메시지를 제거하는 데는 성공했지만, **상류 (UDCAP) 가 데이터를 emit 하지 않는 상태에선 binding 을 어떻게 정리해도 0** 이라는 결정적 evidence 를 확보. 디버깅 elimination 측면에서 가치 있음 — 미래에 글러브 sensor pipeline 이 살아나면 9.29 fix 는 그대로 유효.
>
> **다음 단계**:
> - 즉시: `ust_260504_win` (gripper) 로 전환해 manipulation 테스트 진행
> - 단기: 글러브 펌웨어 업데이트 가능성 확인 (UDCAP UI 의 firmware section)
> - 중기: UDCAP-Driver 다운그레이드 (v0.1.8.2 → v0.1.7.x) 시도
> - 장기: UDexREAL support contact 또는 글러브 교체 검토

### 1.2 본 로그의 결정적 패턴 (4가지)

#### Pattern A: 4개 controller 등록 + 모든 액션 0 (변화 없음)

```
idx=11 cls=Controller serial='LHR-E227UD40' controller_type='knuckles' role=Left
idx=12 cls=Controller serial='LHR-E227UD41' controller_type='knuckles' role=Right
idx=13 cls=Controller serial='1PASH5D1P17365_Controller_Left'  controller_type='oculus_touch' role=0
idx=14 cls=Controller serial='1PASH5D1P17365_Controller_Right' controller_type='oculus_touch' role=0

left:  trigger=0.000 grip=0.000 finger_curls=[모두 0]
right: trigger=0.000 grip=0.000 finger_curls=[모두 0]
ctrls.left  (legacy): pose=(-0.095,+0.785,-0.620) trigger=0.00 grip=0.00 menu=False
ctrls.right (legacy): pose=(+0.101,+0.789,-0.605) trigger=0.00 grip=0.00 menu=False
```

→ 9.29 fix 후 oculus_touch 측 trigger/grip 도 0. **사용자가 PICO Touch 컨트롤러를 잡고 squeeze 했음에도** 0 이라는 게 핵심 — 영상 (research/38 분석) 시점과 다른 새로운 패턴.

#### Pattern B: Skeletal probe `bActive=False` (변화 없음)

```
left: action_handle=0x1000cac800000413
    getSkeletalActionData: bActive=False activeOrigin=0x0
    getSkeletalTrackingLevel FAILED: ValueError ...b'\x01\x00\x00\x00'  (= raw uint32 = 1 = Partial)
    getBoneCount=31
right: ... 동일
```

→ Tracking level 정의는 SteamVR 가 알지만 (1=Partial 응답), **active source 가 없음** (bActive=False). 9.29 fix 의 oculus_touch binding 추가가 skeleton 채널엔 영향 없음 (oculus_touch profile 에 skeleton path 없음).

#### Pattern C: VMC packet=0 (변화 없음)

```
[GR1T2FourierUDCAPDevice][advance #100] VMC port=39539 bones_received=0 (waiting for first packet)
[GR1T2FourierUDCAPDevice][advance #200] VMC port=39539 bones_received=0
...
[GR1T2FourierUDCAPDevice][advance #700] VMC port=39539 bones_received=0
```

→ 35초 / 700 frames 동안 VMC packet 0개. UDCAP UI 의 `VMC_State=True` (config XML 확인) 인데도 broadcast 안 함.

#### Pattern D: stuck-finger warning + finger-scale advice (변화 없음)

```
[GR1T2Retarget][stuck-finger-warn] After 200 frames the following fingers have variation < 0.05 rad
  Stuck: ['l_idx','l_mid','l_pky','l_rng','l_thb','r_idx','r_mid','r_pky','r_rng','r_thb']

[GR1T2Retarget][finger-scale-advice] After ~30 s of teleop:
  L_idx max curl reached = 0.00 rad (0% of joint limit)
  R_idx max curl reached = 0.00 rad (0% of joint limit)
```

→ retargeter 가 자체 진단으로도 "finger 데이터 도달 안 함" 확정. `--vmc_subtract_rest false` 등 우리 측 토글로는 해결 불가 (변환할 raw data 가 없음).

### 1.3 9.29 fix 가 실제로 적용됐는지 검증

vrserver.txt 새 트레이스를 직접 확인 못 했지만, 본 로그의 패턴이 9.29 적용 후 기대했던 변화 (oculus_touch 측 trigger/grip 활성) 가 나타나지 않은 이유는:

**가설 A** (가능성 높음): 9.29 fix 자체는 적용됐지만, 사용자가 SteamVR Manage Controller Bindings 에서 **"Save Personal Binding" 누르지 않음** (research/36 gotcha #24).

**가설 B**: PICO Touch 컨트롤러를 사용자가 손에 안 들고 있어서 oculus_touch axis 가 0 (idle).

**가설 C**: 사용자가 진짜로 PICO Touch 를 잡고 있는데도 axis 가 0 — VD streamer 의 controller forwarding 이 비활성 (이전 영상에서는 정상이었으니 가능성 낮음).

→ **이 검증은 Phase 2 로 미룸** — 사용자가 gripper subproject 로 pivot 하기로 결정했으므로 9.29 fix 의 oculus_touch 측 효과는 ust_260504_win 에서 직접 검증 가능 (그 앱은 oculus_touch binding 이 default 채택).

## 2. 결정적 증거 — UDCAP UI Hand Capture Preview 미동작

### 2.1 사용자 스크린샷 분석 (UDCAP UI v0.1.8.2)

| UI 요소 | 표시 값 | 해석 |
|---|---|---|
| 상단 hand capture preview | 양 글러브 사진 (왼쪽 / 오른쪽) | **사용자가 손가락 굽혔을 때 이 preview 의 손가락 모델이 움직이지 않음** ⭐ |
| 좌측 mini-icon (upper) | 빨간 점들이 분포된 손 모양 | "open hand" 캘리브레이션 reference |
| 좌측 mini-icon (lower) | 파란 점들 + Thumb 강조 | "fist" 또는 "per-finger" 캘리브레이션 reference |
| Status | "Working / Gloves are working" | RF 통신 + 페어링은 OK |
| Calibration(F1) 버튼 | 활성 | 언제든 재캘 가능 |
| L glove | 80% 배터리 / FPS 90 / RSSI -60 dBm (orange) | RF 양호 |
| R glove | 100% 배터리 / FPS 143 / RSSI -55 dBm (yellow) | RF 양호 |
| 우하단 VR 아이콘 | (파란색) | SteamVR 연동 활성 |

### 2.2 이 패턴이 시사하는 layer 단절

UDCAP 의 일반적인 데이터 흐름:
```
글러브 finger flex sensor (12개 sensor)
     ↓ 2.4G RF (FPS 90~143)
USB dongle (PC 측)
     ↓ USB serial
UdcapDriver.exe (process: PID 41828)
     ↓ Internal pipeline:
        (a) raw sensor → calibrated angle 변환
        (b) calibrated angle → 21-joint hand pose
        (c) hand pose → 시각화 / VMC OSC / SteamVR driver
     ↓
UI Hand Capture Preview ← (c) 의 첫 consumer
SteamVR knuckles virtual controller ← (c) 의 두 번째 consumer
VMC UDP 39539 broadcast ← (c) 의 세 번째 consumer
```

**모든 (c) consumer 가 0/idle 이라는 사실은 (a) 또는 (b) 단계에서 단절** 임을 의미. RF (FPS) + 배터리 + USB dongle 은 살아있으므로:
- (a) raw sensor → angle 변환 단계 실패 (calibration data corrupt, 또는 sensor raw 자체가 0)
- (b) angle → hand pose 변환 단계 실패 (Driver 내부 hand model 버그)

### 2.3 UDCAP UI hand capture 가 작동하는지 직접 테스트

사용자가 UDCAP UI 를 보면서 손가락 굽힘 → preview 의 손가락 모델 따라오는지 확인.

**시나리오 1**: Preview 가 따라옴 → 사용자 보고 시점과 다른 상태. 우리 앱 layer 에 문제 (binding / sampler) → 9.29 fix 의 효과를 추가 검증.

**시나리오 2** (현재 사용자 케이스): Preview 가 안 따라옴 → **UDCAP 내부 pipeline 깨짐**. 우리 layer 어떤 변경도 무효.

→ 사용자 보고는 시나리오 2 — 즉 **UDCAP 측 단독 문제**.

## 3. 가능 원인 5가지 + 진단 가이드

### 3.1 원인 #1: 글러브 펌웨어 ↔ Driver v0.1.8.2 버전 불일치 (가능성 ★★★★)

#### 가설
- Driver 가 v0.1.8.2 (2026-04-10 release) 로 매우 최신
- 글러브 펌웨어가 구버전이면 sensor packet 형식 달라 Driver 가 raw value 해석 실패
- "Working" 표시는 RF heartbeat 만 보고 — packet payload 형식까지는 검증 안 함

#### 진단
1. UDCAP UI 메뉴 (좌상단 햄버거 또는 ≡) → "About" 또는 "Firmware"
2. 글러브 펌웨어 버전 표시 확인
3. UDCAP UI 또는 [공식 docs](https://udcap-vr-gloves-document.gitbook.io/udcap/software-setup/software-installation-and-update-log) 에서 권장 펌웨어 버전과 비교

#### 조치
- 펌웨어 업데이트 옵션이 UI 에 있으면 양 글러브 모두 최신 펌웨어로
- 일치 후 재시도

### 3.2 원인 #2: UDCAP-Driver v0.1.8.2 자체 버그 (가능성 ★★★)

#### 가설
- v0.1.3.3 (2025-04) → v0.1.8.2 (2026-04) 1년간 5 버전 점프
- v0.1.8.x 시리즈에서 finger pose pipeline 의 일부가 regress 했을 가능성
- 사용자 시스템에서 hand capture preview 가 안 보이는 게 정확히 그 regression

#### 진단
- UDCAP-Driver release page ([github.com/Udexreal/Udcap-Driver/releases](https://github.com/Udexreal/Udcap-Driver/releases)) 의 changelog 확인
- v0.1.7.x 또는 v0.1.6.x 같은 안정 버전이 따로 있는지

#### 조치
- v0.1.8.2 → v0.1.7.x 다운그레이드 시도
- 다운그레이드 후 hand capture preview 가 살아나는지 확인
- 살아나면 v0.1.8.2 가 원인 — UDexREAL support 에 issue report

### 3.3 원인 #3: 글러브 sensor 물리적 손상 (가능성 ★★)

#### 가설
- 12 sensors × 2 글러브 = 24 sensors 중 **finger flex sensor 자체가 단선/노화**
- 사용 빈도 / 세탁 / 보관 환경 영향
- 양손 모두 같은 시기에 발생할 가능성 (같은 환경) — 낮지만 가능

#### 진단
- UDCAP UI 의 "per-finger heatmap" 또는 "raw sensor view" (있으면)
- 각 손가락 굽힐 때 raw sensor 값 변화 보임 → physical sensor OK
- 굽혀도 raw 0 → physical sensor 단선

#### 조치
- 글러브 보증/AS 문의
- 또는 다른 글러브로 교체 (다른 글러브 있으면)

### 3.4 원인 #4: Calibration data corruption (가능성 ★★)

#### 가설
- `UdcapDriver.dll.config` 의 모든 finger Coefficient/Offset/Min/Max 값이 default (예: Coefficient=1, Offset=0)
- 캘리브레이션 했음에도 raw → angle 변환식이 항상 0 출력하는 case
- 재캘 시도 후에도 같은 패턴이면 calibration save 단계 실패

#### 진단
```powershell
# UDCAP UI 종료 + config 백업 + 모든 calibration coefficient 확인
$cfg = "C:\Program Files\UdcapDriver\UdcapDriver.dll.config"
Copy-Item $cfg "${cfg}.bak.before_recal" -Force
# Coefficient 값들이 모두 1.0 / Offset 0 이면 캘리브레이션 적용 안 된 상태
Select-String -Path $cfg -Pattern "Coefficient|Offset" | Select-Object -First 30
```

#### 조치
- UDCAP UI Settings → "Reset Calibration" (있으면)
- UDCAP 완전 재설치 + 캘리브레이션
- 재설치 시 config file 삭제 후 fresh install

### 3.5 원인 #5: Windows USB / RF dongle layer (가능성 ★)

#### 가설
- USB dongle 의 driver 가 finger packet 만 drop
- RSSI 가 -55 ~ -60 dBm 이긴 한데 약간 낮음 (좋은 값은 -40 ~ -50 dBm)

#### 진단
- USB dongle 을 다른 USB 포트로 (USB 3.0 vs USB 2.0)
- 다른 PC 에서 같은 글러브 / dongle / Driver 조합 시도

#### 조치
- USB 2.0 포트 사용 (RF dongle 은 보통 USB 2.0 충분)
- 다른 PC 에서 재테스트

## 4. 9.29 fix (research/40) 의 사후 평가

### 4.1 적용된 변경의 의의

9.29 fix 는 **SteamVR 측 binding plumbing 정리**에 집중:
- `bindings_oculus_touch.json` 신규 — auto-remap SKIP 회피
- `actions.json default_bindings` 에 oculus_touch entry 추가
- `bindings_index.json` 의 grip mode `force_sensor → trigger`

### 4.2 효과 측정

| 기대 효과 | 본 로그에서의 검증 | 결론 |
|---|---|---|
| vrserver.txt 의 auto-remap SKIP 사라짐 | 본 로그에 vrserver.txt 인용 없음 — 직접 확인 못 함 | 미확인 (gripper subproject 에서 검증 가능) |
| oculus_touch 측 trigger/grip 활성화 | 본 로그에 trigger/grip 0 — 사용자가 PICO Touch 잡았는지 불명 | 미확인 |
| skeleton + finger curl 활성화 | 모두 0 / bActive=False | **변화 없음** ❌ |
| VMC packet 도달 | 0 packets | **변화 없음** ❌ |

### 4.3 결론

9.29 fix 는 **SteamVR 측 binding 의 잘못된 동작은 정리** 했지만, **상류 (UDCAP) 가 finger data emit 안 하는 상태**에선 어떤 binding 변경도 0 → 0 이라는 자명한 결과.

→ 9.29 fix 의 진짜 가치는 **나중에 글러브 sensor pipeline 이 살아나면 그때부터 즉시 동작**하는 점. 미래 검증 차원에서 그대로 유지.

또한 oculus_touch 측 trigger/grip 동작 검증은 **`ust_260504_win` (gripper) 에서 자연스럽게 진행** 됨 — 그 앱이 oculus_touch 의 grip pull 만 사용.

## 5. Pivot 결정 — `ust_260504_win` (Gripper) 로 전환

### 5.1 Pivot 이유 (요약)

| 항목 | UDCAP 글러브 (현재) | PICO Touch + Gripper (Pivot 후) |
|---|---|---|
| 손가락 데이터 source | UDCAP sensor (현재 ❌ 미동작) | 컨트롤러 grip pull (이미 영상에서 ✓ 검증) |
| 로봇 손 자유도 | 22 finger joints | 2 gripper joints (open/close) |
| Action 차원 | 36D (14 EEF + 22 hand) | 16D (14 EEF + 2 gripper) |
| Pink IK 부담 | 22 finger 추가 = ~5 ms QP | 2 finger = ~1 ms (덜한 영향) |
| Manipulation 정확도 | Fine (글러브 동작 시) | Coarse but functional |
| Setup 시간 | 디버깅 미해결 | research/36 에서 이미 구현 완료 |

### 5.2 ust_260504_win 의 즉시 사용 가능성

이미 `ust_260504_win` 디렉토리는 모든 모듈 + 테스트 + 진단 스크립트 완비:
- `isaac_file/build_gripper_usd.py` — GR1T2 USD 에서 22-finger Fourier hand 떼내고 2-finger gripper 부착
- `teleop/gr1t2_gripper_device.py` + `gr1t2_gripper_retargeter.py` — PICO Touch grip pull → gripper open/close
- `scripts/run_teleop.py` — 메인 entry
- `scripts/diagnose_gripper.py` + `diagnose_controller_raw.py` — 단계별 진단

#### Step 2. SteamVR / VR streamer 준비

- udcap = ON (글러브는 안 쓰지만 driver 가 떠있어도 무방)

CLI flag 핵심:

#### Step 4. SteamVR Manage Controller Bindings 활성화 (research/36 gotcha #24)

VR 안에서:
1. SteamVR Dashboard → Settings → Controllers → Manage Controller Bindings
2. **App: "UST Teleop GR1T2 Gripper" 선택**

5. SteamVR 재시작 권장

#### Step 5. 검증

PICO Touch 의 grip 버튼 (검지 손가락 안쪽 큰 버튼) 누르면:
- 우리 앱 콘솔 로그: `[GR1T2Gripper #N] L_cmd=+1 max_grip L=0.85 R=0.00`
- Isaac Sim viewport: 왼쪽 gripper 닫힘
- release 시: gripper 열림

문제 시 `diagnose_gripper.py` + `diagnose_controller_raw.py` (research/36 §6) 단계별 진단.

### 6.2 root cause 한 줄 요약

**UDCAP 글러브 또는 v0.1.8.2 driver 의 sensor → finger pose 변환 단계에서 데이터가 사라진다.  RF/배터리/USB 는 정상이지만 finger flex 정보가 driver 의 hand pose computation 후 모든 consumer (UI / VMC / SteamVR knuckles) 에 도달하지 않는다.**

### 6.3 사용자가 외부에 문의 시 보낼 issue 요약

> UDCAP-Driver v0.1.8.2, glove pair (L: 80% battery FPS 90 RSSI -60dBm / R: 100% battery FPS 143 RSSI -55dBm) — UDCAP UI 가 "Working / Gloves are working" 표시함에도 다음 모든 channel 에서 finger 데이터 0:
>
> - UDCAP UI 자체 hand capture preview (제일 위 글러브 사진) 에서 손가락 모델 미동작
> - VMC OSC port 39539 broadcast: 0 packets / 30 seconds
> - SteamVR Skeletal Input 2.0 (`getSkeletalActionData` bActive=False, getBoneCount=31, tracking_level=Partial)
> - SteamVR Index profile finger curl actions (`/user/hand/{l,r}/input/finger/{thumb,index,middle,ring,pinky}`): 모두 0
>
> 시도한 조치:
> - Calibration 재수행 (Open / Fist / Per-finger sequence) — 변화 없음
> - Controller_Priority HIGH → LOW — 변화 없음
> - SteamVR + UdcapDriver + 앱 재시작 — 변화 없음
> - SteamVR Manage Add-Ons : Virtual Desktop Streamer (Quest) ON, prism OFF, udcap ON
>
> 사용자 환경: PICO 4 Ultra + Virtual Desktop streaming + Windows 11 / Conda env / Python 3.11
>
> 의심: UDCAP-Driver v0.1.8.2 (2026-04-10 release) 의 finger pose pipeline regression, 또는 글러브 펌웨어 ↔ Driver 버전 불일치.
