## TL;DR (한 줄 답)

**Yes — `get_body_joints_pose()` 24-joint SMPL stream 이 PICO Motion Tracker 앱의 AI 융합 결과 그대로**. 단, 손목 fine rotation 은 SMPL 자체에 잘 안 잡히므로 PICO 캘리브 앱조차 **controller pose 를 overlay** 한다. NVIDIA SONIC/GR00T 도 동일 패턴 사용.

→ 우리 retargeter 도 **POS = body wrist tracker (SMPL idx 20/21), QUAT = controller** 로 split. 이게 part 15 의 디폴트.

## 1. SDK 자체 진단

`XRoboToolkit-PC-Service-Pybind/bindings/py_bindings.cpp` 가 노출하는 body-관련 API:

| API | 의미 |
|---|---|
| `is_body_data_available()` | Unity APK 가 "Full body tracking" 모드일 때 True |
| `get_body_joints_pose()` | 24×7 array. SMPL 24-joint pose (x,y,z,qx,qy,qz,qw). **AI 융합된 결과**. |
| `get_body_joints_velocity()` | 24×6 array. 각 joint 의 linear+angular velocity |
| `get_body_joints_acceleration()` | 24×6 array |
| `get_body_joints_timestamp()` | 각 joint 별 IMU timestamp |
| `num_motion_data_available()` | Unity APK 가 "Object" 모드일 때 raw PMT 개수 (max 3) |
| `get_motion_tracker_pose()` | 최대 3 PMT raw pose (Object 모드용) |
| `get_motion_tracker_serial_numbers()` | 각 PMT 의 SN |

JSON 채널 구조 (py_bindings.cpp 의 callback 파싱):
- `value.Body.joints[]` → 24-joint SMPL (Full body mode)
- `value.Motion.joints[]` → max 3 raw PMT (Object mode)
- `value.Controller.left / .right.pose` → controller 6DoF
- `value.Head.pose` → HMD 6DoF
- `value.Hand.leftHand / .rightHand` → 26-joint hand tracking

## 2. PICO 측 데이터 흐름

PICO 4 Ultra + PICO Motion Tracker 환경에서:

```
PMT × 5 (waist + 2 forearm + 2 ankle)
HMD pose (IMU + camera SLAM)
Controller pose × 2
        ↓
[PICO Motion Tracker app — PUI ≥ 5.11.0]
  AI fusion (multi-modal tracking algorithm)
  → 24-joint SMPL skeleton @ ~20 ms latency
        ↓
[XRoboToolkit Unity Client APK on headset]
  Tracking → PICO Motion Tracker → Mode = Full body tracking
  Head/Controller/Body toggles ON
  Direction = Send
        ↓
[XRoboToolkit-PC-Service.win / runService.bat]
  RoboticsServiceProcess.exe + Qt6 DLLs
        ↓
[xrobotoolkit_sdk Python binding]
  is_body_data_available() == True
  get_body_joints_pose() = 24×7 SMPL
```

**Source**:
- XRoboToolkit-PC-Service-Pybind README §4: "Get whole body motion tracking (please refer to this example when check Full Body tracking mode in UNITY app)"
- XRoboToolkit-Unity-Client README: Mode 선택 = `None / Full body tracking / Object`
- XRoboToolkit arXiv 2508.00097v2 §II-B/D: full body mode = "whole-body keypoint poses", Object mode = "directly returns motion tracker poses"
- PICO Motion Tracker product page: "multi-modal AI tracking algorithm" → "6DoF data for 24 skeleton points"

## 3. AI 트래킹 반영 여부 — 결론

| 사용자 질문 | 답 | 근거 |
|---|---|---|
| Q1. body_joints_pose 가 PICO 캘리브 앱과 같은 AI 융합 결과인가? | **YES** | XRoboToolkit Unity APK 가 PICO `PXR_BodyTracking` (XR_BD_body_tracking extension) 의 출력을 그대로 forward. 캘리브 앱도 동일 extension 사용. |
| Q2. 융합이 controller pose 까지 포함하는가? | **부분적** | HMD + controllers + PMT 가 INPUT 으로 들어가지만 SMPL 의 L_Wrist/R_Wrist (idx 20/21) 는 AI-smoothed/predicted 라 controller 정밀 회전 보존 X. NVIDIA SONIC/GR00T ZMQ v3 가 동일 한계 명시 — "the wrist joints in joint_pos provide fine-grained wrist control that SMPL alone cannot capture". |
| Q3. 캘리브 앱의 자연스러운 wrist 회전을 보여주는 별도 채널? | **없음** | 캘리브 앱 자체가 SMPL pos + controller quat overlay 를 렌더링. 동일 패턴 재현해야 함. |
| Q4. APK 의 모드 옵션? | **None / Full body tracking / Object** | "Half body" 는 비표준 / fork. |
| Q5. 요구 버전? | PUI ≥ 5.11.0 + PICO Integration SDK 3.1.2 + XRoboToolkit-PICO-1.1.1.apk + 최소 2 PMT 캘리브 |

## 4. 우리 환경에서의 의미 (ust_hm_grip)

사용자 환경:
- PICO 4 Ultra + 5 PMT (waist + 2 forearm + 2 ankle) + 2 controllers + HMD
- XRoboToolkit Unity APK = Full body tracking 모드 활성
- xrobotoolkit_sdk → 24-joint SMPL 받음

PICO 캘리브 앱 화면 = **이미 받고 있는 SMPL 데이터의 시각화**. 따라서:

- **POSITION**: SMPL `L_Wrist / R_Wrist` (idx 20/21) → robot wrist EEF 위치. 자연스러움 (5 PMT 융합 결과).
- **ROTATION**: SMPL wrist quat 은 fine controller-grip 회전 무시. → **controller pose 의 quat overlay** 필요.

**= 정확히 part 12 / part 15 의 설계.**

이 split 패턴은 NVIDIA SONIC/GR00T 가 동일 이유로 사용 ([gr00t-wholebodycontrol ZMQ docs](https://nvlabs.github.io/GR00T-WholeBodyControl/tutorials/zmq.html)):
> "we ship SMPL pose AND a separate explicit wrist channel joint_pos[23..28] because the wrist joints in joint_pos provide fine-grained wrist control that SMPL alone cannot capture"

## 5. 우리 retargeter 의 현재 디폴트 (part 15)

`GR1T2GripperDeviceCfg`:
```python
wrist_pos_source:  str = "wrist_tracker"   # SMPL idx 20/21 delta
wrist_quat_source: str = "controller"      # controller quat delta
```

`pico_device_cfg`:
```python
"wrist_pos_source":  "wrist_tracker",
"wrist_quat_source": "controller",
```

이 설정으로 `_compose_eef_target` (retargeter.py 의 part 14 dispatch) 가:
- pos = `idle_pos + (wt_pos - wt_zero) * axis_scale`
- quat = `(ctrl_quat * inv(ctrl_zero_q)) * idle_q`

→ 캘리브 앱 동작 그대로 robot 매핑.

Body data 없으면 (Unity APK 모드 잘못 / PMT 미연결) pos = idle, quat = idle. Controller silent re-couple 없음.

## 6. 실행 체크리스트 (사용자가 직접 확인)

1. PICO 4 Ultra: 시스템 OS PUI 버전 확인 → **5.11.0 이상**
2. PICO Motion Tracker 앱 (PICO 헤드셋 앱) 실행 → 5 PMT 모두 paired + calibration 완료
3. **XRoboToolkit Unity Client APK** 실행:
   - Tracking → PICO Motion Tracker → Mode = **`Full body tracking`** (Object 아님)
   - Head toggle ON, Controller toggle ON, Body toggle ON
   - Direction = Send
   - Start
4. PC: `runService.bat` 실행 → RoboticsServiceProcess.exe 가동
5. 실행:
   ```powershell
   $env:PYTHONPATH = "."
   python -X utf8 -m ust_ws.ust_hm_grip.scripts.run_teleop `
       --env_variant robot_only --render_mode monitor `
       --teleop_device pico_gripper --input_backend xrobotoolkit `
       --xrt_enable_body True --full_body True `
       --gripper_signal_source grip `
       --max_seconds 300 --process_priority high
   ```
6. Startup 로그에서 확인:
   ```
   [XRoboSampler] channel probe:
     HMD pose:                   LIVE
     Body skeleton (24-joint):   AVAILABLE
     Independent PMT:            n=0, serials=[]    ← 비어 있어야 정상 (Full body 모드)
     APK tracking mode:          Full body tracking (SMPL 24-joint AI fusion ON)
     Body role map: {0: 'waist', 18: 'left_forearm', 19: 'right_forearm',
                     20: 'left_wrist', 21: 'right_wrist'}
   ```
7. `[run_teleop][phase_d] body-wrist {side} calibrated — pos_zero=(...) quat_zero=(...)` 출력 후 robot 추적 시작.
8. TRACK 출력에서 `rotation_delta=yaw/.../...` 가 controller 회전 따라가는지 + `L_wrist actual yaw=... roll=... pitch=...` 가 controller delta 와 일치하는지 확인.

## 7. 알려진 한계

- **Forearm tracker (5 PMT) 가 elbow 추정 정확도만 개선**. Joint 수는 여전히 24 (Source: UploadVR).
- **idx 22/23 (L_Hand/R_Hand) 는 wrist endpoint 노드** — 손가락 detail 없음. Finger pose 필요 시 `XR_FB_hand_tracking` 별도 채널 (이미 xrobo_sampler 에서 노출 가능, `xrt_enable_hand` flag).
- **장시간 사용 시 SMPL drift**. PICO Motion Tracker 앱으로 재 캘리브 권장.
- **XRoboToolkit 논문 §V** 가 직접 명시: humanoid retargeting 용 검증은 안 됐음. 우리가 직접 검증해야.
- **`get_motion_tracker_pose()` 최대 3 PMT raw**. 5 PMT 전부 raw 로 받는 채널 없음. Object 모드는 fusion 잃음 → 우리 retargeter 는 Full body 모드 + 자체 IK 권장.
