# Windows Isaac Lab + PICO Connect + XRoboToolkit 아키텍처 분석

> 작성일: 2026-04-08
> 목적: Ubuntu에서 Windows로 전환하여 PICO Connect VR 스트리밍 + XRoboToolkit 전신 트래킹을 동시에 구현할 수 있는지 조사

---

## 1. 핵심 결론

### Docker (WSL2) 경로: 불가능

**Isaac Sim은 Windows WSL2 Docker에서 실행 불가**. NVIDIA가 공식적으로 미지원을 확인.

| 원인 | 상세 |
|------|------|
| Vulkan 미지원 | WSL2는 GPU 반가상화(GPU-PV, WDDM)를 사용하며 Vulkan 1.1+를 노출하지 않음 |
| Hydra Engine 의존 | Isaac Sim의 RTX 렌더러는 Vulkan 기반 → `ERROR_INCOMPATIBLE_DRIVER` |
| Headless도 불가 | 물리 시뮬레이션 파이프라인도 Vulkan/RTX GPU 가속에 의존 |
| GLFW 초기화 실패 | Xvfb 가상 프레임버퍼로도 해결 불가 |

NVIDIA 개발자 포럼 공식 답변:
> "Isaac Sim containers are currently not supported under WSL2."
> "Vulkan is used by the Hydra Engine for RTX rendering... Currently, Vulkan is not supported on WSL."
> -- Sheikh_Dawood, NVIDIA, 2024-01

**영향 범위**: Isaac Sim 4.0.0, 4.5.0, 5.0.0, 5.1.0 모든 버전 동일.

### 네이티브 Windows 경로: 가능

**Isaac Sim + Isaac Lab을 Windows에 네이티브 설치하면 모든 것이 가능.**

```
┌──────────────────────────────────────────────────────────────┐
```

## 2. Windows 네이티브 설치 상세

### 2.1 Isaac Sim 5.1.0 Windows 설치

**공식 지원 확인됨.** 3가지 방법:

#### 방법 A: pip 설치 (권장)

```powershell
# Python 3.11 가상환경 생성
python -m venv C:\isaacsim_venv
C:\isaacsim_venv\Scripts\activate

# Isaac Sim 설치
pip install isaacsim==5.1.0

# 설치 확인
python -c "import isaacsim; print(isaacsim.__version__)"
```

#### 방법 B: 사전 빌드 바이너리

1. NVIDIA 개발자 사이트에서 Windows 바이너리 다운로드
2. `C:\isaacsim`에 압축 해제
3. `post_install.bat` 실행
4. `isaac-sim.bat` 또는 `isaac-sim.headless.bat`으로 실행

#### Windows 최소/권장 사양

| 항목 | 최소 | 권장 (RTX PRO 6000) |
|------|------|---------------------|
| OS | Windows 10/11 | Windows 11 |
| CPU | i7 7th Gen | i9 / Ryzen 9 |
| RAM | 32 GB | 64 GB |
| GPU VRAM | 16 GB | 96 GB (RTX PRO 6000) |
| 드라이버 | 580.88+ | 최신 |
| 저장소 | 50 GB SSD | 1 TB NVMe |
| Python | 3.10 / 3.11 | 3.11 |

### 2.2 Isaac Lab 2.3.0 Windows 설치

```powershell
# Isaac Lab 클론
git clone https://github.com/isaac-sim/IsaacLab.git
cd IsaacLab

# Windows용 설치 스크립트
.\isaaclab.bat -i        # 확장 + RL 프레임워크 설치
.\isaaclab.bat -i none   # 확장만 설치

# 실행
.\isaaclab.bat -p script.py    # Python 스크립트 실행
.\isaaclab.bat -t              # 테스트 실행
.\isaaclab.bat -f              # 포맷팅
```

**참고**: Windows에서 긴 경로(260자 초과) 문제 발생 가능.
```powershell
# 레지스트리에서 긴 경로 활성화
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" `
    -Name "LongPathsEnabled" -Value 1 -PropertyType DWORD -Force
```

### 2.3 CloudXR Runtime 6.0.1 Windows 설치

**Windows 네이티브 지원 확인됨. Docker 불필요.**

| 항목 | 요구사항 |
|------|---------|
| OS | Windows 11 (권장), Windows 10 64-bit |
| GPU | NVIDIA Ada / Blackwell (RTX 4090, RTX 5090, RTX PRO 6000 등) |
| 드라이버 | 573.42 이상 |
| NVENC | 최소 2세션, 3+ 권장 |
| 추가 | MSVC++ Redistributable 2015-2022 |

```
설치 방법:
1. NGC에서 CloudXR SDK 6.0.1 다운로드
2. CloudXR Runtime Windows 인스톨러 실행
3. 또는 SDK에서 직접 라이브러리 링크 (cxrServiceAPI.h)
```

**Stream Manager**: Windows 전용 기능으로, CloudXR 런타임 인스턴스를 RPC로 관리하는 독립 서비스.

### 2.4 XRoboToolkit PC Service

**Windows 네이티브 지원 확인됨.** 크로스 플랫폼:
- Windows x86

## 3. PICO Connect vs CloudXR: 어떤 것이 필요한가?

### 중요한 인사이트: PICO Connect가 불필요할 수 있음

현재 프로젝트 아키텍처에서 VR 렌더링 스트리밍은 **CloudXR.js**가 담당합니다.
PICO Connect는 SteamVR 게임 스트리밍 도구이며, 로봇 텔레오퍼레이션에는 불필요합니다.

| 기능 | CloudXR 6.0.1 | PICO Connect |
|------|---------------|--------------|
| VR 렌더링 스트리밍 | O (WebRTC) | O (PCVR) |
| Isaac Sim 직접 통합 | O (OpenXR Kit 확장) | X (SteamVR 경유) |
| Linux 서버 지원 | O (Docker) | X (Windows만) |
| Windows 서버 지원 | O (네이티브) | O (네이티브) |
| 추가 SW 필요 | X | SteamVR |
| 지연시간 | 낮음 (직접 WebRTC) | 중간 (SteamVR 경유) |
| PICO 클라이언트 | 웹 브라우저 | PICO Connect 앱 |
| XRoboToolkit 동시실행 | O (별도 앱) | 미확인 |

**결론**: Windows로 전환해도 **CloudXR를 사용하는 것이 PICO Connect보다 적합**.

### PICO OS 6 멀티태스킹

PICO OS 6은 앱 멀티태스킹을 지원합니다:
- CloudXR.js (웹 브라우저): VR 렌더링 수신/표시
- XRoboToolkit App: 전신 트래킹 데이터 전송
- 두 앱은 다른 리소스를 사용 (XRT=센서/트래킹, 브라우저=디스플레이/네트워크)
- **동시 실행 가능** (PICO OS 6 멀티태스킹 기능)

## 4. GPU 리소스 공유 분석

Windows에서 단일 RTX PRO 6000으로 3개 작업 동시 실행:

| 작업 | GPU 리소스 | VRAM 예상 |
|------|-----------|-----------|
| Isaac Sim 렌더링 (1 env) | CUDA + RTX 코어 | ~8-16 GB |
| CloudXR 인코딩 (NVENC) | NVENC 전용 회로 (2-3세션) | ~1-2 GB |
| XRoboToolkit PC Service | CPU만 (gRPC 서버) | 0 GB |

**RTX PRO 6000 (96 GB VRAM)**: 충분한 여유.
- NVENC 세션 제한: 무제한 (Professional GPU)
- CUDA + NVENC 동시 사용: 지원됨 (NVENC은 별도 하드웨어 블록)

**잠재적 병목**: Isaac Sim이 GPU를 100% 사용하면 CloudXR 인코딩 지연 가능.
- 해결: `render_interval=2` 설정으로 렌더 부하 줄이기 (이미 VR 환경에 적용됨)

## 5. 구현 아키텍처 비교

### 안 A: Windows 네이티브 (CloudXR, PICO Connect 불필요)

```
Windows 11 PC (RTX PRO 6000)
  ├─ Isaac Sim 5.1.0 (pip install, 네이티브)
  │   └─ Isaac Lab 2.3.0 (isaaclab.bat)
  │       └─ Kitchen Sorting Env + OpenXR Kit 확장
  ├─ CloudXR Runtime 6.0.1 (Windows 네이티브)
  │   └─ WebRTC → PICO 브라우저 (CloudXR.js)
  └─ XRoboToolkit PC Service (RoboticsServiceProcess.exe)
      └─ gRPC ← PICO XRoboToolkit App

PICO 4 Ultra:
  ├─ CloudXR.js (브라우저) → VR 렌더링 표시
  └─ XRoboToolkit App → 전신+손 트래킹

Windows N100 미니PC:
  └─ UDCAP → VMC UDP:39539 → 메인 PC unified_bridge
```

**장점**:
- PICO Connect / SteamVR 불필요
- 기존 CloudXR.js 인프라 재활용
- 지연시간 최소 (직접 WebRTC)
- CloudXR + XRoboToolkit 동시 실행 가능 (PICO OS 6)

**단점**:
- Ubuntu → Windows 환경 이전 필요
- isaaclab.sh → isaaclab.bat 전환
- Docker 워크플로우 포기
- ust_ws 코드 경로 수정 필요

### 안 B: Windows + PICO Connect + SteamVR

```
Windows 11 PC (RTX PRO 6000)
  ├─ Isaac Sim 5.1.0 (네이티브)
  ├─ SteamVR → PICO Connect → VR 렌더링
  └─ XRoboToolkit PC Service

PICO 4 Ultra:
  ├─ PICO Connect (VR 스트리밍)
  └─ XRoboToolkit App (트래킹, 백그라운드?)
```

**장점**:
- PICO Connect의 최적화된 스트리밍
- SteamVR 에코시스템 활용

**단점**:
- SteamVR 추가 설치/설정 필요
- PICO Connect + XRoboToolkit 동시 실행 보장 없음
- CloudXR 대비 추가 복잡성 (SteamVR 레이어)
- PICO Connect가 디스플레이를 점유 → XRoboToolkit UI 사용 불가

### 안 C: 하이브리드 (Ubuntu 유지, CloudXR 직접)

```
Ubuntu PC (RTX PRO 6000) → 기존 환경 유지
  ├─ Isaac Sim Docker (기존)
  ├─ CloudXR Runtime 6.0.1 Docker (기존)
  └─ XRoboToolkit PC Service (기존)

PICO 4 Ultra:
  ├─ CloudXR.js (브라우저)
  └─ XRoboToolkit App
```

**장점**:
- 환경 이전 불필요
- 이미 구축된 인프라 활용
- Docker 워크플로우 유지

**단점**:
- CloudXR.js + XRoboToolkit 동시 실행 검증 필요

## 6. 권장 방안

### 최우선: 안 C (Ubuntu 유지) + PICO OS 6 멀티태스킹 검증

Windows로 이전하기 전에, **현재 Ubuntu 환경에서** CloudXR.js + XRoboToolkit 동시 실행을 먼저 테스트해야 합니다.

**검증 순서:**

1. **방안3 (모니터 뷰)로 트래킹 파이프라인 검증** (이미 구현 완료)
   ```bash
   ./isaaclab.sh -p ust_ws/ust_260220/scripts/run_teleop.py \
       --teleop_device pico --render_mode monitor
   ```

2. **PICO OS 6 멀티태스킹 테스트**
   - PICO에서 XRoboToolkit App 실행 → 트래킹 데이터 전송 확인
   - 동시에 PICO 브라우저로 CloudXR.js 접속 시도
   - 두 앱이 공존 가능한지 확인

3. **공존 가능하면**: Ubuntu 환경에서 전신 트래킹 + VR 뷰 달성 (Windows 이전 불필요!)

4. **공존 불가하면**: 안 A (Windows 네이티브 + CloudXR)로 이전 검토

### Windows 이전이 필요한 경우: 안 A 실행 계획

| 단계 | 작업 | 예상 소요 |
|------|------|----------|
| 1 | Windows 11 설치 (듀얼부트 또는 전환) | 1일 |
| 2 | NVIDIA 드라이버 + CUDA 설치 | 0.5일 |
| 3 | Python 3.11 + Isaac Sim pip 설치 | 0.5일 |
| 4 | Isaac Lab 클론 + 설치 (isaaclab.bat) | 0.5일 |
| 5 | ust_ws 코드 이전 + 경로 수정 | 1일 |
| 6 | CloudXR Runtime 6.0.1 네이티브 설치 | 0.5일 |
| 7 | XRoboToolkit PC Service Windows 빌드 | 1일 |
| 8 | 통합 테스트 | 1-2일 |
