# ust_ws 코드베이스 → Windows 11 + SteamVR 마이그레이션 분석 가이드

> **근거 문서**: [28. SteamVR 휴머노이드 텔레오퍼레이션 구현 가이드 (Windows 단일 PC + Virtual Desktop + UDCAP VR Glove).md](./28.%20SteamVR%20휴머노이드%20텔레오퍼레이션%20구현%20가이드%20(Windows%20단일%20PC%20+%20Virtual%20Desktop%20+%20UDCAP%20VR%20Glove).md)
>
> **목적**: 기존 `ust_ws/` 코드(Ubuntu 24.04 + ROS2 + Docker + XRoboToolkit ConsoleDemo subprocess + CloudXR 6.0.1) 전체를 문서 28의 Windows 11 단일 PC 아키텍처(SteamVR + Virtual Desktop + UDCAP VR Glove + pyopenvr in-process)로 마이그레이션하기 위한 파일별 상세 매핑과 실행 로드맵.
>
> **스코프**: 본 문서는 *설계/매핑 분석*이며 실제 코드 변경은 포함하지 않는다. 구현은 `/sc:implement` 단계에서 수행.

---

## 0. 요약 (TL;DR)

| 분류 | 건수 | 처리 방침 |
|------|------|----------|
| **그대로 재사용** (순수 Python/PyTorch) | 약 20 파일 | 이동/재배치만 |
| **경량 수정 후 재사용** (플랫폼 추상화/인터페이스 교체) | 6 파일 | Linux syscall 제거, TCP→in-process |
| **신규 작성** (SteamVR/pyopenvr/dex-retargeting 경로) | 8 파일 | 문서 28 §3–§5 구조 |
| **폐기 또는 보류** (ROS2/CloudXR/ConsoleDemo/Docker) | 약 30 파일 | 아카이브만, 호출 경로에서 제거 |

**핵심 변경**:
1. **TCP :8889 brideg 완전 제거** — `unified_bridge.py` + `XRTDataParser` + `PICOFullBodyTeleopDevice._recv_loop`는 없어진다. Isaac Lab 프로세스 내부에 `SteamVRSampler` 스레드(pyopenvr)만 남는다.
2. **ROS 2 의존 전면 삭제** — `ust_260207`의 `run_ros2_bridge.py` 및 `rbpodo_ros2/`, `ust_project1/` ROS 2 경로는 Windows에서 사용 불가. 실기 연동은 차후 별도 Linux PC 확장.
3. **ConsoleDemo/XRT SDK 경로 폐기** — XRoboToolkit Linux 바이너리는 재컴파일/사용 대상 아님. Vive Tracker 에뮬레이션은 Virtual Desktop의 `Forward Trackers to SteamVR`이 대체.
4. **UDCAPFingerMapper 용도 전환** — VMC bone → Inspire 12D 매퍼는 Path B(VMC 폴백)에만 남기고, 주 경로는 SteamVR Skeletal Input + `dex-retargeting`.
5. **G1PICORetargeter의 재탄생** — 순수 수학부(38D Pink IK 액션 조립, 좌표 변환, idle pose)는 유지하되 입력을 `XRTFrame`에서 `SteamVRSnapshot`으로 교체.
6. **렌더링 파이프라인**: 1단계는 Virtual Desktop 데스크탑 모드(문서 28 부록 Path-4) → Isaac Sim 창을 2D로 VR에 투영. CloudXR/SteamVR 네이티브 스테레오는 후순위.

## 1. 현 상태 아키텍처(Ubuntu) 요약

```
┌──────────────────── Ubuntu 24.04 호스트 ────────────────────┐
│                                                             │
│  PICO 4 Ultra (5 motion tracker, Enhanced Forearm)          │
│      │ USB-C 또는 Wi-Fi                                     │
│      ▼                                                      │
│  XRoboToolkit PC Service (gRPC)                             │
│      │                                                      │
│      │ (subprocess stdout, JSON lines)                      │
│      ▼                                                      │
│  unified_bridge.py  ◄── UDCAP Driver (Linux) VMC :39539     │
│      │ ConsoleDemo + python-osc 수신, JSON 병합             │
│      │                                                      │
│      │ TCP :8889 (network_mode:host)                        │
│      ▼                                                      │
│  ┌─── Docker container (Isaac Lab 2.x) ──────────┐          │
│  │   PICOFullBodyTeleopDevice (TCP client)       │          │
│  │     └→ XRTDataParser → G1PICORetargeter       │          │
│  │         └→ 38D Pink IK action                 │          │
│  │   ManagerBasedRLEnv (kitchen_sorting_env_cfg) │          │
│  │   (선택) CloudXR Runtime container ──WebRTC──┼─▶ PICO    │
│  └───────────────────────────────────────────────┘          │
└─────────────────────────────────────────────────────────────┘
```

핵심 병목:
- **3 stage IPC** (ConsoleDemo stdout → unified_bridge → TCP → Docker) 각 stage 마다 jitter/버퍼링 이슈 (`stdbuf`, `lsof`, `LD_LIBRARY_PATH` 우회 코드가 산재).
- **Linux-only** 바이너리(ConsoleDemo/RoboticsServiceProcess), **Linux-only** shell 스크립트, **Linux-only** ROS2.
- **CloudXR Docker** — Windows에서 네트워크/IPC 포팅 비용이 크다.

### 4.3 리타게터 전략 — `G1PICORetargeter` vs `dex-retargeting`

**판단**:
- 기존 `G1PICORetargeter`는 **상체+그리퍼** 38D 액션을 **델타 누적 없이 절대 좌표**로 조립하는 Pink IK 포맷 전용이었다. 구조(좌표 변환 → 손목 EEF → 24D 손가락 조립)는 단일 `advance()` 호출이다.
- 문서 28은 **상체(Pink IK) + 손가락(dex-retargeting)** 을 **분리**한다. Pink IK는 Isaac Lab 내장 `PinkIKController`를 그대로 쓰고, 손가락은 `dex-retargeting` 라이브러리의 DexPilot 솔버를 쓴다.

**결정**: `G1PICORetargeter`의 **구조는 유지하되 내부는 리팩터링**한다.
- **유지**: `ACTION_DIM=38`, 38D 텐서 조립, pelvis frame 적용, idle pose fallback, gripper threshold
- **교체**: 좌표 변환 `XRT Z-in→Z-out` → `SVR Y-up→Z-up` (문서 28 §5.3)
- **교체**: 24D 손가락 (UDCAP VMC bend/spread) → `dex-retargeting` 5 fingertip 기반 Inspire 24D
- **유지(폴백)**: `UDCAPFingerMapper`는 Path B VMC 수신 시에만 사용. SteamVR Skeletal Input 장애 시 `fingertips` 대신 VMC bone 기반 bend/spread로 fallback.
- **추가**: `forearm_to_wrist()` 함수 (문서 28 §5.2).

**결론**: `ust_ws/` 내 **대부분의 Python 코드(~80%)는 플랫폼 독립**이며, **실제로 교체가 필요한 부분은 데이터 입력 파이프라인 한 곳**(ConsoleDemo subprocess + TCP 브리지 + XRT JSON 파서)에 집중되어 있다. 이를 `SteamVRSampler`(pyopenvr in-process) + `PicoUDCAPDevice`(DeviceBase)로 치환하면, Isaac Lab 환경/리타게터/학습 파이프라인은 손대지 않고도 Windows 11 + SteamVR + Virtual Desktop + UDCAP VR Glove 구성에서 동작한다. ROS 2/Docker/CloudXR은 1단계 스코프에서 제외하여 범위를 단순화하고, 지연/복잡도를 최소화한다. 예상 구현 기간은 **4주**이며, 치명적 리스크는 Pico OS 버전/VD 라이선스/Pink IK 휠 세 가지로 좁혀진다.
