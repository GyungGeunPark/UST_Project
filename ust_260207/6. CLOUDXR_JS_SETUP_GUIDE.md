## 1. 개요 및 아키텍처

### CloudXR.js란?

CloudXR.js는 **JavaScript 기반 WebXR 클라이언트 프레임워크**입니다.
CloudXR Runtime 서버에서 렌더링된 VR 영상을 WebRTC로 Quest 브라우저에 스트리밍합니다.

- **프로토콜:** WebRTC (영상/오디오) + WebSocket (시그널링)
- **클라이언트:** Quest 3S 내장 브라우저 (네이티브 APK 불필요)
- **배포:** npm 패키지 (NGC Early Access에서 다운로드)
- **버전:** 6.0.0-beta (Early Access)
- **프레임워크:** vanilla WebGL, Three.js, React Three Fiber 등 호환

### 전체 아키텍처

```
┌─────────────────────────────┐
│  Meta Quest 3S              │
│  내장 브라우저 (WebXR)       │
│                             │
│  CloudXR.js 웹 앱           │
│  (Hand Tracking → WebRTC)   │
└──────────┬──────────────────┘
           │ wss:// (WebSocket, TCP 48322)
           │ + WebRTC (UDP 47998)
           ▼
┌─────────────────────────────┐
│  HAProxy (WebSocket 프록시)  │  ← Docker 컨테이너
│  TLS 종단점                  │
│  wss://외부:48322            │
│  → ws://localhost:49100      │
└──────────┬──────────────────┘
           │ ws:// (WebSocket, TCP 49100)
           ▼
┌─────────────────────────────┐
│  CloudXR Runtime 6.0.1      │  ← Docker 컨테이너
│  nvcr.io/nvidia/cloudxr-    │
│  runtime-early-access:      │
│  6.0.1-webrtc               │
│  - WebSocket 시그널링 (49100)│
│  - 미디어 스트리밍 (47998)   │
│  - IPC 소켓 (/openxr)       │
└──────────┬──────────────────┘
           │ Unix Domain Socket
           │ /openxr/run/ipc_cloudxr
           ▼
┌─────────────────────────────┐
│  Isaac Lab 2.3.0            │  ← Docker 컨테이너
│  OpenXR 클라이언트           │
│  로봇 시뮬레이션 + 렌더링    │
│  Hand Tracking 데이터 수신   │
└─────────────────────────────┘
```

### 네이티브 APK vs CloudXR.js 비교

| 항목 | 네이티브 APK (4.0.1) | CloudXR.js (6.0.0-beta) |
|---|---|---|
| 클라이언트 | 안드로이드 APK 설치 | 웹 브라우저 접속 |
| 프로토콜 | TCP/UDP 직접 연결 | WebRTC + WebSocket |
| 시그널링 포트 | TCP 48010 | TCP 49100 (ws) / 48322 (wss 프록시) |
| Quest 3S 호환 | ✗ (SIGSEGV 크래시) | ✓ (브라우저 기반) |
| Runtime 6.0.1 호환 | ✗ (버전 불일치) | ✓ (공식 지원) |
| 설치 필요 | APK sideload 필요 | URL 접속만 |

## 2. CloudXR.js 다운로드 (★ 중요: 현재 상황)

### 2.1 현재 다운로드 상태 (2026-02-07 확인)

**CloudXR.js는 현재 공개 다운로드가 불가능합니다.**

| NGC URL | 상태 |
|---|---|
| `catalog.ngc.nvidia.com/.../resources/cloudxr-js-early-access` | **404 Not Found** |
| NGC 검색 "cloudxr-js" | **결과 없음** |
| npm 레지스트리 "cloudxr" | **NVIDIA 패키지 없음** |

NVIDIA 공식 문서(docs.nvidia.com/cloudxr-sdk)에서는 이 NGC URL을 참조하지만,
실제로 해당 리소스는 **EA 승인을 받은 사용자에게만 보이거나, 아직 공개되지 않은 상태**입니다.

### 2.2 NGC에서 실제 존재하는 CloudXR 리소스

| 리소스 | NGC URL | 상태 | 버전 |
|---|---|---|---|
| CloudXR Runtime (Container) | `.../containers/cloudxr-runtime` | ✓ 존재 | 5.0.2, 5.0.1, 5.0.0, 0.1.0-isaac |
| CloudXR Runtime EA (Container) | `.../containers/cloudxr-runtime-early-access` | ✓ 존재 | **6.0.1-webrtc** (★ 현재 사용) |
| CloudXR Runtime (Resource/ZIP) | `.../resources/cloudxr-runtime` | ✓ 존재 | **6.0.2** (공개 다운로드 가능) |
| CloudXR SDK (Collection) | `.../collections/cloudxr-sdk` | ✓ 존재 | CloudXR.js를 "Early Access"로 언급 |
| CloudXR Stream Manager | `.../resources/cloudxr-stream-manager` | ✓ 존재 | - |
| **CloudXR.js** | `.../resources/cloudxr-js-early-access` | **✗ 404** | - |

> **핵심:** CloudXR SDK Collection 페이지에서 CloudXR.js를 "Early Access 웹 기반 클라이언트 SDK"로 설명하지만,
> 실제 다운로드 리소스 페이지는 존재하지 않거나 EA 승인 사용자에게만 보입니다.

| npm | Node.js에 포함 | `npm --version` |

### 3.2 Node.js 설치 (없는 경우)

```bash
# NodeSource에서 Node.js 20.x LTS 설치
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# 버전 확인
node --version   # v20.19.0 이상이어야 함
npm --version
```

### 3.3 CloudXR Runtime 포트 확인

CloudXR Runtime 6.0.1이 사용하는 포트:

```
TCP 49100       ← WebSocket 시그널링 (CloudXR.js 연결)
TCP 48322       ← WebSocket 프록시 (HTTPS 모드, HAProxy)
UDP 47998-48012 ← 미디어 스트리밍
```

> **참고**: Runtime 6.0.1은 `--network host` 모드로 실행하므로 별도 포트 매핑(`-p`)이 불필요합니다.

Docker run 명령:

```bash
docker run -it --rm \
    --name ust-cloudxr-runtime \
    --network host \
    --gpus=all \
    -e "ACCEPT_EULA=Y" \
    --mount "type=bind,src=$(pwd)/openxr,dst=/openxr" \
    nvcr.io/nvidia/cloudxr-runtime-early-access:6.0.1-webrtc
```

### 3.4 방화벽 포트 개방

```bash
# CloudXR Runtime 6.0.1 포트
sudo ufw allow 49100/tcp        # WebSocket 시그널링
sudo ufw allow 48322/tcp        # HTTPS WebSocket 프록시 (HAProxy)
sudo ufw allow 47998:48012/udp  # 미디어 스트리밍

# 웹 서버 포트
sudo ufw allow 8080/tcp     # CloudXR.js 웹 앱 (HTTP)
sudo ufw allow 8443/tcp     # CloudXR.js 웹 앱 (HTTPS, 선택)
```

## 6. WebSocket 프록시 설정 (HTTPS)

### 왜 프록시가 필요한가?

HTTPS 웹 페이지에서 비보안 WebSocket(`ws://`)에 연결하면 **Mixed Content** 보안 정책으로 차단됩니다.

```
HTTPS 페이지 → ws://server:49100  ← ✗ 브라우저가 차단
HTTPS 페이지 → wss://proxy:48322  ← ✓ TLS로 암호화되어 허용
```

### 프록시 아키텍처

```
Quest 브라우저 (HTTPS)
    ↓ wss://192.168.0.117:48322 (암호화)
HAProxy (TLS 종단점)
    ↓ ws://localhost:49100 (평문, 내부)
CloudXR Runtime
```

### Docker + HAProxy 설정

CloudXR.js EA 패키지에 포함된 Docker 설정을 사용합니다:

```bash
# proxy 디렉토리로 이동
cd ~/ust_ws/cloudxr_js/proxy

# HAProxy + 자체 서명 인증서 생성 후 실행
docker compose up -d

# 확인
docker ps | grep haproxy
ss -tlnp | grep 48322
```

**수동 HAProxy 설정 (EA 패키지가 없는 경우):**

```bash
# HAProxy 설치
sudo apt install haproxy

# 자체 서명 인증서 생성
mkdir -p ~/ust_ws/cloudxr_js/certs
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
    -keyout ~/ust_ws/cloudxr_js/certs/server.key \
    -out ~/ust_ws/cloudxr_js/certs/server.crt \
    -subj "/CN=192.168.0.117"

# PEM 파일 결합 (HAProxy 형식)
cat ~/ust_ws/cloudxr_js/certs/server.crt \
    ~/ust_ws/cloudxr_js/certs/server.key \
    > ~/ust_ws/cloudxr_js/certs/server.pem
```

HAProxy 설정 파일 (`haproxy.cfg`):

```
global
    log stdout format raw local0

defaults
    mode http
    timeout connect 5s
    timeout client 30s
    timeout server 30s

frontend wss_frontend
    bind *:48322 ssl crt /path/to/server.pem
    default_backend cloudxr_ws

backend cloudxr_ws
    server cloudxr 127.0.0.1:49100
```

## 7. Quest 3S 브라우저 설정

### 7.1 HTTP 모드 (개발 전용)

Quest 내장 브라우저에서 HTTP 사이트의 WebXR을 허용하려면:

1. Quest 3S에서 **Meta Quest Browser** 열기
2. 주소창에 `chrome://flags` 입력
3. 검색창에 `insecure` 입력
4. **"Unsafely treat insecure origin as secure"** 항목 찾기
5. **Enable** 선택
6. 입력란에 서버 URL 추가: `http://192.168.0.117:8080`
7. **Relaunch** 버튼 클릭 (브라우저 재시작)
8. `http://192.168.0.117:8080` 접속

### 7.2 HTTPS 모드 (★ 권장)

자체 서명 인증서를 사용하는 경우, Quest 브라우저에 신뢰를 추가해야 합니다:

**Step A: WebSocket 프록시 인증서 신뢰**

1. Quest 브라우저에서 `https://192.168.0.117:48322/` 접속
2. "연결이 비공개가 아닙니다" 경고 표시
3. "고급" → "192.168.0.117(안전하지 않음)으로 이동" 클릭
4. **"501 Not Implemented"** 페이지가 표시되면 정상 (인증서 신뢰 완료)

**Step B: 웹 앱 인증서 신뢰**

1. Quest 브라우저에서 `https://192.168.0.117:8080/` 접속
2. 동일하게 인증서 경고 수락
3. CloudXR.js 웹 앱이 로드됨

**Step C: CloudXR 연결**

1. 웹 앱의 **"Enter VR"** 또는 **"Connect"** 버튼 클릭
2. Zone 설정: **"Manual IP Address"** 선택
3. 서버 IP 입력: `192.168.0.117`
4. 연결 시작
5. VR 몰입 모드 진입

## 8. Isaac Lab 연결 및 텔레오퍼레이션

### 8.1 전체 실행 순서

모든 구성요소를 올바른 순서로 시작해야 합니다:

```
[Step 1] CloudXR Runtime Docker 시작
    ↓ (IPC 소켓 생성 대기)
[Step 2] Isaac Lab 시작 (OpenXR 환경변수 설정)
    ↓ (시뮬레이션 렌더링 시작)
[Step 3] WebSocket 프록시 시작 (HTTPS 모드인 경우)
    ↓
[Step 4] CloudXR.js 웹 서버 시작
    ↓
[Step 5] Quest 3S 브라우저에서 접속
    ↓
[Step 6] VR 텔레오퍼레이션 시작
```

### 8.2 Step 1: CloudXR Runtime 시작 (호스트)

```bash
cd ~/ust_ws

# openxr 폴더 권한 설정
```

## 9. 트러블슈팅

### 9.1 NGC에서 CloudXR.js가 보이지 않는 경우

| 상황 | 해결 |
|---|---|
| EA 승인 이메일을 못 받음 | 신청 후 1주일 대기, 스팸함 확인 |
| NGC 로그인했는데 리소스가 없음 | EA 승인이 아직 안 된 것 → 대기 또는 재신청 |
| 다운로드 버튼이 비활성 | NGC 계정에 EA 조직 액세스가 없음 → NVIDIA 지원 문의 |

### 9.2 npm install 에러

```bash
# Node.js 버전 확인
node --version  # v20.19.0 이상 필요

# npm 캐시 정리 후 재시도
npm cache clean --force
npm install ./cloudxr-js-<version>.tgz
```

### 9.3 Quest 브라우저에서 웹 앱이 안 열리는 경우

| 증상 | 원인 | 해결 |
|---|---|---|
| "사이트에 연결할 수 없음" | 서버 IP 오류 또는 방화벽 | `hostname -I` 확인, 포트 8080 개방 |
| "연결이 비공개가 아닙니다" | 자체 서명 인증서 | "고급" → "안전하지 않음으로 이동" |
| 빈 화면 | JavaScript 로드 실패 | 데스크톱 브라우저에서 먼저 테스트 |
| WebXR 버튼이 안 보임 | HTTP 모드에서 WebXR 비활성 | HTTPS 모드 사용 또는 chrome://flags 설정 |

### 9.4 CloudXR 연결 실패

| 증상 | 원인 | 해결 |
|---|---|---|
| "Connection failed" | 49100 포트 미개방 | `--network host`로 실행 확인, 방화벽 49100/tcp 개방 |
| "WebSocket error" | 프록시 미설정 (HTTPS 모드) | HAProxy 프록시 시작 |
| "Session timeout" | Isaac Lab 미실행 | Isaac Lab 텔레오퍼레이션 먼저 시작 |
| 연결 후 검은 화면 | GPU 렌더링 문제 | `NV_GPU_INDEX=0` 확인 |

### 9.5 Quest 3S 호환성

공식 문서에는 **Quest 3**만 명시되어 있으나, Quest 3S는:
- 동일한 Snapdragon XR2 Gen 2 프로세서
- 동일한 Meta Horizon OS
- 동일한 브라우저 (WebXR 지원)

따라서 **CloudXR.js는 Quest 3S에서 동일하게 작동**해야 합니다.
(네이티브 APK와 달리 브라우저 기반이므로 OS 수준 호환성 문제 없음)
