# Meta Quest 3S CloudXR 클라이언트 크래시 분석 및 해결 가이드

> 작성일: 2026-02-07
> 증상: CloudXR 클라이언트 앱 실행 → 약 3초 후 크래시 → 홈 화면 복귀 반복
> 장비: Meta Quest 3S + CloudXR Runtime 5.0.1 (Docker)

---

## 1. 크래시 로그 분석

### adb logcat에서 확인된 핵심 에러

```
Fatal signal 11 (SIGSEGV), code 1 (SEGV_MAPERR), fault addr 0x0
  in tid XXXX (CloudXRClientOV), pid XXXX (dia.cloudxr.ovr)
  #04 pc 0000000000073a04  libCloudXRClientOVR.so (android_main+384)
  #05 pc 00000000000c4ce8  libCloudXRClientOVR.so
```

### 크래시 패턴 분석

| 시간 | PID | 상태 |
|---|---|---|
| 23:07:06 | 8164 | SIGSEGV → 크래시 (앱 시작 직후) |
| 23:07:15 | 8569 | SIGSEGV → 크래시 (자동 재시작 후) |
| 23:09:58 | 10690 | 앱 실행 → 23:10:01 SIGSEGV (약 3초) |
| 23:11:51 | 11411 | 앱 실행 → 23:11:54 SIGSEGV (약 3초) |
| 23:13:31 | 11812 | 앱 실행 → 23:13:34 SIGSEGV (약 3초) |
| 23:43:43 | 14078 | 앱 실행 → SIGSEGV (동일 패턴) |

**특징:**
- `fault addr 0x0` = **Null Pointer Dereference** (초기화 실패)
- `android_main+384` = 네이티브 메인 함수 시작 직후 크래시
- 서버에 연결 시도조차 하기 전에 크래시 발생
- 매번 동일한 위치에서 크래시 (재현율 100%)

## 2. 근본 원인: 이중 호환성 문제

### ★ 원인 1: CloudXR SDK 버전 불일치 (Client 4.0.1 ↔ Server 5.0.1)

현재 설치된 APK는 **CloudXR SDK 4.0.1**로 빌드되었습니다:

```
// CloudXRCommon.h (SDK 소스에서 확인)
CLOUDXR_VERSION_MAJOR = 4
CLOUDXR_VERSION_MINOR = 0
CLOUDXR_VERSION_PATCH = 1
```

서버는 **CloudXR Runtime 5.0.1**을 실행 중입니다:

```
nvcr.io/nvidia/cloudxr-runtime:5.0.1
```

**NVIDIA 공식 문서에 명시:**
> "The client and server need to be the same NVIDIA CloudXR SDK version."
> "These server/client binaries are not compatible [with earlier versions]."
>
> 출처: CloudXR SDK FAQ (4.0)

**결론: 4.0.1 클라이언트 APK는 5.0.1 서버에 절대로 연결할 수 없습니다.**

### ★ 원인 2: CloudXR 4.0.1 APK와 Quest 3S HorizonOS 비호환

CloudXR 4.0.1 OVR 클라이언트는 **Oculus VrApi (레거시 SDK)**를 사용합니다:

```java
// MainActivity.java
System.loadLibrary("vrapi");          // ← 레거시 Oculus VrApi
System.loadLibrary("CloudXRClientOVR");
```

```xml
<!-- AndroidManifest.xml -->
<meta-data android:name="com.oculus.supportedDevices"
           android:value="quest|quest2" />
<!-- ★ Quest 3, Quest 3S가 목록에 없음! -->
```

**Quest 3S의 HorizonOS는 VrApi 레거시 API에 대한 호환성이 제한적이며,** 이로 인해 `android_main` 실행 시 VrApi 초기화가 실패하고 Null Pointer에 의한 SIGSEGV가 발생합니다.

**NVIDIA 개발자 포럼에 동일한 크래시가 보고됨:**
- "CloudXR Client App on Quest crashes" (Quest 3S + CloudXR 4.0.1)
- "Android Native Client App Immediately Crashing on Meta Quest 3" (Quest 3 + CloudXR 4.0)
- 두 보고 모두 NVIDIA로부터 해결책이 제시되지 않음

## 3. CloudXR 버전별 아키텍처 변화

| 버전 | 서버 아키텍처 | Quest 클라이언트 | 상태 |
|---|---|---|---|
| **4.0 / 4.0.1** | SteamVR 기반 서버 | 네이티브 OVR APK (VrApi) | ★ 현재 APK 버전 |
| **5.0.1** | OpenXR Runtime (Docker) | 공식 Quest APK 없음 | ★ 현재 서버 버전 |
| **6.0+** | 새 아키텍처 (비호환) | **CloudXR.js** (웹 기반) | 최신 |

**핵심: CloudXR 5.0.1 Runtime에 대응하는 네이티브 Quest APK는 존재하지 않습니다.**

CloudXR 5.0/6.0부터 Quest 지원 방식이 네이티브 APK → **CloudXR.js (웹 기반 클라이언트)**로 전환되었습니다.

## 4. 해결 방법

### 방법 A: CloudXR.js 웹 클라이언트 사용 (★ 권장)

CloudXR 5.0.1+ Runtime과 Quest 3S를 연결하는 공식 지원 방법입니다.

**요구사항:**
- CloudXR Early Access 프로그램 가입 (NVIDIA Developer)
- Quest 3S OS 79+ (WebXR 지원)
- Quest 내장 브라우저 사용

**절차:**
1. NVIDIA Developer 포털에서 CloudXR Early Access 신청
2. CloudXR.js 클라이언트 파일 다운로드
3. 서버에 CloudXR.js 호스팅 설정
4. Quest 3S 브라우저에서 서버 URL 접속

```
Quest 3S 브라우저
    ↓ WebXR/WebRTC
CloudXR.js (웹 클라이언트)
    ↓ TCP 48010 + UDP
CloudXR Runtime 5.0.1 (Docker)
    ↓ IPC Socket
Isaac Lab
```

### 방법 B: Apple Vision Pro 사용

Isaac Lab 공식 지원 VR 클라이언트가 있는 디바이스입니다.

- **Isaac XR Teleop Sample Client** (공식 앱)
- CloudXR Runtime 5.0.1과 완전 호환
- Hand Tracking 네이티브 지원

### 방법 C: 서버를 CloudXR 4.0.1로 다운그레이드 (비권장)

이론적으로 서버를 4.0.1로 맞추면 버전 불일치는 해결되지만:

1. CloudXR 4.0.1 서버는 Docker 이미지가 아닌 SteamVR 기반
2. Isaac Lab 2.3.0의 OpenXR 통합과 호환되지 않을 수 있음
3. Quest 3S와 4.0.1 APK의 HorizonOS 비호환 문제는 여전히 남음
4. **따라서 이 방법은 현실적으로 불가능합니다**

### 방법 D: CloudXR 5.0.1 SDK로 새 APK 빌드 (가능하면)

CloudXR 5.0.1 SDK에 Quest용 네이티브 클라이언트 소스가 포함되어 있다면 새로 빌드할 수 있습니다.
하지만 5.0.1부터 네이티브 OVR 클라이언트가 제거되었을 가능성이 높습니다.

**확인 방법:**
1. NVIDIA Early Access에서 CloudXR SDK 5.0.1 다운로드
2. `Client/Sample/Android/OculusVR/` 폴더 존재 여부 확인
3. 있으면 빌드, 없으면 방법 A(CloudXR.js)를 사용

### 방법 E: Isaac Lab 내장 텔레오퍼레이션 (VR 없이)

VR 없이 개발/테스트를 진행하는 임시 대안입니다:

```bash
# 키보드 컨트롤
./isaaclab.sh -p scripts/environments/teleoperation/teleop_se3_agent.py \
    --task Isaac-PickPlace-GR1T2-Abs-v0 \
    --teleop_device keyboard

# SpaceMouse (3Dconnexion) 컨트롤 (있는 경우)
./isaaclab.sh -p scripts/environments/teleoperation/teleop_se3_agent.py \
    --task Isaac-PickPlace-GR1T2-Abs-v0 \
    --teleop_device se3-spacemouse
```

## 5. 현재 APK 문제점 상세

### 5.1 AndroidManifest.xml의 디바이스 지원 목록

```xml
<meta-data android:name="com.oculus.supportedDevices"
           android:value="quest|quest2" />
```

Quest 3와 Quest 3S가 지원 목록에 없습니다. 이것은:
- Quest 3S에서 앱이 "호환되지 않음"으로 표시될 수 있음
- VrApi 초기화 시 디바이스 프로필을 찾지 못할 수 있음

### 5.2 SDK 버전이 너무 낮음

```gradle
compileSdkVersion 28     // Android 9 (2018년)
targetSdkVersion 28      // Android 9
minSdkVersion 25         // Android 7.1
ndkVersion '21.4.7075529' // NDK r21 LTS
```

Quest 3S는 Android 12+ 기반의 HorizonOS를 사용합니다.
SDK 28 대상 앱이 최신 OS에서 정상 동작하지 않을 수 있습니다.

### 5.3 VrApi (레거시) 사용

```java
System.loadLibrary("vrapi");
```

Meta는 VrApi를 레거시로 분류하고 **OpenXR**로의 전환을 권장하고 있습니다.
Quest 3S의 최신 펌웨어에서 VrApi 지원이 축소되었을 수 있습니다.

## 6. 즉시 조치 사항

### 1단계: 현재 APK 제거 (크래시 반복 방지)

```bash
adb uninstall com.nvidia.cloudxr.ovr
```

### 2단계: NVIDIA Early Access 프로그램 신청

1. https://developer.nvidia.com/cloudxr-sdk 접속
2. "Join Early Access" 또는 "Apply for Early Access" 클릭
3. 사용 목적에 "Isaac Lab VR Teleoperation" 기재
4. CloudXR.js 클라이언트 접근 권한 요청

### 3단계: 임시 대안으로 키보드 텔레오퍼레이션 사용

```bash
# Isaac Lab 컨테이너에서
source /workspace/isaaclab/ust_ws/260207_ust/setup_cloudxr_env.sh

./isaaclab.sh -p scripts/environments/teleoperation/teleop_se3_agent.py \
    --task Isaac-PickPlace-GR1T2-Abs-v0 \
    --teleop_device keyboard
```

### 4단계: CloudXR.js 획득 후 Quest 3S 연결

CloudXR.js를 받은 후:
1. 서버에 웹서버 설정 (nginx 또는 간단한 HTTP 서버)
2. CloudXR.js 파일을 호스팅
3. Quest 3S 브라우저에서 `http://192.168.0.117:PORT` 접속
4. WebXR 세션 시작
