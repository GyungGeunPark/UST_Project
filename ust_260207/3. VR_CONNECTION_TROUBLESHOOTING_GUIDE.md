# VR 텔레오퍼레이션 연결 점검 가이드

> 작성일: 2026-02-07
> 대상: Meta Quest 3S + CloudXR Runtime + Isaac Lab 2.3.0
> 목적: XR_ERROR_RUNTIME_UNAVAILABLE 에러 진단 및 해결

## 현재 에러 원인 요약

```
Error [GENERAL | OpenXR-Loader] : failed to parse /workspace/isaaclab/ust_ws/openxr//.
→ Syntax error: value, object or array expected. Is it a valid runtime manifest file?
→ Failed to activate OpenXR: XR_ERROR_RUNTIME_UNAVAILABLE
```

**근본 원인:** OpenXR 로더가 런타임 매니페스트 JSON 파일을 찾지 못해서 **디렉토리 자체를 JSON으로 파싱**하려고 시도한 것입니다.
이는 `XR_RUNTIME_JSON` 환경변수가 설정되지 않았거나, CloudXR Runtime Docker가 실행 중이지 않기 때문입니다.

## Part 1: VR 기기 ↔ Docker CloudXR Runtime 연결 점검

### 1.1 CloudXR Runtime Docker 컨테이너 상태 확인

```bash
# 1단계: CloudXR 컨테이너가 실행 중인지 확인
docker ps | grep cloudxr

# 기대 결과 (예시):
# a1b2c3d4  nvcr.io/nvidia/cloudxr-runtime:5.0.1  ... Up 5 minutes (healthy)
#
# "Up" + "(healthy)" 가 표시되어야 정상
```

**결과별 대응:**

| docker ps 결과 | 의미 | 조치 |
|---|---|---|
| 컨테이너 없음 | CloudXR 미실행 | → 1.2로 이동하여 시작 |
| `Up (unhealthy)` | IPC 소켓 미생성 | → 1.3으로 이동하여 로그 확인 |
| `Up (healthy)` | 정상 실행 중 | → 1.4로 이동하여 네트워크 확인 |
| `Exited (1)` | 시작 실패 | → 1.3으로 이동하여 로그 확인 |

### 1.2 CloudXR Runtime Docker 시작

**방법 A: Docker Compose 사용 (권장)**

```bash
cd /workspace/isaaclab

# CloudXR Runtime + Isaac Lab 동시 시작
./docker/container.py start \
    --files ust_ws/260207_ust/docker-compose.cloudxr-ust.patch.yaml \
    --env-file docker/.env.cloudxr-runtime
```

**방법 B: Docker Run 수동 실행**

```bash
cd /workspace/isaaclab

# openxr 공유 디렉토리 생성 (최초 1회)
mkdir -p ./ust_ws/openxr

# CloudXR Runtime 시작
docker run -it --rm --name cloudxr-runtime \
    --gpus=all \
    -e "ACCEPT_EULA=Y" \
    --mount type=bind,src=$(pwd)/ust_ws/openxr,dst=/openxr \
    -p 48010:48010/tcp \
    -p 47998:47998/udp \
    -p 47999:47999/udp \
    -p 48000:48000/udp \
    -p 48005:48005/udp \
    -p 48008:48008/udp \
    -p 48012:48012/udp \
    nvcr.io/nvidia/cloudxr-runtime:5.0.1
```

**방법 C: start_cloudxr_runtime.sh 스크립트 사용**

```bash
cd /workspace/isaaclab
./ust_ws/260207_ust/start_cloudxr_runtime.sh
```

### 1.3 CloudXR Runtime 로그 확인

```bash
# 컨테이너 로그 확인
docker logs cloudxr-runtime 2>&1 | tail -30

# 정상 로그 예시:
#   CloudXR Runtime starting...
#   OpenXR runtime initialized
#   IPC socket created at /openxr/run/ipc_cloudxr

# 에러 로그 패턴별 대응:
```

| 로그 메시지 | 원인 | 해결 |
|---|---|---|
| `Permission denied: /openxr` | 마운트 권한 문제 | `chmod 777 ./ust_ws/openxr` |
| `GPU not available` | NVIDIA Container Toolkit 미설치 | `nvidia-smi` 확인 후 Toolkit 설치 |
| `EULA not accepted` | EULA 환경변수 누락 | `-e "ACCEPT_EULA=Y"` 추가 |
| `Port 48010 already in use` | 포트 충돌 | `sudo lsof -i :48010` 으로 확인 후 종료 |

### 1.4 CloudXR IPC 소켓 및 매니페스트 파일 확인

CloudXR Runtime이 실행되면 `/openxr` (호스트의 `./ust_ws/openxr`) 폴더에 다음 파일들이 자동 생성됩니다:

```bash

# OpenXR 런타임 매니페스트 확인
test -f ./ust_ws/openxr/share/openxr/1/openxr_cloudxr.json && echo "✓ 매니페스트 존재" || echo "✗ 매니페스트 없음"

# 런타임 라이브러리 확인
test -f ./ust_ws/openxr/lib/libopenxr_cloudxr.so && echo "✓ 라이브러리 존재" || echo "✗ 라이브러리 없음"

# runtime_started 플래그 확인
test -f ./ust_ws/openxr/run/runtime_started && echo "✓ 런타임 시작 완료" || echo "✗ 런타임 미시작"

# PID 파일 확인
cat ./ust_ws/openxr/run/cloudxr.pid 2>/dev/null && echo " (CloudXR PID)" || echo "✗ PID 파일 없음"
```

**기대하는 디렉토리 구조:**

```
./ust_ws/openxr/
├── lib/
│   └── libopenxr_cloudxr.so          ← CloudXR OpenXR 런타임 라이브러리
├── run/
│   ├── ipc_cloudxr                    ← Unix 도메인 소켓 (★ 필수)
│   ├── cloudxr.pid                    ← CloudXR 프로세스 ID
│   └── runtime_started                ← 런타임 초기화 완료 플래그
└── share/

```

### 2.1 환경변수 설정 확인 (★ 이번 에러의 직접 원인)

**현재 에러의 핵심 원인:** `XR_RUNTIME_JSON` 환경변수가 설정되지 않아서 OpenXR 로더가 디렉토리를 JSON으로 파싱 시도

```bash
# 현재 환경변수 확인
echo "XR_RUNTIME_JSON = $XR_RUNTIME_JSON"
echo "XDG_RUNTIME_DIR = $XDG_RUNTIME_DIR"
```

**예상되는 올바른 값:**
```
XR_RUNTIME_JSON = /workspace/isaaclab/ust_ws/openxr/share/openxr/1/openxr_cloudxr.json
XDG_RUNTIME_DIR = /workspace/isaaclab/ust_ws/openxr/run
```

> **만약 빈 값이면:** 이것이 에러의 원인입니다! 아래 2.2에서 해결하세요.

**방법 C: Docker Compose 사용 시 (자동 설정)**

단, 컨테이너 내부 경로(`/openxr/...`)가 사용되므로 호스트에서 직접 실행하는 경우와 다릅니다:

| 환경 | XR_RUNTIME_JSON 경로 |
|---|---|
| Docker Compose 내부 | `/openxr/share/openxr/1/openxr_cloudxr.json` |
| 호스트에서 직접 실행 | `/workspace/isaaclab/ust_ws/openxr/share/openxr/1/openxr_cloudxr.json` |

### 2.3 OpenXR 런타임 매니페스트 유효성 검증

```bash
# 매니페스트 파일 내용 확인
cat $XR_RUNTIME_JSON

# 올바른 내용:
# {
#     "file_format_version": "1.0.0",
#     "runtime": {
#         "name": "NVIDIA™ CloudXR™ Runtime (based on Monado™)",
#         "library_path": "../../../lib/libopenxr_cloudxr.so"
#     }
# }

# JSON 유효성 검증 (python 사용)
python3 -c "import json; json.load(open('$XR_RUNTIME_JSON')); print('✓ JSON 유효')" 2>&1 || echo "✗ JSON 파싱 실패"
```

**매니페스트가 가리키는 라이브러리 확인:**

```bash
# library_path는 매니페스트 기준 상대경로: ../../../lib/libopenxr_cloudxr.so
# 즉, openxr/share/openxr/1/ 에서 3단계 상위 = openxr/
# 최종 경로: openxr/lib/libopenxr_cloudxr.so

MANIFEST_DIR=$(dirname $XR_RUNTIME_JSON)
LIB_PATH=$(python3 -c "import json; print(json.load(open('$XR_RUNTIME_JSON'))['runtime']['library_path'])")
FULL_LIB_PATH=$(realpath "${MANIFEST_DIR}/${LIB_PATH}" 2>/dev/null)

echo "라이브러리 절대 경로: $FULL_LIB_PATH"
test -f "$FULL_LIB_PATH" && echo "✓ 라이브러리 존재" || echo "✗ 라이브러리 없음"
```

### 2.6 Isaac Lab에서 OpenXR 로드 테스트

```bash

cd /workspace/isaaclab

python3 -c "

import json

xdg_dir = os.environ.get('XDG_RUNTIME_DIR', '')

# 1. 환경변수 확인
print('[1] 환경변수')
if xr_json:
    print(f'  XR_RUNTIME_JSON = {xr_json} ✓')
else:
    print('  XR_RUNTIME_JSON = (미설정) ✗ ← 에러 원인!')

if xdg_dir:
    print(f'  XDG_RUNTIME_DIR = {xdg_dir} ✓')
else:
    print('  XDG_RUNTIME_DIR = (미설정) ✗')
print()

# 2. 매니페스트 파일 확인
print('[2] OpenXR 매니페스트')
if xr_json and os.path.isfile(xr_json):
    try:
        data = json.load(open(xr_json))
        print(f'  파일 존재: ✓')
        print(f'  런타임 이름: {data[\"runtime\"][\"name\"]}')
        print(f'  라이브러리: {data[\"runtime\"][\"library_path\"]}')

        # 라이브러리 실제 존재 확인
        lib_dir = os.path.dirname(xr_json)
        lib_path = os.path.normpath(os.path.join(lib_dir, data['runtime']['library_path']))
        if os.path.isfile(lib_path):
            print(f'  라이브러리 존재: ✓ ({lib_path})')
        else:
            print(f'  라이브러리 존재: ✗ ({lib_path})')
    except Exception as e:
        print(f'  JSON 파싱 실패: {e} ✗')
else:
    print(f'  파일 없음: ✗')
print()

# 3. IPC 소켓 확인
print('[3] IPC 소켓')
if xdg_dir:
    import stat
    sock_path = os.path.join(xdg_dir, 'ipc_cloudxr')
    if os.path.exists(sock_path):
        mode = os.stat(sock_path).st_mode
        if stat.S_ISSOCK(mode):
            print(f'  {sock_path} ✓ (소켓)')
        else:
            print(f'  {sock_path} ✗ (소켓이 아닌 파일)')
    else:
        print(f'  {sock_path} ✗ (존재하지 않음)')
else:
    print('  XDG_RUNTIME_DIR 미설정으로 확인 불가 ✗')
print()

# 4. runtime_started 플래그
print('[4] CloudXR Runtime 상태')
if xdg_dir:
    started = os.path.join(xdg_dir, 'runtime_started')
    pid_file = os.path.join(xdg_dir, 'cloudxr.pid')

    if os.path.exists(started):
        print(f'  runtime_started: ✓')
    else:
        print(f'  runtime_started: ✗')

    if os.path.exists(pid_file):
        with open(pid_file) as f:
            pid = f.read().strip()
        print(f'  cloudxr.pid: {pid} ✓')
    else:
        print(f'  cloudxr.pid: ✗')
print()

# 5. 종합 판단
print('[종합 판단]')
issues = []
if not xr_json:
    issues.append('XR_RUNTIME_JSON 환경변수를 설정하세요: source ./ust_ws/260207_ust/setup_cloudxr_env.sh')
elif not os.path.isfile(xr_json):
    issues.append('OpenXR 매니페스트 파일이 없습니다. CloudXR Runtime Docker를 먼저 실행하세요.')
if not xdg_dir:
    issues.append('XDG_RUNTIME_DIR 환경변수를 설정하세요.')
elif xdg_dir and not os.path.exists(os.path.join(xdg_dir, 'ipc_cloudxr')):
    issues.append('IPC 소켓이 없습니다. CloudXR Runtime Docker가 실행 중인지 확인하세요.')

if issues:
    print('  ✗ 문제 발견:')
    for i, issue in enumerate(issues, 1):
        print(f'    {i}. {issue}')
else:
    print('  ✓ 모든 점검 통과! Isaac Lab에서 OpenXR 세션을 시작할 수 있습니다.')
"
```

## Part 4: 에러별 빠른 참조표

| 에러 메시지 | 원인 | 해결 |
|---|---|---|
| `failed to parse .../ust_ws//.` | XR_RUNTIME_JSON 미설정 | `source ./ust_ws/260207_ust/setup_cloudxr_env.sh` |
| `failed to parse .../openxr//.` | XR_RUNTIME_JSON이 디렉토리를 가리킴 | 위와 동일 |
| `XR_ERROR_RUNTIME_UNAVAILABLE` | OpenXR 런타임 로드 실패 | 환경변수 설정 + CloudXR Docker 실행 |
| `XR_ERROR_INSTANCE_LOST` | CloudXR Runtime 연결 끊김 | CloudXR Docker 재시작 |
| `RuntimeInterface::LoadRuntimes - failed` | 런타임 로더가 런타임을 못 찾음 | `$XR_RUNTIME_JSON` 파일 존재 확인 |
| `Failed querying extension properties` | 위 에러의 연쇄 결과 | 근본 원인(환경변수/Docker) 해결 |

## Part 6: Docker Compose vs 호스트 직접 실행 차이점

| 항목 | Docker Compose 실행 | 호스트에서 직접 실행 |
|---|---|---|
| 환경변수 설정 | yaml에서 자동 | `source setup_cloudxr_env.sh` 필요 |
| XR_RUNTIME_JSON | `/openxr/share/openxr/1/openxr_cloudxr.json` | `/workspace/isaaclab/ust_ws/openxr/share/openxr/1/openxr_cloudxr.json` |
| XDG_RUNTIME_DIR | `/openxr/run` | `/workspace/isaaclab/ust_ws/openxr/run` |
| openxr 폴더 | Docker 볼륨 마운트 | 호스트 경로 직접 참조 |
| 실행 순서 | depends_on으로 자동 | 수동으로 CloudXR 먼저 시작 |
| 헬스체크 | 자동 (IPC 소켓 확인) | 수동 확인 필요 |

> **주의:** 현재 환경(호스트에서 직접 Isaac Lab 실행)에서는 반드시 `source setup_cloudxr_env.sh`를 실행해야 합니다.
> Docker Compose로 실행하는 경우는 yaml 파일에서 환경변수가 자동 설정되므로 별도 설정이 필요 없습니다.
