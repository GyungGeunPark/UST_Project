## 전략 A: Isaac Lab 중심 통합 스택 (상세 구성)

### 왜 Isaac Lab 중심인가?

RTX Pro 6000(48GB VRAM)을 보유한 환경에서 Isaac Lab은 **가장 균형 잡힌 통합 플랫폼**이다. 이전 Isaac Sim의 주요 불만이었던 설치 복잡도, 학습 곡선, 문서화 부족이 Isaac Lab v2.3에서 크게 개선되었다.

핵심적 변화:
- 2025년 **오픈소스화**: `pip install isaacsim[all]`로 설치 가능 (기존 12GB+ 별도 설치에서 개선)
- **Docker 공식 지원**: `nvcr.io/nvidia/isaac-lab:2.3.0` 컨테이너로 환경 일관성 보장
- **ManagerBased 워크플로우**: ObservationManager, ActionManager, RewardManager 등으로 모듈화되어 학습 곡선 대폭 완화
- **Isaac Lab Mimic**: 소수 시연에서 자동 데이터 증강 → 수천 개 데이터 생성
- **LeRobot 공식 통합**: Isaac Lab Arena + EnvHub로 ACT, Diffusion Policy, GR00T N1.5 학습/평가

Isaac Lab은 URDF, MJCF, OnShape에서 USD로의 변환을 내장 지원한다. 모바일 매니퓰레이터 URDF가 있다면:

```python
# ArticulationCfg로 로봇 정의
from isaaclab.assets.articulation import ArticulationCfg
from isaaclab.actuators import ImplicitActuatorCfg

MOBILE_MANIP_CFG = ArticulationCfg(
    spawn=sim_utils.UsdFileCfg(
        usd_path="/path/to/your_robot.usd",
        # 또는 URDF 직접 로딩:
        # usd_path=None, urdf_path="/path/to/your_robot.urdf"
    ),
    actuators={
        "arm": ImplicitActuatorCfg(
            joint_names_expr=["arm_joint_.*"],
            stiffness=100.0, damping=10.0,
        ),
        "base": ImplicitActuatorCfg(
            joint_names_expr=["base_.*"],
            stiffness=0.0, damping=100.0,
        ),
    },
)
```

## 전략 A vs B 상세 비교

### 1. 성능 비교 (RTX Pro 6000 기준)

| 항목 | 전략 A (Isaac Lab) | 전략 B (MuJoCo + LeRobot) |
|:---|:---|:---|
| 물리 시뮬레이션 속도 | ~700K steps/s (상태 기반, 4,096 envs) | CPU: 수만 steps/s / MJX: ~950K steps/s (A100 기준) |
| GPU 병렬 환경 수 | 4,096~16,384 (PhysX 5 Direct-GPU) | MJX: 4,096~8,192 / MuJoCo Warp: 수천 개 |
| GPU 메모리 사용량 | ~6.1GB (로코모션) / ~16.7GB (카메라) | MJX: JAX 자동관리 / CPU: 최소 |
| 렌더링 속도 | ~182 FPS (RTX 레이트레이싱, 최고 품질) | ~2,263 FPS (OpenGL, 기능적 품질) |
| 렌더링 품질 | ★★★★★ (포토리얼리스틱 레이트레이싱) | ★★☆☆☆ (OpenGL 기본) |
| Sim-to-Real 전이 | ★★★★★ (도메인 랜덤화, Cosmos 증강) | ★★★☆☆ (시각적 격차 큼) |

**분석**: RTX Pro 6000의 48GB VRAM은 Isaac Lab에서 최대 효과를 발휘한다. MuJoCo는 CPU 기반이므로 GPU를 제대로 활용하지 못하나, MJX/Warp를 사용하면 GPU 가속이 가능하다. 다만 MJX는 JAX 기반이라 RTX Pro 6000보다 A100/H100에서 더 최적화되어 있다.

### 2. 모방 학습 생태계 비교

| 항목 | 전략 A (Isaac Lab) | 전략 B (MuJoCo + LeRobot) |
|:---|:---|:---|
| ACT | ⚠️ LeRobot 경유 (Isaac Lab Arena) | ✅ 네이티브 (원래 MuJoCo에서 개발됨) |
| Diffusion Policy | ⚠️ LeRobot 경유 | ✅ 네이티브 (원래 robosuite/MuJoCo에서 개발됨) |
| GR00T N1.5 | ✅ 네이티브 (NVIDIA 생태계) | ✅ LeRobot v0.4.0 통합 |
| Robomimic (BC, BC-RNN) | ✅ 네이티브 (Isaac Lab Mimic) | ✅ 네이티브 (robosuite 1차 지원) |
| 데이터 증강 | ✅ Isaac Lab Mimic + Cosmos (자동) | ⚠️ MimicGen (robosuite 의존) |
| VLA 모델 (π0, SmolVLA) | ⚠️ LeRobot 경유 | ✅ LeRobot 네이티브 |
| 데이터 형식 | HDF5 → LeRobot 변환 필요 | LeRobot 네이티브 (phospho 자동) |
| 사전학습 모델 수 | GR00T N 계열 | ACT, DP, π0, π0.5, SmolVLA, GR00T 모두 |

**분석**: 모방 학습 알고리즘 다양성에서는 전략 B(MuJoCo + LeRobot)가 압도적이다. 그러나 Isaac Lab은 **자동 데이터 증강(Isaac Lab Mimic)**과 **시각 증강(Cosmos)**이라는 독보적 강점을 가진다. 10개의 수동 시연으로 1,000개 이상의 훈련 데이터를 자동 생성할 수 있어, 데이터 효율성 면에서 크게 앞선다.

## 최종 추천: 하이브리드 전략 (가장 균형적)

두 전략의 장점을 결합하면 **가장 통합적이면서도 구현 난이도를 낮출 수 있다**.

### 🏆 하이브리드 전략: "MuJoCo로 시작, Isaac Lab으로 확장"

```
Phase 1 (1주차): MuJoCo + LeRobot으로 빠르게 프로토타이핑
├── pip install mujoco lerobot
├── 기존 MuJoCo 환경(gym-aloha, LIBERO)에서 ACT/Diffusion Policy 검증
├── Open-Teach 또는 phospho로 Meta Quest 3S 데이터 수집 파이프라인 구축
└── Gazebo에서 모바일 베이스 + ROS2/Nav2 테스트

Phase 2 (2~3주차): Isaac Lab으로 스케일업
├── Docker로 Isaac Lab 환경 구축
├── MuJoCo에서 검증된 태스크를 Isaac Lab 환경으로 이식
├── Isaac Lab Mimic으로 데이터 자동 증강 (10 demos → 1,000+)
├── RTX 레이트레이싱으로 포토리얼리스틱 훈련 데이터 생성
└── Cosmos 시각 증강으로 Sim-to-Real 격차 축소

Phase 3 (4주차~): 통합 및 배포
├── Isaac Lab Arena + LeRobot EnvHub로 정책 평가 통합
├── Isaac Lab ROS2 브리지 또는 Gazebo로 실제 로봇 배포
├── (선택) Newton 물리 엔진으로 미분 가능 시뮬레이션 실험
└── (선택) GR00T N1.5 파운데이션 모델 파인튜닝
```

### 이 하이브리드 전략의 이점

1. **즉시 생산성**: MuJoCo + LeRobot은 설치 30분 만에 첫 훈련 시작 가능
2. **검증된 파이프라인**: ACT/Diffusion Policy가 원래 개발된 환경에서 먼저 검증
3. **점진적 복잡도**: Isaac Lab의 학습 곡선을 MuJoCo 경험 후에 도전
4. **RTX Pro 6000 최대 활용**: Phase 2에서 GPU의 48GB VRAM을 포토리얼리스틱 렌더링과 대규모 병렬 시뮬레이션에 투입
5. **데이터 효율성**: Isaac Lab Mimic의 자동 증강으로 소수 시연에서 대규모 데이터 생성
6. **미래 확장성**: Newton 물리 엔진, GR00T 파운데이션 모델로의 자연스러운 전환 경로
