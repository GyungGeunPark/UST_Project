Performance Guide

This comprehensive guide covers both performance tuning and analysis for your CloudXR web application running on XR headsets. Learn how to optimize settings for the best performance and visual quality, and how to profile and analyze your application to identify bottlenecks.

This guide is intended to assist in optimizing CloudXR.js applications for these devices:

  • Meta Quest 3
  • Pico 4 Ultra

Framebuffer Scale Factor

XRWebGLLayer option framebufferScaleFactor requests a higher or lower resolution framebuffer than the default. This directly affects visual clarity and rendering performance.

  • 2.0 max value allowed
  • 1.5 max effective value on Quest 3 (values above this do not increase framebuffer size)
  • 1.2 approximately matches native display resolution
  • 1.0 uses OpenXR "recommended resolution" (lower than physical)

Quest 3 Recommendations:

  • Unset - high performance (possibly dynamic)
  • 1.2 - performance
  • 1.4 - balanced
  • 1.5 - quality

Performance impact: Very high - scales approximately with the square of the factor. Increasing from 1.0 to 1.5 typically adds 3-4ms per frame.

Quality impact: Critical for visual clarity, especially for text and UI elements. Undershooting native resolution results in noticeably blurry visuals.

Example (React Three Fiber with @react-three/xr):

import { createXRStore } from '@react-three/xr';

const store = createXRStore({
  frameBufferScaling: 1.5  // Quest 3 optimal
});

Example (Vanilla WebXR):

const xrSession = await navigator.xr.requestSession('immersive-vr');
const baseLayer = new XRWebGLLayer(xrSession, gl, {
  framebufferScaleFactor: 1.5  // Quest 3 optimal
});
xrSession.updateRenderState({ baseLayer });

Fixed Foveation Rendering (FFR)

XRWebGLLayer member fixedFoveation makes the WebXR render/compositor-submit use a foveated rendering algorithm to reduce the number of pixels rendered substantially. This trades rendering quality in peripheral vision where the human eye has lower acuity with rendering performance. This is a WebXR feature that is available on the Meta Quest Browser.

Meta Quest Browser Values:

Level Value Description Use Case
NONE 0.0 Full resolution everywhere Maximum quality, testing
LOW 0.333 Minimal peripheral reduction Quality-focused experiences
MEDIUM 0.666 Balanced quality/performance Recommended default
HIGH 1.0 Maximum peripheral reduction Performance-critical scenarios

Quest 3 Recommendation: MEDIUM (0.666) provides a good balance - saves 10-20% frame time with minimal perceived quality loss during natural head movement.

Performance impact: Medium - reduces pixel shading workload in peripheral regions proportional to the foveation level.

Quality impact: Peripheral image quality is reduced. At LOW and MEDIUM, this is typically imperceptible during natural use. At HIGH, peripheral degradation may become noticeable.

Important: This setting controls local client-side rendering only. It is separate from server-side/stream foveation, which is configured on the CloudXR Runtime and affects the streamed video.

Example (React Three Fiber):

const store = createXRStore({
  foveation: 0.666  // MEDIUM level
});

Example (Vanilla WebXR):

const baseLayer = new XRWebGLLayer(xrSession, gl, { /* options */ });
xrSession.updateRenderState({ baseLayer });

// Set foveation after layer is set in render state
if ('fixedFoveation' in baseLayer) {
  baseLayer.fixedFoveation = 0.666;  // MEDIUM level
}

WebGL Context Antialiasing

The WebGLContext option antialias enables multisampling anti-aliasing (MSAA) for the WebGL context.

Quest 3 Recommendation: false

At nominal settings, enabling antialiasing can increase frame time by 2.5ms or more with minimal visual improvement. The cost scales with framebuffer size, making it even more expensive at higher framebufferScaleFactor values.

Note: Chromium-based browsers on Android platforms, such as Meta Quest Browser, may restrict WebGL to 2x multisampling, limiting quality gains even when enabled.

Example (React Three Fiber):

<Canvas
  gl={{
    antialias: false,  // Recommended
    powerPreference: 'high-performance',
    alpha: true,
    depth: true,
    stencil: false,
  }}
>
  {/* Your scene */}
</Canvas>

Example (Vanilla WebGL):

const gl = canvas.getContext('webgl2', {
  antialias: false,
  powerPreference: 'high-performance'
});

Stream Resolution (Per-Eye Width/Height)

The CloudXR Session options perEyeWidth, perEyeHeight determine the resolution of the video stream from the server. Higher resolution provides better visual quality but decreases performance across the entire client-server pipeline.

Requirements:

  • Both perEyeWidth and perEyeHeight must be multiples of 16
  • Derived stream dimensions (packed frame) must also be multiples of 16

Quest 3 Recommendations:

  • Balanced: perEyeWidth: 2048, perEyeHeight: 1792
  • Performance: perEyeWidth: 1792, perEyeHeight: 1536
  • Quality: perEyeWidth: 2048, perEyeHeight: 1792 (with higher bitrate)

Performance impact: High - Increases server rendering and encode time, network bandwidth and latency, client decode and rendering time.

Quality impact: High - Low resolutions result in blurry visuals with strong visual artifacts.

Example:

const session = CloudXR.createSession({
  serverAddress: 'your-server-ip',
  serverPort: 49100,
  useSecureConnection: false,
  gl: webglContext,
  perEyeWidth: 2048,   // Must be multiple of 16
  perEyeHeight: 1792,  // Must be multiple of 16
  referenceSpace: xrReferenceSpace,
  deviceFrameRate: 90,
  maxStreamingBitrateKbps: 150000  // 150 Mbps
});

Device Frame Rate

There are two frame rate controls, serving different purposes, and they both need to be set for optimal performance.

  • CloudXR.js (deviceFrameRate): Informs the CloudXR networking layer about the target frame rate. This allows CloudXR to tune streaming parameters, buffer sizes, and timing predictions for optimal streaming performance at your target frame rate.

  • WebXR (updateTargetFrameRate): Actually requests the physical refresh rate from the XR device. This is what controls the hardware refresh rate and determines how often XRSession.requestAnimationFrame() callbacks fire.

Critical importance: Device frame rate directly impacts pose capture rate. In WebXR, pose updates are only received in XRSession.requestAnimationFrame() callbacks. If the device frame rate drops, pose update frequency drops proportionally, creating a feedback loop that can cause stuttering and dropped frames.

Recommended values:

  • Quest 3: 90 Hz (native)
  • Pico 4 Ultra: Check device capabilities

Important: Always verify the requested frame rate is supported by the device. Unsupported values may fall back to lower rates.

Example:

// 1. Tell CloudXR about the target frame rate (for networking optimization)
const session = CloudXR.createSession({
  // ... other options
  deviceFrameRate: 90,  // Quest 3 native
});

// 2. Actually set the device frame rate (in your XR session setup)
const xrSession = await navigator.xr.requestSession('immersive-vr');
if ('updateTargetFrameRate' in xrSession) {
  await xrSession.updateTargetFrameRate(90);
  console.log('Frame rate set to:', xrSession.frameRate);
}

Maximum Streaming Bitrate

The CloudXR Session option maxStreamingBitrateKbps sets the upper limit for video stream bitrate. Higher bitrates improve visual quality but require more network bandwidth.

Recommendations:

  • WiFi 6/6E: 150000 to 200000 Kbps (150-200 Mbps)
  • WiFi 5: 100000 to 150000 Kbps (100-150 Mbps)
  • Constrained networks: 80000 to 100000 Kbps (80-100 Mbps)

Performance impact: Medium, network dependent. Exceeding available bandwidth causes packet loss, increased latency, and stuttering.

Quality impact: High. Higher bitrate means better visual quality with fewer compression artifacts. Balance with network capabilities.

Example:

const session = CloudXR.createSession({
  // ... other options
  maxStreamingBitrateKbps: 150000,  // 150 Mbps
});

Complete Configuration Example

Here's a complete example showing all performance settings together using React Three Fiber and CloudXR.js:

import { Canvas } from '@react-three/fiber';
import { XR, createXRStore } from '@react-three/xr';
import * as CloudXR from '@nvidia/cloudxr';

// Performance profile constants
const PERFORMANCE_PROFILE = {
  // WebXR settings
  webglContext_antialias: false,
  xrWebGLLayer_framebufferScaleFactor: 1.5,
  xrWebGLLayer_fixedFoveationLevel: 0.666, // MEDIUM
  
  // CloudXR streaming settings
  deviceFrameRate: 90,
  perEyeWidth: 2048,
  perEyeHeight: 1792,
  maxStreamingBitrateKbps: 150000,
};

// Create XR store with performance settings
const xrStore = createXRStore({
  foveation: PERFORMANCE_PROFILE.xrWebGLLayer_fixedFoveationLevel,
  frameBufferScaling: PERFORMANCE_PROFILE.xrWebGLLayer_framebufferScaleFactor,
});

function App() {
  return (
    <Canvas
      gl={{
        antialias: PERFORMANCE_PROFILE.webglContext_antialias,
        powerPreference: 'high-performance',
        alpha: true,
        depth: true,
        stencil: false,
        failIfMajorPerformanceCaveat: true,
        preserveDrawingBuffer: true,
      }}
    >
      <XR store={xrStore}>
        {/* Your CloudXR component and scene */}
      </XR>
    </Canvas>
  );
}

// In your CloudXR session creation code:
function createCloudXRSession(gl: WebGL2RenderingContext, referenceSpace: XRReferenceSpace) {
  const session = CloudXR.createSession({
    serverAddress: 'your-server-ip',
    serverPort: 49100,
    useSecureConnection: false,
    gl: gl,
    perEyeWidth: PERFORMANCE_PROFILE.perEyeWidth,
    perEyeHeight: PERFORMANCE_PROFILE.perEyeHeight,
    referenceSpace: referenceSpace,
    deviceFrameRate: PERFORMANCE_PROFILE.deviceFrameRate,
    maxStreamingBitrateKbps: PERFORMANCE_PROFILE.maxStreamingBitrateKbps,
  });
  
  return session;
}

Performance Profiling and Analysis

This section explains how to profile and analyze the performance of your CloudXR web application running on XR headsets.

Prerequisites

  • XR headset capable of running CloudXR.js client (e.g. Quest 3)
  • USB-C cable (USB 3.0 or higher recommended for better data transfer speeds)
  • Computer capable of running adb via Meta Quest Developer Hub, Android Studio or similar

Setup: Connecting to Your PC

Step 1: Enable Developer Mode on Device

For Meta Quest 3:

  1. Install the Meta Quest mobile app on your smartphone
  2. Pair your Quest headset with the mobile app
  3. In the mobile app, go to Menu → Devices
  4. Select your Quest headset
  5. Tap Developer Mode and toggle it ON
  6. The headset will reboot to enable developer mode

For other devices, consult the documentation.

Step 2: Install adb

There are many ways to install and use adb, including:

  • Meta Quest Developer Hub (recommended for Meta devices)
  • Android Studio (found in <Android SDK>/platform-tools/)
  • Standalone Android Platform Tools (can be downloaded from Android developers site)
  • Unity (when Android support is installed)

Step 3: Connect via USB

  1. Install OEM specific drivers, if needed (consult your device documentation).
  2. Turn on and (if needed) log into your headset
  3. Connect your headset to your PC using a USB-C cable
  4. Put on the headset and accept any needed prompts

You can verify the connection by:

  • Checking for devices in Meta Quest Developer Hub
  • Running adb devices from a command prompt

Chrome DevTools Remote Debugging

Step 1: Access Chrome Inspect

  1. On your PC, open a chromium-based browser (such as Google Chrome or Microsoft Edge)
  2. Navigate to chrome://inspect in the address bar
  3. Make sure "Discover USB devices" is checked
  4. You should see your device listed under "Remote Target"

Step 2: Open Your Web Application on device

  1. Put on your headset
  2. Open the Browser app
  3. Navigate to your development server URL (e.g. one of the examples described in examples/README.md )
  4. Launch your CloudXR application

Step 3: Connect DevTools

  1. Back on your PC at chrome://inspect, you should now see your web page listed under your device
  2. Click the "inspect" link next to your page
  3. A Chrome DevTools window will open, connected to your browser

Note: The DevTools window has full access to your running application:

  • Console: View logs and errors
  • Network: Monitor network requests and bandwidth
  • Performance: Record and analyze performance profiles
  • Memory: Analyze memory usage and detect leaks
  • Sources: Debug JavaScript with breakpoints

Recording Performance Profiles

  1. In the Chrome DevTools window connected to your device, navigate to the Performance tab
  2. Click the Record button (circle icon) or press Ctrl+E
  3. Put on your headset and interact with your CloudXR application
  4. Perform the actions you want to profile (e.g., streaming session, user interactions)
  5. After 5-10 seconds, click Stop in DevTools to end the recording
  6. DevTools will process and display the performance timeline

Troubleshooting Performance Issues

Frame rate drops below target

Symptoms: Application runs below target frame rate (90 fps for Quest 3)

Common causes and solutions:

  1. High GPU load

    • Reduce framebufferScaleFactor to 1.2 or 1.0
    • Increase fixedFoveation to HIGH (1.0)
    • Verify antialias: false in WebGL context

  2. Network bandwidth insufficient

    • Reduce maxStreamingBitrateKbps
    • Reduce perEyeWidth and perEyeHeight
    • Check WiFi quality and proximity to access point

  3. Server encoding bottleneck

    • Reduce perEyeWidth and perEyeHeight
    • Ensure server has adequate GPU resources
    • Check server-side metrics

Visual quality issues

Symptoms: Blurry image, compression artifacts, or pixelation

Solutions:

  1. Blurry overall image

    • Increase framebufferScaleFactor (if frame rate allows)
    • Increase perEyeWidth and perEyeHeight
    • Increase maxStreamingBitrateKbps

  2. Compression artifacts or blocking

    • Increase maxStreamingBitrateKbps
    • Check network quality (packet loss, jitter)

  3. Peripheral blur or warping

    • Reduce fixedFoveation to LOW or NONE
    • Note: This may impact frame rate

Stuttering or judder

Symptoms: Inconsistent frame timing, perceived stuttering

Causes and solutions:

  1. Frame rate instability

    • Profile with Chrome DevTools to identify bottlenecks
    • Look for long JavaScript tasks or render operations
    • Reduce settings until stable frame rate is achieved

  2. Network jitter

    • Check network quality (ping variance, packet loss)
    • Reduce maxStreamingBitrateKbps if network is unstable
    • Consider wired connection for server (if on WiFi)

Best Practices

  1. Start with recommended defaults: Use the balanced profiles provided for your target device, then tune based on specific needs.

  2. Test on target hardware: Performance characteristics vary significantly between devices. Always test on your target headset.

  3. Maintain target frame rate: If you need high quality visuals and are having performance issues, drop the requested frame rate to a lower value. Failing to meet target frame rate cascades, making performance and quality degrade rapidly.

  4. Document your profile: Save your performance configuration as constants or configuration files for easy testing and deployment.
