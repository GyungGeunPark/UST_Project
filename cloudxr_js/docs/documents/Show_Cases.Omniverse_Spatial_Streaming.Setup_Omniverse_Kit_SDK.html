Omniverse Kit Setup for Streaming to Meta Headsets

Developing a new Kit XR application for streaming to the Meta Quest 3 headset begins with configuring the necessary settings and dependencies. This utilizes the Kit app template as the foundation for an XR-specific template. The Kit app template allows developers to fork, customize, and use it for developing, packaging, and sharing their extensions. This toolkit is crucial for developing GPU-accelerated applications within the NVIDIA Omniverse ecosystem. The Omniverse platform includes pre-configured templates, tools, and sample code designed to simplify and expedite the creation of high-performance applications using OpenUSD.

To begin, select a folder in your code editor to serve as your workspace.

Note: For Windows OS, ensure long path support is enabled, or ensure the workspace folder is in a shallow nested location.

🖥️ I. Clone the Kit Repository

  1. Be sure to create a new folder instead of using a location where other templates reside, as this could lead to configuration errors or conflicts due to updates to the template.

  2. Open a new terminal in your code editor.

  3. Clone the repository:

    git clone --single-branch --branch 109.0.2 https://github.com/NVIDIA-Omniverse/kit-app-template.git

  4. Navigate into the newly cloned directory:

    cd kit-app-template

  5. In the terminal, use the template new command:

    # on Windows
    .\repo.bat template new

    # on Linux
    ./repo.sh template new

    This command creates an application containing the Kit SDK.

  6. When prompted: Select what you want to create - Select Application

  7. When prompted to Select desired template:

    • Select USD Composer to create a Kit app for authoring, editing and testing your USD data in XR. Or:
    • If you'd like to create a smaller footprint application just for streaming your USD, you can instead select Kit Base Editor.

  8. Give your application and sample extension a desired name and version, like my_company.my_usd_composer. We won't be using a sample extension for this guide, so you can leave the extension name at its default value.

  9. When prompted: Do you want to add application layers? Select No.

🖥️ II. Modify your Kit App Extensions & Settings

  1. Open: my_company.my_usd_composer.kit in your code editor.

    Note: On Windows, the file is at kit-app-template\source\apps\. On Linux, it is at kit-app-template/source/apps/.

  2. Include the following extensions to the end of the [dependencies] list:

    # Core infrastructure for doing XR inside Kit
    "omni.kit.xr.core" = {version = ">=109.0.2"}
    # This extension contains the XR parts to build the menu windows for the different xr profiles
    "omni.kit.xr.ui.window.profile" = {version = ">=109.0.2"}
    # This extension contains the XR parts for viewport integration
    "omni.kit.xr.ui.window.viewport" = {version = ">=109.0.2"}
    # This extension the common ui widgets for the stage
    "omni.kit.xr.ui.stage" = {version = ">=109.0.2"}
    # The CloudXR runtime
    "omni.kit.xr.cloudxr" = {version = ">=6.0.4"}

  3. Save your .kit file.

🖥️ III. Build and Launch the Kit Application

To be able to run the application, you need to build it first. The build process compiles your application and its extensions, preparing them for launch.

  1. In the terminal window, enter the following command to build your app:

    # on Windows
    .\repo.bat build

    # on Linux
    ./repo.sh build

  2. When the build process is finished, a message appears:

    BUILD (RELEASE) SUCCEEDED (<time taken>)

  3. Type the following command to launch your application:

    # on Windows
    .\repo.bat launch

    # on Linux
    ./repo.sh launch

    Note: The first time a Kit application is launched it will compile and cache the RTX shaders, this can take several minutes.

    When the launch process is complete, the application opens in a new window. You may need to dock the XR panel.

  4. First locate the asset file included in the Workflow Example. Or download the USD dataset visionpro_purse_example.usd.

  5. Open the visionpro_purse_example.usd file and allow all the files to load. At this point, if you need to get more familiar with Omniverse, its default interface and UI, or OpenUSD, refer to the Omniverse documentation. To understand more about what you can do with Kit App Template, please refer to the Kit App Template Companion Guide.

Configure CloudXR for Meta Quest 3

  1. Stop any existing Simulated XR modes that might be running by clicking Stop XR from the XR panel.

  2. Configure the OpenXR settings:

    • Change the Selected Output Plugin from Simulated XR to OpenXR
    • Change the OpenXR Runtime dropdown to CloudXR 6 (WebRTC)

  3. Click Start XR.

    • You know that you have successfully started the server with the runtime when you see this message within the viewport window: "Status: Running XR"

  4. Find IP Address: Type ipconfig in the Command Prompt (Press Win + R, type cmd, and hit Enter) in Windows OS, or ifconfig in Linux. Take note of the IP address for use in connecting the client to the server.

  5. Manage XR Session: You can now either Stop XR or leave the server running in the background while you set up the client.
