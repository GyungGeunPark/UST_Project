
# Isaac Sim에서 페이로드(Payload) 처리 및 계층 구조 수정 최종 안내서

이 문서는 `instanceable`이 해제되고 **페이로드(Payload)**로 로드된 로봇의 계층 구조를 수정할 수 없는 근본적인 문제를 해결하는 방법을 설명합니다.

## 1. 문제의 핵심: 페이로드(Payload)란 무엇인가?

사용자께서 `link1`의 이름 변경이나 `link2`의 이동이 불가능하다고 하셨는데, 그 원인은 해당 링크들이 **페이로드(Payload)**로 로드되었기 때문입니다.

*   **페이로드(Payload):** USD에서 성능과 협업을 위해 사용하는 기능으로, 씬(Scene)을 열 때 전체 데이터를 즉시 로드하는 대신, 실제 데이터는 외부 파일에 남겨두고 '참조'만 가져오는 방식입니다. 뷰포트에는 로봇이 보이지만, 내부적으로는 껍데기만 있는 상태와 같습니다.
*   **왜 수정이 안 되는가?:** 페이로드 상태에서는 원본 파일을 보호하기 위해 계층 구조 변경, 이름 변경, 재질 수정 등 대부분의 직접적인 편집이 막힙니다. `instanceable` 체크를 해제한 것은 올바른 방향이었지만, 페이로드가 근본적인 원인입니다.

## 2. 해결 방법: 페이로드 로드 후 계층 구조 수정

이 문제를 해결하려면 페이로드를 명시적으로 "로드"하여 씬(Stage) 상에서 실제 데이터로 전환한 다음, 계층 구조를 수정하고, 그 결과를 새로운 파일로 저장해야 합니다.

제공된 `fix_robot_with_payloads.py` 스크립트는 이 모든 과정을 자동화합니다.

### 스크립트의 작동 원리

1.  **페이로드 로드:** 로봇과 관련된 모든 프림을 순회하며 페이로드를 로드하여 직접 편집 가능한 상태로 만듭니다.
2.  **계층 구조 수정:** 이전 안내서와 동일하게 `link2`를 `link1`의 자식으로 이동시켜 올바른 로봇 계층을 구성합니다.
3.  **Articulation Root 설정:** `link1`에 Articulation Root를 올바르게 설정합니다.
4.  **새 파일로 저장:** 모든 수정이 완료된 결과를 **`ust_project1_flattened_fixed.usd`** 라는 새로운 독립 파일로 저장합니다. 이 파일은 더 이상 페이로드 참조를 포함하지 않으므로 사용하기 편리합니다.

## 3. 스크립트 실행 방법

1.  **원본 파일 열기:** Isaac Sim에서 기존의 `ust_project1.usd` 파일을 엽니다.

2.  **스크립트 에디터 열기:** 상단 메뉴에서 `Window` > `Script Editor`를 선택합니다.

3.  **스크립트 내용 복사 및 붙여넣기:**
    *   `fix_robot_with_payloads.py` 파일의 **전체 내용**을 복사하여 스크립트 에디터 창에 붙여넣습니다.

4.  **스크립트 실행:**
    *   스크립트 에디터 상단의 `Run` 버튼을 클릭합니다.
    *   콘솔 창(`Window` > `Console`)을 통해 페이로드를 로드하고 계층을 수정한 후 새로운 파일을 저장하는 과정을 확인할 수 있습니다.

5.  **최종 결과 확인:**
    *   스크립트 실행이 완료되면, `isaac_file` 폴더 안에 **`ust_project1_flattened_fixed.usd`** 라는 새로운 파일이 생성됩니다.

## 4. 최종 단계

이제 모든 문제가 해결된 **`ust_project1_flattened_fixed.usd`** 파일을 사용하면 됩니다.

*   **이 파일을 열어서 Lula Robot Description Editor 설정을 진행하십시오.**
*   Lula 에디터에서 `Robot Prim`으로 `link1`을 선택하면, `link1`부터 `link5`까지 모든 관절이 순서대로 올바르게 표시될 것입니다.

이 과정을 통해 페이로드로 인한 수정 불가 문제를 해결하고, RMPflow를 위한 로봇 설정을 성공적으로 완료할 수 있습니다.
